## Détail des problèmes

### #1 — Filtre "Statut santé" cassé fonctionnellement (`totalLinks=0`)

**Sévérité** : 🔴 Critique
**Fichier(s)** : `resources/views/pages/admin/settings/gpo/index.blade.php:469`

**Constat** : `GpoHealthStatusCalculator::calculate($g, 0)` est appelé avec `totalLinks` **hard-codé à 0**. Conséquences :
- Toute GPO active (`versionNumber > 0`) sera classée `Orphaned` (priorité 2 dans le calculator quand totalLinks===0).
- Toute GPO `versionNumber === 0/null` sera `Stale`.
- Aucune GPO ne pourra jamais matcher `healthy` ni `conflicting`.
- De surcroît, `GpoSummary::versionNumber` est null en sortie `list()` — 100% des GPOs tombent en `stale`.

**Solutions possibles** :
1. Précomputer `linksCountByGuid` via N appels `getLinks` cappés à 100 GPOs au `loadGpos()`.
2. Retirer les statuts `healthy`/`conflicting` de l'UI (n'exposer que `stale`/`orphaned`) et amender D4.

**Action** : ⏳ En attente Q2.

### #2 — Risque CSV injection (=, +, -, @, tab) dans les exports

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Gpo/Support/GpoExportSerializer.php`

**Constat** : Aucune protection contre CSV injection. Un `displayName` commençant par `=`, `+`, `-`, `@`, `\t`, `\r` est interprété comme formule par Excel/Sheets. Le BOM UTF-8 garantit l'ouverture Excel ce qui aggrave le risque pour un attaquant qui contrôlerait un display name AD via délégation.

**Solutions possibles** :
1. Préfixer toute cellule string dangereuse par une apostrophe `'` dans `toCsvRows`.
2. Helper `Str::escapeForCsv()` dédié.

**Action** : ✅ Corrigé (Option A — méthode privée `escapeCsvCell` ajoutée).

### #3 — Injection JS via `wire:click="selectOu('{{ $suggestion }}')"`

**Sévérité** : 🟠 Important
**Fichier(s)** : `resources/views/pages/admin/settings/gpo/by-ou/index.blade.php:275`, `resources/views/pages/admin/settings/gpo/_partials/advanced-filters-panel.blade.php:128`

**Constat** : Les DNs OU sont interpolés directement dans une chaîne JS d'attribut `wire:click` via `{{ $suggestion }}`. Un DN AD légal contenant `'` (ex `OU=O'Brien,DC=…`) casse la syntaxe. Risque XSS si un attaquant peut créer une OU avec un nom malicieux via délégation.

**Solutions possibles** :
1. `wire:click="selectOu(@js($suggestion))"` (Livewire helper qui sérialise en JSON safe).
2. Indexation : `wire:click="selectSuggestion({{ $loop->index }})"`.

**Action** : ✅ Corrigé (Option A — `@js()`).

### #4 — Tests d'export CSV/JSON ne testent aucun contenu généré

**Sévérité** : 🟠 Important
**Fichier(s)** : `tests/Feature/Gpo/GpoIndexExportTest.php:81-124`

**Constat** : Les tests vérifient `assertMethodExists` et la présence du bouton. Aucun n'appelle réellement `exportCsv()`/`exportJson()`, ne vérifie le Content-Type/Content-Disposition, le périmètre filtré (AC2.4), le BOM UTF-8, ni l'émission du log `gpo.export.csv/json` (AC8.1).

**Solutions possibles** :
1. `Livewire::test(...)->call('exportCsv')` + capture `StreamedResponse` + assertions headers + contenu.
2. Tester `exportCsv()` comme méthode unitaire avec instance directe.

**Action** : ✅ Corrigé (Option A — 4 tests réels ajoutés couvrant happy CSV, happy JSON, filtré, logs).
