## Détail des problèmes

### #1 — Tooltip « Local » faux sur la surface parc-defaults
**Sévérité** : 🟠 — **Fichier** : `resources/views/pages/admin/settings/parc-defaults/_partials/registry-tab.blade.php` L.276/282/316 ; `docs/qa/domains/controlhub-contract.md` (Section 9)
**Constat** : libellé « Réglage propre à ce parc/groupe » copié depuis `capabilities-tab`, alors que cette surface édite le **défaut diffusé à toute la flotte** (maille Broadcast). Réintroduit l'ambiguïté que FR8 doit lever.
**Solution appliquée** : tooltips différenciés par surface — sur `parc-defaults`, « Défaut diffusé — aucune contrainte amont. » ; QA Section 9 corrigée en cohérence.
**Action** : corrigé automatiquement.

### #2 — Vérité du libellé permissif non verrouillée par un test
**Sévérité** : 🟠 — **Fichier** : les 2 tests Feature de badge
**Constat** : aucun test n'ancre le contenu du tooltip permissif ni n'interdit une formulation trompeuse (« la valeur amont s'applique »). C'est l'angle mort #1 documenté.
**Solution appliquée** : assertion positive sur « votre réglage local prévaut » + `assertDontSee('valeur amont')` sur les 2 surfaces.
**Action** : corrigé automatiquement.

### #3 — Badge « Local » rendu même en standalone
**Sévérité** : 🟡 — **Fichier** : les 2 partials ; AC#3 vs AC#6
**Constat** : AC#3 (« marqueur local qu'un contrat soit actif ou non ») contredit AC#6 (« strictement identique à 27.12 sans contrat »). Le dev a tranché « toujours », ce qui n'est pas byte-identique et ajoute du bruit dans le cas nominal standalone.
**Décision orchestrateur** : gater les badges sur `hasActiveContract()` — standalone = table nue byte-identique ; tri-état visible dès qu'un contrat existe. Réversible (cf. Question 1).
**Action** : corrigé automatiquement (décision tranchée, réversible).

### #4 — Double évaluation `isCapabilityLocked` dans `addableCapabilities()`
**Sévérité** : 🟡 — **Fichier** : `capabilities-tab.blade.php` L.149/157
**Constat** : `reject(isCapabilityLocked)` puis `capabilityUpstreamStatus()` rappelle `isCapabilityLocked` (toujours false ici). Itération redondante (pas N+1 SQL, sets mémoïsés).
**Solution appliquée** : pour les addables, `isCapabilityPermissive($c) ? 'permissive' : 'local'` (locked déjà exclu).
**Action** : corrigé automatiquement.

### #5 — Double clé `is_upstream_locked` + `upstream_status`
**Sévérité** : 🟡 — **Fichier** : les 2 partials
**Constat** : deux clés pour une seule source de vérité ; smell de cohérence.
**Solutions possibles** : (A) ne garder que `upstream_status`, tester `=== 'locked'` partout ; (B) inverse.
**Action** : ⏳ backlog — 2 solutions valides, refactor multi-sites sans gain fonctionnel ; hors périmètre des corrections auto pour garder le diff focalisé.

### #6 — Surfaces non testées pour severed/absent
**Sévérité** : 🟡 — **Fichier** : tests Feature
**Constat** : AC#6 couvre standalone OU `absent` OU `severed` ; seul standalone est testé au niveau Livewire.
**Solution appliquée** : cas Feature « contrat severed → tous Local/aucun badge amont » ajouté.
**Action** : corrigé automatiquement.

### #7 — Pas de compteur de requêtes au rendu Livewire
