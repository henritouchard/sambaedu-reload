## Détail des problèmes

### #1 — `ShortcutsUpstreamAdapter` : payload incomplet, l'agent rejette tout le type `shortcuts`

**Sévérité** : 🟠 (requalifié 🔴 par opus côté impact e2e)
**Fichier(s)** : `app/Services/ControlHub/Resolution/ShortcutsUpstreamAdapter.php:50-56`

**Constat initial (sonnet)** : `toPayload()` émet `{name, target}` (2 champs). Le vrai `ShortcutsStateProvider::payloadFor()` émet `{name, target, args, icon, place}` (+`desktop_path` si `place=desktop`). Le test AC#2 ne le détecte pas car le fake local émet aussi `{name, target}`.

**Avis Opus (3/3)** : confirmé et plus grave. `agent/shared/handler_shortcuts.go:398-401` (`parseShortcutSpec`) rejette tout spec dont `place == ""` → `handler_shortcuts.go:201-203` `return nil, fmt.Errorf("payload shortcuts inattendu : enveloppe invalide")` ⇒ l'item amont sans `place` fait **échouer TOUTE la convergence du type `shortcuts`** sur le poste, pas seulement cet item. Mitigation : `shortcuts` est le type de démonstration de l'aggregate, expansion par-type déférée Epic 33 par décision Henri, aucun controlHub réel n'impose de shortcuts aujourd'hui — MAIS l'adaptateur est **câblé en prod** (`AgentServiceProvider:103`).

**Solutions possibles** : (A) ne pas enregistrer l'adaptateur shortcuts jusqu'à Epic 33 ; (B) compléter le payload avec `place` par défaut résoluble + `args`/`icon` vides ; (C) documenter l'interdiction d'item shortcuts amont avant Epic 33.

**Action** : ✅ **Résolu — option (A) (décision Henri)**. `ShortcutsUpstreamAdapter` retiré du binding `UpstreamContractSource` dans `AgentServiceProvider` (seul `RegistryUpstreamAdapter` câblé). Classe conservée + PHPDoc « non câblé en prod, gated Epic 33, aligner `toPayload()` sur `payloadFor()` avant réenregistrement ». Tests verts (13/13, dont `container_wires_every_provider_through_the_decorator` et le test aggregate qui instancie l'adaptateur en direct).

### #2 — `RegistryUpstreamAdapter::typedValue()` : `REG_MULTI_SZ` non géré

**Sévérité** : 🟠
**Fichier(s)** : `app/Services/ControlHub/Resolution/RegistryUpstreamAdapter.php:91-97`

**Constat initial (sonnet)** : `match` ne gère que `REG_DWORD/REG_QWORD`→int, `default`→string. Le vrai `AbstractCapabilityStateProvider::typedValue()` traite `REG_MULTI_SZ`→`coerceMultiSz()`→`list<string>`. Un item amont `REG_MULTI_SZ` produit une string JSON au lieu d'un tableau ; l'`exclusiveKey` (type exclu) matche quand même, l'amont gagne, l'agent reçoit une valeur mal typée.

**Avis Opus (2/2)** : confirmé ; gravité moindre que #1 (MULTI_SZ amont = cas de bord, `type` reste correct, seul `value` est faux). La PHPDoc « iso `typedValue()` » **surpromet** (MULTI_SZ absent) → à corriger a minima.

**Action** : ✅ Corrigé — `RegistryUpstreamAdapter::typedValue()` aligné (ajout `REG_MULTI_SZ => coerceMultiSz()`, méthode copiée du provider réel), PHPDoc rendue exacte, test `upstream_reg_multi_sz_value_is_coerced_to_list` ajouté.

### #3 — Test NFR3 : neutralisation `generated_at` redondante

**Sévérité** : 🟡
**Fichier(s)** : `tests/Feature/ControlHub/UpstreamContractResolutionTest.php:181-187`

**Constat initial (sonnet)** : `StateHasher::hashState()` `unset` déjà `generated_at` (`VOLATILE_STATE_KEYS`) → la ligne `$bare['generated_at'] = $deco['generated_at']` est sans effet et laisse croire que le hash inclut l'horodatage. La vraie assertion forte (byte-identité scope par scope) est correcte.

**Avis Opus (1/1)** : exact mais immatériel, pure cosmétique.

**Action** : ✅ Corrigé — ligne supprimée + commentaire expliquant que `hashState()` exclut déjà `generated_at`.

### #4 — Route HKLM → Machine non testée

**Sévérité** : 🟡
**Fichier(s)** : `tests/Feature/ControlHub/UpstreamContractResolutionTest.php` (couverture)

**Constat initial (sonnet)** : tous les tests registry utilisent `HKCU`→Session ; la branche `scopeFor()` HKLM→Machine n'est jamais exercée.

**Avis Opus (2/2)** : confirmé ; logique correcte (`strcasecmp`) mais c'est précisément le routage de portée qui mérite un test.

**Action** : ✅ Corrigé — test `upstream_hklm_item_routes_to_machine_scope` ajouté (item `HKLM|...` → candidat en `SCOPE_MACHINE`, absent de `SCOPE_SESSION`).

### #5 — `parts()` silencieux sur clé malformée

**Sévérité** : 🟡
**Fichier(s)** : `app/Services/ControlHub/Resolution/RegistryUpstreamAdapter.php:74-84`

**Constat initial (sonnet)** : une clé sans `|` (`'HKCU'` seul) → `path=''`/`name=''` → candidat fantôme `exclusiveKey='hkcu||'`, sans log ni exception.

**Avis Opus (2/2)** : confirmé ; **ne peut pas écraser un local légitime** (clé différente), produit un candidat fantôme livré à l'agent (impact faible, pollution pas corruption).

**Action** : ✅ Corrigé — `toPayload()` émet un `Log::channel('agent')->warning` sur clé malformée (`< 3` segments), défauts sûrs conservés (pas d'exception, ignoré proprement côté agent). Pas de skip dur (éviterait une régression silencieuse de candidat ; le warning trace l'anomalie de configuration amont).

### M2 — Mémoïsation singleton = cache durée-conteneur (PHPDoc trompeuse)

**Sévérité** : 🟡 (latent)
**Fichier(s)** : `app/Services/ControlHub/Resolution/UpstreamContractSource.php:56-59`

**Avis Opus** : `UpstreamContractSource` garde `$resolved`/`$grouped` à vie. En PHP-FPM (pool www-admin) le conteneur est par-requête → OK. Mais `laravel/octane` est présent et les workers de queue sont long-running : si `compile()` était un jour appelé dans un worker, la source servirait un contrat **périmé** (pas de listener `ControlHubContractChanged`). Risque pratique **nul aujourd'hui** (seul `StateController` HTTP résout via `compile()`), mais la PHPDoc « pas de cache » est trompeuse — c'en est un (durée de vie conteneur).

**Action** : ✅ Corrigé — PHPDoc rendue honnête (mémoïsation = cache durée-conteneur, sûr en PHP-FPM par-requête, caveat Octane/queue long-running explicité → brancher un listener sur `ControlHubContractChanged` si l'usage migre vers un worker long-running).

### M3 / M4 / M5 / M6 — Latents notés (hors scope 28.3)

- **M3** : la source clé par `(providerType, scope)`, pas par identité de provider. Deux futurs providers de même `type()`+`scope()` recevraient les **mêmes** candidats amont (doublon en sortie exclusive). Aucun cas aujourd'hui (seul `registry` dupliqué, discriminé par scope). Fragilité architecturale à surveiller si un type est dédoublé à même portée.
- **M4** : `value=null` sur un item `locked`/`permissive` → coercé `0` (DWORD) / `''` (string/shortcuts) sans signalement. Sémantique d'un « verrou sans valeur » ambiguë mais bornée. À clarifier au format d'échange Epic 33.
- **M5** : le local transcrit `HKCR` → `hive=HKCU, path=Software\Classes` ; un item amont `HKCR` ne matche pas et n'est pas routé par le handler Go (HKLM/HKCU only) → inapplicable. Edge case explicite côté local, non géré côté amont (Epic 33).
- **M6** : `explode('|')` mis-split si un `path`/`name` contient `|` (légal pour un value name). Convention de bridge volontairement minimale → Epic 33 (schéma figé).

**Action** : ❌ Non corrigés — documentés comme coutures/fragilités à reprendre au format d'échange versionné (Epic 33) ; aucun impact sur les AC de 28.3.
