## Détail des problèmes

### #1 — Gate de type observer désaligné du chokepoint

**Sévérité** : 🟡
**Fichier(s)** : `app/Observers/UserGroupUserPivotObserver.php:115`

**Constat (review opus)** : l'observer filtrait `['classe','equipe']` alors que `syncRoleAwareAdGroupMembers` traite `['class','classe','equipe']` comme classe-like. Bénin aujourd'hui (aucun `type='class'` stocké), mais piège latent : une ligne `class` verrait ses changements de rôle non reprojetés.

**Action** : corrigé — gate aligné sur `['class','classe','equipe']` avec commentaire de traçabilité.

### #2 — Rôle NULL confondu avec « hors vocabulaire »

**Sévérité** : 🟡
**Fichier(s)** : `app/Services/UserGroupService.php` (boucle D2.2)

**Constat (review opus)** : les appelants castent le pivot `role` en string — un NULL SQL devient `''`, qui tombait dans la branche « hors vocabulaire » → `Log::warning` par membre et par projection. Comportement resté correct (fallback dérivé = ancienne partition), mais logs trompeurs si un `attach` brut recrée des NULL.

**Action** : corrigé — `''` est traité comme arête ABSENTE (défaut dérivé, silencieux) ; le warning reste réservé aux vraies valeurs hors vocabulaire.

### #3 — Parité brownfield sans membre SE4-only

**Sévérité** : 🟡
**Fichier(s)** : `tests/Unit/Services/UserGroupServiceLegacyCompatibilityTest.php` (test brownfield AC8)

**Constat (review opus)** : le test prouvait zéro retrait pour des membres SE4 présents en SQL ; le cas le plus dangereux (membre AD sans ligne SQL, protégé par le filtre `current ∩ sqlKnown` du diff) n'était pas exercé.

**Action** : corrigé — DN `prof.se4only` (sans User SQL) ajouté au fixture `Equipe_3A` ; l'assertion zéro-remove le couvre désormais explicitement.

### #4 — Contrat de consommation pour 42.3 (rafale d'updates)

**Sévérité** : 🟡 (prospectif, rien à corriger en 42.2)
**Fichier(s)** : `app/Observers/UserGroupUserPivotObserver.php`, `UserGroupService::resyncGroupAdProjection`

**Constat (review opus)** : un `sync()` associatif modifiant K rôles émet K events `updated` → K reprojections idempotentes du même groupe. Sans impact en 42.2 (le seul écrivain de masse, le read-back, est suspendu) ; 42.3 devra encadrer ses écritures en masse par `disableAdResync()` + un `resyncGroupAdProjection` explicite unique.

**Action** : documenté dans la story 42.2 (note pour 42.3) et dans ce doc — à reporter dans la story 42.3 au create-story.
