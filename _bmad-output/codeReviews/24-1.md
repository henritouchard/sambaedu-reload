## Détail des problèmes

### #1 — Regex hash sans modificateur `D`

**Sévérité** : 🟠
**Fichier(s)** : `app/Http/Requests/Api/V1/Agent/ReportRequest.php:63`

**Constat initial (review)** : `/^[0-9a-f]{64}$/` sans `D` — `$` matche avant un `\n` final ; hash forgé 65 octets passerait → varchar(64) PG 22001/500, comparaison `===` jamais vraie.

**Avis Fable** : pertinence 2. **Vecteur d'attaque partiellement faux** : le middleware global `TrimStrings` trime le `\n` avant validation (prouvé par test HTTP — 200, ni 422 ni 500). Le `/D` reste juste en défense en profondeur (la règle ne doit pas dépendre d'un middleware global).

**Action** : corrigé automatiquement — `/^[0-9a-f]{64}$/D` + test des `rules()` hors pipeline HTTP.

### #2 — History `validated()` vs « brut complet »

**Sévérité** : 🟡
**Fichier(s)** : `app/Http/Controllers/Api/V1/Agent/ReportController.php`, `app/Services/Agent/Reporting/ReportIngestService.php`, `docs/agent/report-endpoint.md`

**Constat initial (review)** : `validated()` strippe les champs inconnus que le contrat §9 tolère — perdus de l'historique de debug, alors que la doc annonce « payload brut complet ».

**Avis Fable** : pertinence 2. Recommande `$request->json()->all()` — table explicitement de debug, le brut est plus utile pour diagnostiquer un agent émettant des champs futurs. Fix trivial.

**Solutions possibles** :
1. Persister `$request->json()->all()` pour la history (recommandé)
2. Corriger la doc + docblock migration en « payload validé »

**Action** : en attente de décision utilisateur (Q1).

**Avis Fable** : pertinence 2. Collision vérifiée réelle, impact faible, fix sans ambiguïté.

**Action** : corrigé automatiquement — `dailyAt('02:35')`, commentaire et doc alignés.

### #5 — Race `updateOrCreate` sur l'UNIQUE

**Sévérité** : 🟠
