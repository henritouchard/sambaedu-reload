### #1 — Spy `DepotSyncService` (AC4) n'asserte pas dans un chemin de matérialisation réel

**Constat initial (review)** : Les deux tests AC4 posent le spy mais court-circuitent avant la boucle de matérialisation (pas de contrat / pas d'items `applications`). Le garde-fou « `DepotSyncService` jamais appelé pendant une matérialisation réelle » n'est donc pas prouvé.

**Avis Opus** : Exact, mais le risque réel ≈ 0 : `OrderedApplicationProvisioner` ne déclare même pas `DepotSyncService` en dépendance et `materializeFromSource` est un simple `firstOrCreate`. Correction triviale, valeur de non-régression.

### #A — (manqué) Idempotence concurrente PG / unique `app_id`

**Sévérité** : 🟠 — **Pertinence** : finding manqué par la review sonnet
**Fichier(s)** : schéma `applications` (`unique(depot_id, app_id)`, `depot_id` nullable), `AppStoreService::materializeFromSource`

**Constat (Opus)** : Pas d'unique sur `app_id` seul. `materializeFromSource` insère `depot_id = null` ; en PG les NULL sont distincts dans un index composite → deux exécutions concurrentes peuvent insérer deux lignes `firefox`. Invisible en SQLite. Séquentiellement correct (2ᵉ `exists()` court-circuite), ingestion sérialisée → risque réel faible, mais l'invariant « 1 ligne/app_id » n'est garanti que par convention.

**Action** : ✅ Corrigé (décision utilisateur 2026-06-29) — index unique partiel `applications_materialized_app_id_unique` sur `app_id` WHERE `depot_id IS NULL` (migration `2026_06_29_110000_*` + miroir bootstrap test). Périmètre validé : 195 tests verts.
