## Détail des problèmes

### #1 — Délégation scopée par parc inatteignable (AC5)
**Sévérité** : 🔴 · **Pertinence** : 3 · **Fichiers** : `FolderAccessRulePolicy.php`, `routes/web.php`, `folder-rules/[id]/index.blade.php`

**Constat (review sonnet)** : `FolderAccessRulePolicy::viewAny/view/manage` ne vérifient que la permission GLOBALE ; routes `folder-rules` et actions Livewire (`abort_unless(Gate::allows('manage-folderrule'))`) sont des gates globaux → un délégué scopé parc (sans droit global) prend 403 au routeur, avant que `canOnWorkstationGroup` (service) ne s'exécute. Le seul test « prouvant » AC5 appelait le service en direct, contournant Gate/route/Livewire. Bug identique à `WorkstationGroupPolicy` (story 7.1, docblock cité).

**Évaluation orchestrateur** : confirmé par lecture (policy global-only ; toutes les actions en gate global ; `RoutesProtectionTest::scopedParcRoutesProvider` ne liste pas folder-rules). AC5 réellement non satisfaite via l'app.

**Action** : ✅ Corrigé (patron 7.1 répliqué). Policy : `viewAny` = global OU `getAuthorizedWorkstationGroups('folderrule.manage')` non vide ; `view/manage($rule)` = global OU `canOnWorkstationGroup` sur ≥1 parc assigné. Routes → `can:viewAny-folderrule` (gate policy-backed) ; mount détail → `view-folderrule,$rule` ; liste filtrée par `scopedUser` ; attach/detach délégués au service (contrôle par parc). Preuve : test policy scopé (viewAny OK, parc A OK, parc B refusé, global refusé) + RoutesProtection scopé.

### #2 — Non-régression AC6 aveugle
**Sévérité** : 🟠 · **Pertinence** : 2 · **Fichier** : `RoutesProtectionTest.php`

**Constat** : les routes folder-rules absentes de `protectedRoutesProvider`/`scopedParcRoutesProvider` → le trou #1 non détecté par la baseline citée comme preuve.

**Action** : ✅ Corrigé. +2 entrées 403-sans-permission, +1 entrée délégué scopé. Vertes (échouaient avant #1 — ancrage TDD).

### #3 — `assertCanManageParc` autorise sur actor null
**Sévérité** : 🟡 · **Pertinence** : 2 · **Fichier** : `FolderAccessRuleService.php`

**Constat** : `if ($actor === null) return;` autorise sans condition. Bypass silencieux si `currentUser()` renvoie null pour un authentifié (guard fédéré non-`User`, cf. login fédéré controlHub).

**Action** : ✅ Corrigé. Méthodes système explicites `attachParcAsSystem/detachParcAsSystem` (seeds/CLI) ; UI `attachParc/detachParc` lèvent sur acteur null. Tests seeds routés vers les méthodes système.

### #4 — `deriveTrustee` casse sur virgule échappée
**Sévérité** : 🟡 · **Pertinence** : 2 · **Fichier** : `FolderAccessRule.php`

**Constat** : regex `/(?:^|,)\s*CN=([^,]+)/i` tronque un CN contenant `\,` (DN RFC 4514, ex. `CN=Salle B\, annexe,OU=Groups`) → trustee irrésoluble LSA (règle inopérante silencieuse).

**Évaluation orchestrateur** : réel quoique rare pour un nom de classe. Fix correct sans dépendance LDAP (préserve le provider PG-pur / critère Keycloak).

**Action** : ✅ Corrigé. Regex durcie `CN=((?:[^,\\]|\\.)*)` + dé-échappement. Test `CN=Salle B\, annexe,OU=Groups` → `Salle B, annexe`.

### #5 — Bouton detachParc par Gate global
**Sévérité** : 🟡 · **Pertinence** : 2 · **Fichier** : `folder-rules/[id]/index.blade.php`

**Constat** : bouton de retrait affiché à tout titulaire global, faux-positif UX une fois #1 corrigé (droit global de vue mais pas de gestion sur tous les parcs).

**Action** : ✅ Corrigé. `assignedParcs` calcule `can_manage` par parc (`canOnWorkstationGroup`) ; retrait conditionné `@if($parc['can_manage'])` ; actions règle passent la règle en ressource.
