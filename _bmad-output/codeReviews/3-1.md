## Questions en attente

> Questions nécessitant une décision d'Henri avant de pouvoir finaliser la story.

1. **Q1 (#1 + #10)** — La condition handshake `$mac === '' && $uuid === ''` actuelle dévie du legacy `empty($mac) || empty($uuid)`. Un firmware iPXE ancien qui poste MAC mais omet UUID (BIOS Lenovo, ROM pré-1.21) recevra un menu `known` au lieu d'un re-handshake → résolution potentiellement erronée. **Corriger en `||` pour parité iso-legacy stricte, ou conserver `&&` en documentant DO-14 (dérogation justifiée par UX) ?**

2. **Q2 (#7)** — `IPXE_FORCE_UEFI_PRODUCTS` env override en `(array) env(...)` cast une string CSV en singleton inutilisable. **Override env CSV nécessaire (parse via explode), ou config/ipxe.php seule source vérité (override env retiré + docblock corrigé) ?**

3. **Q3 (B3)** — `throttle:600,1` keyé par IP. En LAN scolaire avec rentrée simultanée (200+ postes), si tous passent derrière un même NAT vu par Laravel comme une IP unique → saturation à 60 postes × 10 retries. **Les postes du LAN sambaedu ont-ils chacun leur IP RFC1918 individuelle visible côté Laravel (ConfirmÉ → 600/IP OK), ou faut-il keyer par MAC/UUID ?**

4. **Q4 (#4)** — `{{ $serverBaseUrl }}` HTML-escape via Blade. Vector théorique si `Host` ou `IPXE_SE4FS_URL` contient `&` (rejeté par Symfony en HTTP mais possible via config). **Sanitisation défensive (regex `/^https?:\/\/[a-z0-9.\-:]+$/i` + `{!! !!}`) ou statu quo documenté ?**

5. **Q5 (#8)** — `$action['label']` et `$action['name']` injectés non sanitisés dans `known.blade.php`. En 3.1 `$action === null` donc code mort. **Sanitiser préventivement maintenant (3 lignes) ou laisser à 3.2 sous forme de TODO documenté ?**

## Détail des problèmes

### #1 — Condition handshake `&&` au lieu de `||` : dérogation iso-legacy non documentée

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Ipxe/Services/IpxeService.php:55` + `tests/Feature/Ipxe/IpxeBootEndpointTest.php:59`

**Constat initial (review sonnet)** :
Le legacy `sambaedu/ipxe/boot.php:26` teste `empty($mac) || empty($uuid)` (handshake si l'un OU l'autre est vide). L'implémentation 3.1 teste `$mac === '' && $uuid === ''` (handshake seulement si LES DEUX sont vides). Régression non documentée vs D4 "iso-legacy stricte".

**Avis Opus** : pertinence **3**. Vérifié dans le code. Cas usage réel : iPXE chargé sans `${uuid}` posé sur certains BIOS Lenovo, iPXE rom-builtin pré-1.21. Le commentaire ligne 54 dit "premier appel sans paramètres" — ambigu. La déviation `&&` n'est pas formalisée en DO-N.

**Solutions possibles** :
1. **Aligner sur legacy** : `if ($mac === '' || $uuid === '')` — parité stricte
2. **Documenter dérogation** : ajouter DO-14 dans Dev Agent Record + test couvrant les 2 cas asymétriques (MAC sans UUID, UUID sans MAC)

**Action** : en attente décision Henri (Q1)

### #2 — Renders non protégés par try/catch → exception Blade = 500 HTML au lieu de text/plain

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Ipxe/Services/IpxeService.php:62, 72, 78-84`

**Constat initial (review sonnet)** :
3 appels renderer sans try/catch. Une exception Blade remontera au handler Laravel qui retourne du HTML/JSON, jamais `text/plain` (viol D10). L'event `ipxe.boot.render_error` (D7) n'est jamais émis.

**Avis Opus** : pertinence **3**. Vérifié. Probabilité faible en stable mais coût élevé (poste bloqué au boot, pas de menu = noir + reboot). Couplé avec #3.

**Solutions possibles** :
```php
try {
    $body = $this->renderer->renderKnown($workstation, $action, $baseUrl);
} catch (\Throwable $e) {
    Log::channel($this->channel())->error('ipxe.boot.render_error', [
        'action_type' => 'ipxe.boot.render_error',
        'exception_class' => $e::class,
        'message' => mb_substr($e->getMessage(), 0, 200),
        'ip' => $ip,
        'mac_prefix' => mb_substr($mac, 0, 6),
        'uuid_prefix' => mb_substr($uuid, 0, 8),
    ]);
    return $this->respond("#!ipxe\necho Erreur serveur SE4FS\nsleep 10\nexit 0\n");
}
```

**Action** : correction automatique étape 8

### #4 — `{{ $serverBaseUrl }}` HTML-encodé → chaîne `chain` cassée si Host contient `&`

**Sévérité** : 🟠 Important
**Fichier(s)** : `resources/views/ipxe/menu/known.blade.php:24, 34` + `app/Ipxe/Services/IpxeMenuRenderer.php:102`

**Constat initial (review sonnet)** :
`{{ $serverBaseUrl }}` HTML-escape via Blade. Si Host header contient `&`, rendu `&amp;` casse iPXE.

**Avis Opus** : pertinence **1**. Vector quasi-théorique : Symfony `Request::getHost()` valide via regex et rejette les Host avec `&`. Mais : `config('ipxe.se4fs_url')` setté manuellement avec un `&` (admin maladroit) déclenche le bug.

**Solutions possibles** :
1. Passer `serverBaseUrl` en `{!! !!}` après sanitisation upstream regex `/^https?:\/\/[a-z0-9.\-:]+$/i`
2. Documenter le comportement et accepter le risque (rare)

**Action** : en attente décision Henri (Q4)

### #5 — `assertSame(1, count)` fragile sans isolation transactionnelle

**Sévérité** : 🟠 Important
**Fichier(s)** : `tests/Feature/Ipxe/IpxeBootEndpointTest.php:167-172`

**Constat initial (review sonnet)** :
SQLite `:memory:` partagée, pas de `RefreshDatabase` ni `DatabaseTransactions`. Tests précédents dans la même classe ont inséré des rows `machine_boot_logs` → count > 1 → assertion FAIL.

**Avis Opus** : pertinence **3** — **plus grave que pondéré par Sonnet**. Vérifié : `TestCase.php` n'use pas RefreshDatabase, `IpxeSchemaBootstrapper` est idempotent (pas de truncate). **Solutions possibles** :
1. Ajouter `use RefreshDatabase` dans la classe de test
2. Filtrer le count par discriminant unique (e.g. `where('machine_name', 'pc-logged-1234')` avec machine_name unique au test)
3. Truncate `machine_boot_logs` en `setUp()`

**Action** : correction automatique étape 8 (solution 2 — moins intrusive)
