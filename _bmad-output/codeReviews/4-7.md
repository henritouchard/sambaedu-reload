## Détail des problèmes

### #1 — Mapping APCu cassé : `user`/`machine` sont des arrays LDAP

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Dto/Wallpaper/WallpaperContext.php:65-70`
**AC concerné** : AC 3, AC 4, AC 5

**Constat initial (Sonnet)** :
Dans le dict APCu posé par `applications.inc.php:983`, les clés `user` et `machine` sont des **tableaux AD** (`user['cn']`, `user['fullname']`, `machine['cn']`). `WallpaperContext::fromApcuArray` fait :
```php
userLogin: (string) ($apcu['user'] ?? ''),        // → "Array"
machineName: (string) ($apcu['machine'] ?? ''),   // → "Array"
```
En prod : `userLogin = "Array"` → niveau 6 (per-user) cassé, bandeau affiche `"Array"` partout. Tests ne détectent pas car `seedContext()` passe `'user' => 'jdoe'` (string).

**Avis Opus (3/3)** :
Confirmé après lecture de `sambaedu/includes/applications.inc.php:894` (`$machinel = search_machine(...)`) et `:908` (`$userl = search_user(...)`) — arrays LDAP. Ligne 983-988 APCu stocke `'user' => $userl`, `'machine' => $machinel`. PHP 8+ : `(string)$array` → `"Array"` + E_WARNING. **La variable `'salle'` par contre est bien un string** (cf. `applications.inc.php:920`, `ldap_dn2cn()`). Donc `salleName` OK.
**Aggravation** : Les tests passent parce qu'ils seed avec strings — coverage trompeur.

**Solutions possibles** :
1. Corriger `fromApcuArray` avec check `is_array` :
   ```php
   userLogin: (string) (is_array($apcu['user'] ?? null)
       ? ($apcu['user']['cn'] ?? '')
       : ($apcu['user'] ?? '')),
   userFullname: is_array($apcu['user'] ?? null)
       ? (string) ($apcu['user']['fullname'] ?? $apcu['user']['cn'] ?? '')
       : (string) ($apcu['fullname'] ?? $apcu['cn'] ?? ''),
   machineName: (string) (is_array($apcu['machine'] ?? null)
       ? ($apcu['machine']['cn'] ?? '')
       : ($apcu['machine'] ?? '')),
   ```
2. Ajouter un test `ApcuWallpaperContextRepositoryTest` qui seed la **vraie structure** avec arrays `user['cn']`, `user['fullname']`, `machine['cn']`.

**Action** : ⏳ **Correction auto** (pattern clair, pas de choix architectural)

2. Alternative : donner aux orphans un `owner_type='orphan'` synthétique (lien avec #D)

**Constat** :

**Solutions possibles** :
1. Ajouter `$file->getMimeType()` ou `exif_imagetype($file->getRealPath())` dans `assertValidFile`.
2. Doublon avec #10 pour les limites Imagick.
