## Détail des problèmes corrigés automatiquement

### #5 — `ca_cert_pem` vide silencieux quand PKI non initialisée (CRITIQUE)

**Sévérité** : 🔴 Critique — Pertinence Opus 3/3
**Fichier(s)** : `app/Auth/V1/Http/Controllers/EnrollController.php:91-103`

**Constat** : Le controller catchait `RuntimeException` de `CaInitializer::getCaCertPem()` et retournait `200 success` avec `ca_cert_pem = ''`. Le poste se retrouvait sans CA root → soit refus HTTPS, soit bascule en mode "skip CA verify" (faille critique : MitM possible avec n'importe quel cert self-signed).

**Action** : Retour `503 service_unavailable` avec message explicite, hors environnements `local`/`testing` (où le mock est utilisé dans les tests).

### #7 — `writeSecureFile` non atomique (race chmod 0600)

**Sévérité** : 🟠 Important — Pertinence Opus 2/3
**Fichier(s)** : `app/Auth/V1/Pki/CaInitializer.php:587-606`

**Constat** : `file_put_contents()` → `chmod(0600)` laissait une fenêtre où la clé privée existait avec umask par défaut (souvent 0644).

**Action** : Wrap `umask(0077)` autour du `file_put_contents` pour les fichiers privés (`0600`), restauration dans `finally`. Garantit que le fichier est créé directement avec 0600 sans fenêtre.

### #9 — `DualModeCoexistenceTest` + `AuthV1NamespaceTest` listes incomplètes

**Sévérité** : 🟠 Important — Pertinence Opus 2/3
**Fichier(s)** : `tests/Feature/Auth/V1/DualModeCoexistenceTest.php:67`, `tests/Architecture/AuthV1NamespaceTest.php:263-270`

**Constat** : Les 2 tests gardent-fou D8 vérifiaient 6 routes legacy mais oubliaient `gpo/shortcuts_out.php` et `gpo/applications.php`. `applications.php` est **critique** car c'est l'endpoint qui distribue les bootstrap tokens md5/APCu consommés par `/api/v1/agent/enroll`. Une refacto qui le supprimerait casserait toute la chaîne d'enrôlement.

**Action** : Ajout de `'shortcuts_out'` et `'applications'` (sans `_out`) aux deux listes de routes attendues + alignement du docblock.

### #10 — `EnsureRefreshToken::expires_at instanceof Carbon` fragile

**Sévérité** : 🟡 Mineur — Pertinence Opus 1.5/3
**Fichier(s)** : `app/Auth/V1/Http/Middleware/EnsureRefreshToken.php:87`

**Constat** : Si le cast Eloquent retournait `null` ou string mal formée, la condition `instanceof Carbon` court-circuitait silencieusement → token expiré laissé passer.

**Action** : Fail-secure — si `expires_at` n'est pas une instance Carbon valide, traiter comme expiré (return 401 `refresh.expired`).

### #4 — Test `missing_bootstrap_token` mock inutile

**Sévérité** : 🟠 Important — Pertinence Opus 2/3
**Fichier(s)** : `tests/Feature/Auth/V1/EnrollControllerTest.php:127-134`, `tests/Unit/Auth/V1/Http/Middleware/RequireBootstrapTokenTest.php:37-45`

**Constat** : Les tests `missing_*` mockaient `bootstrapTokenValid(false)` mais le mock n'était jamais appelé (middleware rejette avant sur header absent). Test passe par coïncidence — si on inversait l'ordre des checks, les tests passeraient toujours.

**Action** : Retirer les mocks superflus + ajouter `shouldNotReceive('isValid')` pour figer l'invariant "header absent court-circuite la validation".

### #A — Pas de headers HSTS / Cache-Control sur réponses tokens (CRITIQUE)

**Sévérité** : 🔴 Critique — Pertinence Opus 3/3
**Fichier(s)** : `app/Auth/V1/Http/Controllers/EnrollController.php`, `RefreshController.php`, `PingController.php` + new middleware `EnsureSecureApiHeaders`

**Constat** : Les réponses d'enrôlement et de refresh contiennent `access_token` + `refresh_token` clear dans le body. Sans `Cache-Control: no-store, no-cache`, des proxies intermédiaires (entreprise, WiFi public, CDN) pourraient cacher la réponse. Sans HSTS, un attaquant MitM pourrait downgrade HTTPS → HTTP.

**Action** : Création middleware `EnsureSecureApiHeaders` appliqué au groupe `/api/v1/agent/*` ajoutant `Cache-Control: no-store, no-cache, must-revalidate, private` + `Pragma: no-cache` + `Strict-Transport-Security: max-age=31536000; includeSubDomains` (compat anciens postes Win 8.1+ : HSTS sans `preload`).

### #B — `WorkstationJwtVerifier` sans garde-fou symétrique fixtures-test-en-prod

**Sévérité** : 🟠 Important — Pertinence Opus 2/3
**Fichier(s)** : `app/Auth/V1/Jwt/WorkstationJwtVerifier.php:135-159`

**Constat** : `WorkstationJwtIssuer.php:137-144` a un garde-fou `forbid_test_keys_in_production` mais le Verifier lit les fichiers sans la même vérification. Sur un déploiement prod mal configuré (env vars mal positionnées pointant sur `tests/fixtures/`), le Verifier accepterait des JWT signés avec la clé publique des fixtures committées au repo.

**Action** : Ajout du même garde-fou symétrique dans `WorkstationJwtVerifier::buildKeyMap()` — skip toute clé dont le path matche `tests/fixtures/` en environnement `production`, log `critical`.

### #1 — Limitation révocation access tokens 24h dans runbook

**Sévérité** : 🟠 Important — Pertinence Opus 2.5/3
**Fichier(s)** : `docs/qa/domains/auth.md`

**Constat** : La doc QA mentionne « 24h » de manière elliptique mais ne dit pas explicitement que `workstation:revoke` ne révoque pas les access tokens. L'admin ops qui suit le runbook pour révoquer un poste compromis pourrait croire à une révocation complète immédiate.

**Action** : Ajout d'un encadré explicite dans Section Révocation expliquant la limitation Phase 2 (revoke = refresh-only, fenêtre 24h max access). Mention de l'option `auth:ca:init --force` pour une révocation totale immédiate (régénère paire JWT → kid disparaît → tous les access tokens deviennent invalides).

### #I — `replace_placeholders=true` sur channel `auth-v1`

**Sévérité** : 🟠 Important — Pertinence Opus 2/3
**Fichier(s)** : `config/logging.php:184`

**Constat** : Le channel `auth-v1` est SECURITY-CRITICAL. Si un attaquant arrive à logger une string contrôlable contenant `{placeholder}`, Laravel essaiera de remplacer depuis le context. Inutile pour ce channel.

**Action** : `'replace_placeholders' => false` sur `auth-v1`.
