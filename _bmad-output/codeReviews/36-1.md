## Détail des problèmes

### #1 — Branche `absent` : cible recalculée au lieu du store
**Sévérité** : 🔴 · **Pertinence** : 3 · **Fichier** : `agent/shared/handler_fs_acl.go` (branche `absent` de `Apply`)

**Constat (review sonnet)** : `target := spec.targetAce(sid)` est calculé depuis le payload COURANT ; la branche `present` consulte pourtant `store[id]`. Si `rights`/`applies_to` d'une capacité changent, un poste en `present` (ACE ancien masque, mémorisée) qui bascule `absent` au même cycle recalcule `target` avec le nouveau masque → `RemoveAce` ne trouve rien, mais `store[id]` est supprimé inconditionnellement → ACE orpheline permanente, `Test()` rapporte `compliant` à tort.

**Évaluation orchestrateur** : confirmé par lecture directe (branche `absent` ~l.554 utilisait `target` + `delete` inconditionnel ; branche `present` lit bien `store[id]`). Bug latent réel du handler générique (ne se déclenche pas avec le seed actuel — `rights`/`applies_to` constants — mais impacte toute future capacité/36.2/36.4 qui varierait ces champs). Exactement le scénario que le store D4 devait empêcher.

**Action** : ✅ Corrigé. La branche `absent` retire `rec.ace()` (ACE du store) si une entrée existe, fallback `target` sinon ; `Test()` juge la conformité `absent` sur l'ACE du store. Test Go `TestFsAclAbsentRemovesStoredAceNotRecomputed`.

### #2 — Q2 non appliqué au runtime (garde-fou « serveur ET agent »)
**Sévérité** : 🔴 · **Pertinence** : 3 · **Fichiers** : `FsAclCapabilityProvider.php`, `handler_fs_acl.go`, `AppServiceProvider.php`

**Constat (review sonnet)** : `violations()` n'a aucun appelant hors tests (le provider ne réutilise que les constantes d'enum) ; l'agent ne refuse que les SID système well-known (trustee), jamais un `deny` à héritage descendant sur racine protégée. La variante que Q2 devait rendre *inexprimable* était seulement « absente du catalogue », pas structurellement impossible : une migration/un bug 36.4 pouvait injecter `{path: C:\Windows, deny, folder_subfolders_files}` — compilée, servie, appliquée telle quelle.

**Évaluation orchestrateur** : confirmé (`grep` : 0 appelant de `violations()` ; aucun observer `CapabilityProjection` ; handler sans garde racine-protégée). Viole le garde-fou epic explicite « validation d'authoring serveur ET refus agent (défense en profondeur) ». AC de 36.1 non réellement satisfaite (validation seulement testée, pas active).

**Action** : ✅ Corrigé, deux volets.
- **2a (agent)** : helpers Go miroir du guard PHP (racines protégées + normalisation + noms courts) ; refus dans `Apply` ET `Test` (erreur d'item isolée) d'un `deny` descendant sur racine protégée ; `deny list_folder folder_only` sur Program Files PASSE (variante autorisée Q2). Tests Go dédiés. C'est le filet ultime : même une projection fautive ne casse pas le poste.
- **2b (serveur)** : observer `CapabilityProjectionObserver` (`saving`, uniquement `mechanism==='fs_acl'`) appelant `violations()` et levant `FsAclAuthoringException` ; enregistré dans `AppServiceProvider::boot` (gaté hors `testing`, patron Workstation). Test Feature 6 cas. Protège 36.4 par construction.

### #3 — Noms courts 8.3 contournent Q2
**Sévérité** : 🟠 · **Pertinence** : 2 · **Fichier** : `FsAclAuthoringGuard.php`

**Constat (review sonnet)** : comparaison Q2 strictement textuelle ; `C:\PROGRA~1` désigne physiquement `C:\Program Files` mais ne matche aucune racine protégée → `deny` descendant appliqué sur la racine réelle.

**Évaluation orchestrateur** : réel (8.3 activé par défaut sur le volume système). Le serveur ne peut résoudre le nom long (pas d'accès FS), donc refus à l'authoring.

**Action** : ✅ Corrigé. `hasShortName83` (motif `~[0-9]`) refuse tout chemin à segment court 8.3, au guard ET côté agent. Tests des deux côtés.

### #4 — Listes principals système divergentes
**Sévérité** : 🟠 · **Pertinence** : 2 · **Fichier** : `FsAclAuthoringGuard.php`

**Constat (review sonnet)** : le guard bloque des noms énumérés ; l'agent bloque tout `S-1-5-32-*`/`S-1-5-80-*`. Un `deny` sur `BUILTIN\Backup Operators` passe l'authoring puis échoue à chaque cycle agent (capacité inerte, jamais signalée).

**Évaluation orchestrateur** : réel (UX : capacité silencieusement inerte). Alignement parfait impossible (serveur = noms, agent = SID, NFR7). Alignement par nom possible sur les préfixes.

**Action** : ✅ Corrigé. `isSystemTrustee` refuse aussi les préfixes `BUILTIN\` et `NT SERVICE\` (docblock : autorité finale = agent/SID). Tests guard + Feature.

### #5 — Store persisté une seule fois par passe
**Sévérité** : 🟡 · **Pertinence** : 2 · **Fichier** : `handler_fs_acl.go`

**Constat (review sonnet)** : `writeFsAclState` appelé une seule fois en fin de passe ; crash entre un `RemoveAce` réussi et l'écriture → disque sans l'ACE, store désynchronisé (transitoire, auto-réparé au cycle suivant, mais fenêtre fail-open sur un deny).

**Évaluation orchestrateur** : réel mais mineur (self-healing, fail-open = mode de défaillance le plus sûr pour un deny). Fix cheap.

**Action** : ✅ Corrigé. Closure `persist()` appelée après chaque mutation réussie ; écriture uniquement sur mutation (2 passes stables = zéro I/O). Tests Go de stabilité verts.
