## Détail des problèmes

### #1 — `Read` : conflation type/présence sur le chemin `ensure:"absent"`

**Sévérité** : 🟠
**Fichier(s)** : `agent/windows/handler_registry_windows.go` (branche `default` de `Read`), `agent/shared/handler_registry.go` (doc `RegistryOps.Read`), `agent/shared/handler_registry_test.go`

**Constat (review opus)** :
`Read` renvoyait `present=false` pour toute valeur d'un type hors {DWORD, QWORD, SZ, EXPAND_SZ, MULTI_SZ}. Inoffensif pour un item d'écriture (apply réécrit), mais fatal pour un item `ensure:"absent"` : une valeur réellement existante en REG_BINARY/REG_NONE/REG_LINK était vue absente ⇒ jugée conforme ⇒ jamais supprimée, rapportée `compliant`. Exactement le « résidu » silencieux que la story élimine. Le fake en mémoire (présence = existence de clé de map) masquait le bug ; aucun test n'exerçait ce chemin. Socle réutilisé par 35.2/35.5.

**Solution appliquée** :
La branche `default` de `Read` renvoie désormais `present=true` avec un Kind sentinelle hors contrat `"REG_UNSUPPORTED"` : le chemin `absent` voit la valeur et la supprime (AC3 strict) ; le chemin d'écriture garde son comportement historique (`Equal()` échoue sur le Kind → réécriture au type cible). Doc de l'interface `RegistryOps.Read` mise à jour (présence indépendante du type). Test shared ajouté : `TestRegistryAbsentDeletesValueOfUnmanagedKind` (valeur `REG_UNSUPPORTED` présente + item absent ⇒ Test false ⇒ Apply supprime ⇒ re-Test true).

**Action** : corrigé automatiquement (l'AC3 tranchait déjà la question de périmètre).

### #2 — Relabel asymétrique du retrofit

**Sévérité** : 🟡
**Fichier(s)** : `database/migrations/2026_07_03_100000_retrofit_ensure_off_on_only_capabilities.php`

**Constat (review opus)** :
Le retrofit conservait « Géré » pour `windows_updates_managed` mais imposait « Activé » à `llmnr_disabled` (origine des deux seeds = « Géré »). Changement non requis par l'AC4, divergence up() ≠ inverse(down()) sur ce libellé. Zéro impact flotte (métadonnée UI, jamais dans le payload compilé).

**Solution appliquée** :
`'on' => 'Géré'` pour les deux (libellés d'origine conservés, le retrofit n'ajoute que le « off ») + commentaire de décision dans la migration. Dev Agent Record de la story mis à jour.

**Action** : corrigé automatiquement (option 1 de la review — symétrie, moindre choix).

### #3 — Angle mort du test de réversibilité

**Sévérité** : 🟡
**Fichier(s)** : `tests/Feature/Migrations/CapabilitiesSchemaAndSeedTest.php` (`retrofit_migration_is_idempotent_and_reversible`)

**Constat (review opus)** :
Après `down()`, le test n'assertait que `allowedOptionValues() === ['on']` — un down() restaurant un mauvais libellé passait silencieusement.

**Solution appliquée** :
Assertion ajoutée : `options === [['value' => 'on', 'label' => 'Géré']]` pour les deux capacités après down(). Le volet Go du finding (fake ne modélisant pas le type) est couvert par le test du #1.

**Action** : corrigé automatiquement.
