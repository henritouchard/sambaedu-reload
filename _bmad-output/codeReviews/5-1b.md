## Détail des problèmes

### #1 — Label console inversé + absence log D2 réel

**Sévérité** : 🟠 Important
**Fichier(s)** : `app/Console/Commands/QuotaSnapshotCommand.php:90,292-302`

**Constat Sonnet** :
Le code logge les logins XFS sans correspondance BDD (comptes système non synchronisés) alors que la spec D2 demande de logger les users BDD absents du rapport XFS. Le label console `users BDD absents du rapport : %d` est sémantiquement inversé par rapport au compteur `$stats['missing']` (qui compte l'inverse). La doc `docs/domains/filesystem.md:108` documente `Log::info('QuotaService: user absent du rapport XFS', ...)` — log inexistant dans le code.

**Avis Opus (2/3)** :
Vérifié : le compteur `$stats['missing']` = `count($missingFromDb)` où `$missingFromDb = array_diff($allLogins_XFS, $foundLogins_BDD)` → logins XFS sans BDD. Le commentaire interne lignes 285-291 reconnaît explicitement la limitation ("on ne peut pas les lister ici sans une seconde query"). La fonctionnalité D2 (logger les users BDD absents) est **non-implémentée** alors que la doc dit le contraire. Sévérité légèrement plus haute que "label inversé".

**Solutions** :
1. Implémenter le vrai D2 : requête `User::query()->whereNotIn('login', $allLogins)->whereNotNull('quota_snapshot')->pluck('login')` + loop `Log::info('QuotaService: user absent du rapport XFS', ['login' => ..., 'partition' => ...])`.
2. Corriger le label console : `'logins XFS sans correspondance BDD : %d'`.
3. Aligner la doc sur le comportement effectif.

**Action** : corriger automatiquement (options 1+2+3).

### #3 — Rapport XFS vide efface silencieusement les snapshots existants

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Console/Commands/QuotaSnapshotCommand.php:266-277`

**Constat Sonnet** :
Si `parseReport('/var/sambaedu')` retourne `[]` (succès pipeline mais 0 ligne remontée), la boucle `updateSnapshots()` exécute `unset($snapshot[partitionKey])` pour CHAQUE user → tous les snapshots sambaedu sont effacés silencieusement.

**Avis Opus (3/3)** :
Pire que décrit — **perte de données silencieuse à chaque run** dès qu'une partition retourne 0 résultat. Le commentaire lignes 269-271 ("on nettoie la clé pour refléter l'état réel") est intentionnel mais conflate "absent du rapport" avec "rapport vide" — cas critiquement différents. Contradiction explicite avec D2. Le test `it_updates_users_in_batch` reproduit accidentellement ce cas (sambaedu output `''`) mais ne l'assert pas.

**Solutions** :
1. Distinguer `null` (rapport-échec, conserver) vs `[]` (rapport-vide, conserver aussi par cohérence D2) vs present (mettre à jour).
2. Supprimer le `unset()` ligne 272. Un user absent du rapport = snapshot conservé, pas effacé.
3. Ajouter un test `it_preserves_sambaedu_snapshot_when_report_is_empty`.

**Action** : corriger automatiquement (priorité 1 — sécurité des données).

### #5 — Double arrondi du `percent` (perte de précision marginale)

**Sévérité** : 🟡 Mineur
**Fichier(s)** : `app/Console/Commands/QuotaSnapshotCommand.php:328-334`, `quota-section.blade.php:215`

**Constat Sonnet** :
Le `percent` est calculé depuis `used_mb / soft_mb` arrondis, au lieu de `used_kb / soft_kb`. Cas `used=1000kb, soft=1023kb` → percent=100% au lieu de 98%.

**Avis Opus (1/3)** :
Validation override impose soft >= 10 Mo → erreur d'arrondi < 1 point en pratique. **Sonnet a raté** que le même bug existe dans `buildPartitionSnapshotFromUsage()` (refresh manuel). Cohérence à améliorer mais pas critique.

**Solution** :
`$percent = $raw['soft_kb'] > 0 ? min(100, (int) round($raw['used_kb'] / $raw['soft_kb'] * 100)) : 0;` — aux deux endroits.

**Action** : corriger automatiquement (en passant, trivial).

`RateLimiter::attempt('quota-refresh:' . auth()->id(), 5, fn() => ..., 60)`.
