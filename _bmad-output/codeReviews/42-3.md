## Détail des problèmes

### #1 — 500 au re-render de la page classe (défaut pré-existant, gate de la story)

**Sévérité** : 🔴
**Fichier(s)** : `_partials/head-teacher-section.blade.php`, `_partials/class-share-section.blade.php` (cause) ; toute action du parent `index.blade.php` (symptôme)

**Constat (review opus, REPRODUIT par 3 probes vrai canal)** : `updateMemberRole` sur classe → `ViewException: Invalid Livewire child tag name` ; `removeMember` INCHANGÉ sur classe → erreur identique (pré-existant) ; sur `projet` → OK. Cause : les 2 SFC enfants structuraient leur template autour d'un `@if (!$isClasse) … @else … @endif` de premier niveau ; le marqueur `<!--[if BLOCK]>` de `SupportMorphAwareBladeCompilation` fait capturer un tag racine vide par `SupportNestingComponents` au re-render. L'écriture pivot réussissait côté serveur (succès partiel + crash navigateur).

**Action** : corrigé — les deux partials enveloppés dans une balise racine `<div>` stable (avec commentaire de traçabilité). Débloque l'édition de rôle 42.3 ET `removeMember` existant. Vérifié par les 6 tests rebasculés sur `->call()` (verts).

### #2 — AC2 « jamais de 500 » — résolu par #1 ; le test valeur-invalide passe désormais par le vrai canal sur fixture classe.

### #3 — Garde owner sur le type DB

**Constat (review opus)** : `$this->type` est une propriété Livewire publique non `#[Locked]` ré-hydratée du client — un payload forgé `type='classe'` sur un groupe `projet` contournait le refus D3 owner-hors-classe (impact faible : l'appelant a déjà `update-group`).

**Action** : corrigé — la garde owner est déplacée APRÈS le chargement du groupe et compare `$group->type` (DB).

### #4 — Tests classe hors du vrai canal

**Action** : corrigé — les 6 mutations `->instance()->updateMemberRole(...)` rebasculées en `->call('updateMemberRole', ...)->assertOk()` ; la note de contournement remplacée. Les lectures de computed (`members()`, `availableUsers()`) restent en accès direct (légitime).

### #5 — Surcharge au rattachement sur type réel non-classe

**Constat (review opus)** : `updateExistingPivot` est un no-op silencieux si l'arête n'existe pas ; le fake de test garantit l'arête. En pratique les arêtes SONT créées par le flux réel (fonctionnalité existante) — confiance modérée, pas de bug avéré.

**Action** : à valider au runbook e2e /vm différé (surcharge d'un rôle au rattachement sur un groupe non-classe réel) — consigné doc QA §17.
