### #1 — HOSTNAME_REGEX incompatible avec `cups_name` contenant underscore

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Services/Print/PrintDriverService.php:460,688,714` + `app/Services/Print/CupsPrinterService.php:39`

**Constat initial (Sonnet)** :
`PrintDriverService` réutilise `HOSTNAME_REGEX = '/^[a-zA-Z0-9][a-zA-Z0-9-]{0,14}$/'` pour valider les `cups_name` dans `getDriverForPrinter()`, `attachDriverToPrinter()` et `detachDriverFromPrinter()`. Or `CupsPrinterService::NAME_REGEX = '/^[a-zA-Z0-9_-]{1,15}$/'` autorise les underscores. Les tests 6.1 utilisent des noms avec underscores (`imp_mine`, `imp_other`, `imp_orph` dans `tests/Feature/Livewire/Parc/PrintersTabTest.php:171-176`).

**Avis Opus** : Note **3/3 — confirmé bug bloquant**.
Vérifié à `PrintDriverService.php:460,688,714` et `CupsPrinterService.php:39`. Régression silencieuse côté UX : un admin qui ouvre la modale d'édit d'`imp_mine` voit le banner « Samba injoignable » (faux positif). Aucun test 6.2 ne déclenche le bug (tous utilisent `imp1/impd/impatt` sans underscore). Impact upload : impossible d'uploader un driver pour `imp_mine` (l'étape 5 rejette le cups_name).

**Solutions possibles** :
1. Ajouter une méthode `validateCupsName(string $name): void` séparée utilisant `CupsPrinterService::NAME_REGEX` (recommandée).
2. Importer la constante `CupsPrinterService::NAME_REGEX` dans `PrintDriverService` et l'utiliser.

**Action** : ✅ corrigé automatiquement — créer `validateCupsName()` séparée + remplacer les 3 appels `validatePivotHostname($cupsName)` + ajouter test data-provider `valid_cups_names_with_underscore`.

### #13 — Regex parsing `getDriverForPrinter` greedy split incorrect avec virgule

**Sévérité** : 🟡 Mineur
**Fichier(s)** : `app/Services/Print/PrintDriverService.php:478` + `:438`

**Constat (Opus, nouveau)** :
Les regex `/^\s*description:\s*\[(.+),(.+),(.+)\]\s*$/` (getprinter) et la variante enumprinters sont greedy. Si `smb_driver` ou `smb_comment` contient une virgule (ex. `Acme, Inc Printer`), le split est faux.
