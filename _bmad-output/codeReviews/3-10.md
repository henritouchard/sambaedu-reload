## Détail des problèmes

### #M1 — 🔴 Path traversal `.`/`..` dans le nom de famille (trouvé par le second avis opus, manqué par sonnet)

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Ipxe/Iso/Services/WinpeDriverIngestor.php` (`validateFamily`) + `resources/views/pages/admin/ipxe/iso-windows/index.blade.php` (validation Livewire)

**Constat** :
La regex anti-traversal `^[A-Za-z0-9._-]+$` bloque le `/` mais **autorise `.` et `..`** (`preg_match('/^[A-Za-z0-9._-]+$/', '..')` → `1`). Le test existant `it_validates_the_family_name` ne testait que `../evil` (avec slash, bloqué) → fausse impression de couverture.
- `famille = ".."` → `$familyDir = $packPath . '/..'` = **`storage/install`** (parent du pack). `removeDirectory($familyDir)` efface RÉCURSIVEMENT `storage/install/iso` (ISO sources multi-Go), `.uploads`, etc. **Perte de données catastrophique depuis un simple champ texte / argument CLI.**
- `famille = "."` → efface toutes les familles du pack.
Les deux points d'entrée (CLI + upload Livewire) délèguent à la même `validateFamily` (rempart centralisé, mais troué).

**Avis Opus** : pertinence 3/3 — prouvé par le code ; seul finding à conséquence grave ; la solution proposée (durcir `validateFamily`) est la bonne, point unique.

**Solution appliquée** :
`validateFamily` exige désormais **au moins un caractère alphanumérique** (`preg_match('/[A-Za-z0-9]/', …)`) en plus de la liste blanche → rejette `.`, `..`, `...`, `--`, `__`. Test `it_rejects_dot_only_family_names` (DataProvider 5 cas) ajouté, `Process::assertNothingRan()` prouve qu'aucune suppression n'est tentée.

**Action** : ✅ Corrigé automatiquement.

### #5 — 🟠 `removeDirectory` silencieuse → résidu mélangé

**Sévérité** : 🟠 Important
**Fichier(s)** : `app/Ipxe/Iso/Services/WinpeDriverIngestor.php` (`ingest`)

**Constat** :
`removeDirectory()` est `@`-silencieuse. Si un ancien fichier de la famille est root-owned (ex. un précédent `sudo artisan …:ingest`), la purge échoue sans bruit, `mkdir` voit le dossier déjà présent (`is_dir` vrai), et anciens + nouveaux pilotes coexistent → mélange injecté dans le boot.wim sans erreur.

**Avis Opus** : pertinence 2/3 — réel et prouvé ; nuance : `!is_dir` seul ne suffit pas (le dossier est recréé juste après) → vérifier qu'il est bien **vide**.

**Solution appliquée** :
Après `removeDirectory($familyDir)`, si le dossier existe encore **avec des fichiers** (`directoryHasFiles()`) → `WinpeDriverIngestionException` explicite (droits/propriétaire). Helper `directoryHasFiles()` ajouté.

**Action** : ✅ Corrigé automatiquement.

### #1 — 🟠 `refreshDriverFamilies()` non-récursif + case-sensitive + duplication (viole D3)

**Sévérité** : 🟠 Important
**Fichier(s)** : `resources/views/pages/admin/ipxe/iso-windows/index.blade.php` + `app/Ipxe/Iso/Services/WinpeDriverInjector.php`

**Constat** :
Le composant comptait les `.inf` avec `glob($dir.'/*.inf')` : **non-récursif ET sensible à la casse**. L'injecteur (`collectFamilies`/`findInfFiles`) est récursif + `strtolower(...)==='inf'`. Les packs Lenovo/Intel livrent souvent des `*.INF` majuscules → l'UI affiche « 0 .inf » alors que l'injection les trouve et les injecte (l'UI ment sur l'état réel). De plus, logique de comptage dupliquée → viole D3 (« zéro duplication »).

**Avis Opus** : pertinence 2/3 — sonnet a vu la récursivité mais **manqué la casse** `.INF`, qui est le vrai bug pratique. Solution (rendre `collectFamilies` public et réutiliser) corrige les deux d'un coup.

**Solution appliquée** :
`WinpeDriverInjector::collectFamilies()` rendu **public** (source unique de comptage). `refreshDriverFamilies()` délègue via `app(WinpeDriverInjector::class)->collectFamilies($packPath)`. Import ajouté.

**Action** : ✅ Corrigé automatiquement.

### #6 — 🟡 Commentaire erroné `-s` innoextract + doute validité `-q`

**Sévérité** : 🟡 Mineur
**Fichier(s)** : `app/Ipxe/Iso/Services/WinpeDriverIngestor.php` (`extractArchive`)

**Constat** :
Commentaire « `-s` extract files » : faux, `-s` = `--silent`. Plus important (opus) : la combinaison `innoextract -s -q -d` n'a jamais été exécutée contre un vrai binaire (tests `Process::fake()`, hôte sans innoextract). `-q` non garanti standard → risque en prod.

**Avis Opus** : pertinence 2/3 — au-delà du cosmétique ; ajouter une validation VM réelle.

**Solution appliquée** : commentaire corrigé (`-s`/`-q` silencieux, extraction par défaut) + renvoi explicite au smoke e2e VM. **Validité réelle de `-q` → Q2 (action Henri, smoke).**

**Action** : ✅ Corrigé (commentaire) / ⏳ Q2 pour la validation VM.

### #2 — 🟡 `wimlibArg()` n'échappe pas `"`/`\`

**Sévérité** : 🟡 Mineur
**Fichier(s)** : `app/Ipxe/Iso/Services/WinpeDriverInjector.php` (`wimlibArg`)

**Constat** : chemins à espace entourés de `"` sans échapper les `"`/`\` internes → si `winpe_drivers_path` contient un `"`, le `--command` wimlib est mal parsé → exception opaque. Pas une RCE (escapeshellarg externe ; famille validée).

**Avis Opus** : pertinence 1/3 — réel mais inoffensif (entrée = config admin), priorité basse.

**Solution appliquée** : `str_replace(['\\','"'], ['\\\\','\\"'], $path)` avant le guillemet.

**Action** : ✅ Corrigé automatiquement.
