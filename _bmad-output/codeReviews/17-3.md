## Détail des problèmes

### #1 — `.diff` upstream POST multipart vs endpoint GET → 405

**Sévérité** : 🟠
**Fichier(s)** : `_bmad-output/implementation-artifacts/17-3-upstream-se4_applications.diff`

**Constat sonnet** : Le `.diff` conserve `curl -F` (POST multipart). L'endpoint API v1 `routes/api.php:256` est `Route::get` strict. Si Henri applique le `.diff` côté repo Debian + redéploie → tous les postes obtiennent **HTTP 405 Method Not Allowed**, scripts applications cassés en parc.

**Avis Opus** : Pertinence **3** (bloquant runtime). Confirmé : `routes/api.php:256 = Route::get`. Le `.diff` envoie `curl.exe -F` (POST). **Incohérence interne #S1 majeure** : les fixtures `tests/Fixtures/Gpo/se4_applications_template_pristine/.../startup.cmd:7` (et `_unknown`) utilisent **déjà GET query string** : `curl.exe -o "..." "###_APPLICATIONS_SCRIPTS_URL_###?os=windows&action=startup"`. L'auteur a clairement vu la transition POST→GET en rédigeant les fixtures, mais a oublié de l'appliquer au `.diff`.

**Solutions possibles** :
1. **(A)** Corriger le `.diff` en GET query string (aligner sur fixtures, cohérent Q-1) ✅ recommandation Opus
2. **(B)** Ajouter avertissement « NE PAS APPLIQUER avant Story 17.4 » dans le header du `.diff`
3. **(C)** Supprimer le `.diff` du livrable 17.3, le délivrer en 17.4

**Action** : **en attente décision Henri (Q1)**

### #2 — `is_callable($value)` global → élargit la surface RCE/abus

**Sévérité** : 🟠
**Fichier(s)** : `app/Gpo/Services/ApplicationScriptsAssembler.php:1063-1065`

**Constat sonnet** : Le check `is_callable` est placé APRÈS résolution `config/env/default`, s'applique donc à toutes les sources. Si `SAMBAEDU_APPLICATIONS_SCRIPTS_URL=strlen` ou autre nom de fonction PHP, `is_callable=true` et exécuté.

**Avis Opus** : Pertinence **3**. Confirmé : `is_callable('phpinfo')=true`, `is_callable('passthru')=true`, `is_callable('exec')=true`. C'est une **surface d'attaque concrète** via env var compromise (admin malveillant ou breach `.env`). Élargissement de surface vs avant 17.3.

**Solutions possibles** :
1. Scoper le check au seul chemin `default` ET filtrer `is_array || $default instanceof Closure` (exclut strictement les chaînes nom-de-fonction) ✅ recommandation Opus

```php
if (! $found && array_key_exists('default', $spec)) {
    $default = $spec['default'];
    if (is_callable($default) && (is_array($default) || $default instanceof \Closure)) {
        $value = $default();
    } else {
        $value = $default;
    }
    $found = true;
}
// Et supprimer le `if (is_callable($value))` global lignes 1063-1065.
```

**Action** : **corrigé automatiquement**

### #S2 — Regex `extractUrls` ne filtre pas `'`, `<`, `>`

**Sévérité** : 🟠
**Fichier(s)** : `app/Console/Commands/AuditApplicationsGpoTemplateCommand.php:314`

**Constat Opus** : Regex `#https?://[^"\s)]+#` exclut `"`, espace, `)` mais pas `'`, `<`, `>`. Faux positif possible dans `.reg` ou `.xml` du template GPO (la regex capture `http://example.com'>` avec apostrophe et `>`).

**Solution** : étendre l'exclusion : `#https?://[^"\s)\'<>]+#`.
