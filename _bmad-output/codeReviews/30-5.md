## Détail des problèmes

### #1 — `setMachineGroups` : faux refus (collision fantôme)

**Sévérité** : 🔴 — **Pertinence Opus** : 3
**Fichier(s)** : `app/Services/Parc/WorkstationGroupService.php` (~l.926-936), `app/Services/ControlHub/Resolution/UpstreamLockCollisionDetector.php`

**Constat initial (review)** :
`setMachineGroups(machineId, groupIds)` fait `groups()->sync($groupIds)` — remplacement complet des appartenances. Le helper modélise `existing = carriedLabelsExcludingGroups([M], $groupIds)` (labels des groupes ACTUELS hors cibles) ∪ `gained = labels($groupIds)`. Or les groupes actuels hors cibles sont précisément ceux que le `sync()` va **supprimer**. Scénario : M dans A(`parc-a`, locked X=1) + B ; `setMachineGroups(M,[C])` avec C `parc-c`(locked X=2). Post-op M n'est QUE dans C → aucun conflit, mais la garde compose `existing(parc-a) ∪ gained(parc-c)` → collision flaggée → **bloqué à tort**.

**Avis Opus** :
Confirmé, note 3. Pire qu'une violation AC8 : la collision signalée **n'existe pas** en post-opération. Bloque une opération légitime (rescaper un poste hors d'un setup conflictuel). Cause racine = sémantique purement additive du helper, fausse pour les points d'appel `sync()`.

**Solutions possibles** :
1. **(retenue)** Refactor générique du helper : raisonner `pre`/`post` par poste, `gained = post \ pre`. Pour `setMachineGroups`, `post = labels($groupIds)`, `pre = labels actuels` → `existing` effectif = `[]`, le détecteur ne capte qu'une vraie collision cible↔cible.
2. Correctif ciblé `setMachineGroups` : passer `existing = []`, `gained = labels($groupIds)`.

**Action** : corrigé automatiquement (option 1).

### #2 — `setGroupMachines` : faux refus pour postes déjà membres

**Sévérité** : 🟠 — **Pertinence Opus** : 2
**Fichier(s)** : `app/Services/Parc/WorkstationGroupService.php` (~l.942-953)

**Constat initial (review)** :
`setGroupMachines(G, [M1,M2])` fait `workstations()->sync()`. Si M1 est **déjà** dans G et porte un label conflictuel via un autre groupe H, la garde compte `parc-g` comme « gagné » alors que M1 le possédait déjà → collision pré-existante signalée comme introduite (violation AC8).

**Avis Opus** :
Confirmé, note 2. Réel mais étroit : ne touche que les postes **déjà membres** ET déjà en conflit runtime ; pour les postes **nouvellement** ajoutés la sémantique additive tient. Mécanisme distinct de #1.

**Solutions possibles** :
1. **(retenue)** Le modèle générique `pre`/`post` couvre ce cas : un poste déjà membre a `parc-g` dans `pre` → non compté dans `gained`.
2. Correctif ciblé : exclure de `$machineIds` les postes déjà membres de G avant détection.

**Action** : corrigé automatiquement (option 1).
