1. **Fragilité des stubs eval+regex** (#1, #2, #3) — bombes à retardement au prochain changement du legacy

- **Q4:b** — Limitation documentée dans la section "Limitations connues" de la story. Tests authentifiés déférés à Epic 6 (hors scope SHIM EXPRESS ~3h).

## Détail des problèmes

### #1 — Stub `printers.inc.php` : `eval()` + `str_replace` fragile

**Sévérité** : 🔴 Critique
**Fichier** : `legacy/stubs/printers.inc.php:35-48`

**Constat** :
Le stub lit 1079 lignes de legacy à chaque include, passe dans `preg_replace + str_replace` pour patcher la signature de `guid()`, puis `eval()` le résultat. Le pattern recherché est `"function guid()\n{"` **exactement** (espaces, newlines compris). Toute évolution du legacy (reformatage, commentaire, `: string`, indentation tab→espaces, un simple `dos2unix`…) fait **échouer silencieusement le str_replace** : `guid()` sera déclarée sans guard, et à la 2e inclusion → Fatal "Cannot redeclare guid()".

**Impact** :
Bombe à retardement. À la prochaine évolution de `sambaedu/includes/printers.inc.php`, tous les tests et pages `/printers/*` crashent sans avertissement préalable.

**Solutions possibles** :
1. **Préféré** : ajouter un guard `if (!function_exists('guid'))` dans le vrai `sambaedu/includes/printers.inc.php` (modification propre côté legacy, 2 lignes). Le stub se réduit à `require_once`.
2. Remplacer par un wrapper de tokenisation (`token_get_all`) plus robuste qu'un str_replace.
3. **À minima** : ajouter une assertion en fin de stub (`if (!function_exists('guid')) trigger_error(...)`) pour détecter immédiatement que le patch n'a pas pris.

**Action** : en attente de décision Q1.

### #2 — Stub `partages.inc.php` : regex encore plus fragile

**Sévérité** : 🔴 Critique
**Fichier** : `legacy/stubs/partages.inc.php:47-51`

**Constat** :
Même mécanique eval+patch, avec `preg_replace` complexe : `/(array_multisort\(\$res.*?SORT_DESC\);)\s*\n(\s*return \$res;\n\})/s`. Dépend du contenu interne de la fonction (usage de `array_multisort(...SORT_DESC)` juste avant le return). Tout refactor qui déplace, renomme ou supprime ce `array_multisort` casse silencieusement le patch. 673 lignes rechargées via eval à chaque bootstrap.

**Impact** :
Même bombe à retardement. Pire : contamine **tous** les modules (gpo, user, annu, etc.) qui font `include "partages.inc.php"` (grep : `sambaedu/index.php`, `user/index.php`, `gpo/del_roam.php`, `gpo/no_roam.php`, `gpo/user_profile_stats.php`).

**Solutions possibles** :
1. `if (!function_exists('roaming_profiles_stats'))` dans le vrai legacy (2 lignes). Même solution que #1.
2. Token-based patching.
3. Assertion post-eval.

**Action** : en attente de décision Q1.

### #3 — Stubs shadow s'appliquent à TOUS les modules

**Sévérité** : 🟠 Important
**Fichier** : `legacy/stubs/printers.inc.php`, `legacy/stubs/partages.inc.php`, `legacy/stubs/ihm.inc.php`

**Constat** :
Les 3 stubs sont prepend dans l'include_path par `bootstrap.php:60-62`. Toute inclusion de `printers.inc.php`, `partages.inc.php`, `ihm.inc.php` par un module legacy (gpo, user, annu, wpkg…) passe désormais par le stub (donc par l'`eval()`). La story prétend isoler printers, mais l'effet est global.

**Impact** :
- **Performance** : `file_get_contents` + `preg_replace` + `eval` à chaque bootstrap pour 2473 lignes totales, opcache désactivé.
- **Régression potentielle** sur les stories 1bis-18a/b/g (gpo) : si `bootstrap.php` charge `gpo_ui.inc.php` qui fait `include "partages.inc.php"`, il tombe sur le stub qui fait l'eval.
- Les tests GPO existants passent (validé par le dev : 21/21 verts), mais le risque reste pour les scénarios non couverts.

**Solutions possibles** :
1. Même que #1/#2 (fix amont).
2. Documenter explicitement "ces stubs shadowent tous les modules" dans un commentaire d'en-tête.
3. Ajouter au test une vérif explicite que les pages GPO se chargent encore (smoke régression).

**Action** : en attente de décision Q1. Si Q1 = fix amont, devient obsolète.

### #4 — Injection shell dans `view_printers.php` (RCE potentielle)

**Sévérité** : 🟠 Important (sécurité)
**Fichier** : `legacy/modules/printers/view_printers.php:62-64, 67-69, 245`

**Constat** :
```php
$status = $_POST['status'] ?? "";           // attacker-controlled
$able = "cups" . $status;
exec("sudo /usr/sbin/$able {$all_printers[$num]['name']}");
```

`$status` et `$queue` viennent directement de `$_POST`. `$able` est concaténé **sans validation** : un POST `status=enable;whoami` exécute `sudo /usr/sbin/cupsenable;whoami imprimante`. `sudo` étant `NOPASSWD: ALL` pour www-admin → **RCE root**.

La story § Dev Notes mentionne le risque concernant `$all_printers[$num]['name']` mais pas `$status`/`$queue`. Aucune mitigation immédiate n'est proposée dans la story.

**Impact** :
Pendant toute la durée du shim (Epic 6 non livré → plusieurs mois), un admin SambaEdu compromis (ou CSRF sur la page) = RCE root.

**Solutions possibles** :
1. **Minimal** : patch dans le fichier copié `legacy/modules/printers/view_printers.php` pour whitelister : `if (!in_array($status, ['enable','disable'], true)) { die('Invalid status'); }` + idem pour `$queue`. Déroge à "ne pas modifier le legacy" mais justifié par la sécurité.
2. Bloquer la route POST `view_printers.php` dans `blocked_legacy_routes` tant que non validée.
3. Ajouter une note explicite dans la story + créer un ticket dédié pour Epic 6 avec ce risque listé comme NFR sécurité bloquant.

**Action** : en attente de décision Q2.
