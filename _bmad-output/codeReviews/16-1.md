## Détail des problèmes

### #1 — `error.trace` toujours émis dans `GpoActionLog::failure()`

**Sévérité** : 🔴 — **Pertinence Opus : 3/3**
**Fichier** : `app/Gpo/Support/GpoActionLog.php:97-115`

**Constat** : la stacktrace complète est insérée inconditionnellement dans le contexte log, alors que README + AC1.3 spécifient « trace uniquement si `GPO_LOG_LEVEL=debug` ».

**Avis Opus** : confirme. Impact réel sur volume + fuite paths internes en prod. À fixer.

**Solution retenue** : conditionner sur le niveau effectif du channel via `config('logging.channels.gpo.level')`. Si `debug` → inclure trace. Sinon → omettre.

**Action** : ✅ corrigé automatiquement.

### #8 — Whitelist `continue` skip total des patterns shell

**Sévérité** : 🟠 — **Pertinence Opus : 3/3**
**Fichier** : `tests/Architecture/GpoNamespaceTest.php:59-60,202`

**Constat** : `continue` saute toute la vérification pour `SambaToolRunner.php`, y compris `exec()/shell_exec()/passthru()/proc_open()` qui devraient rester interdits **partout**. Seul `Illuminate\Support\Facades\Process` devrait être autorisé dans le runner.

**Avis Opus** : confirme — vraie régression de couverture.

**Solution retenue** : séparer les patterns en deux listes — `FORBIDDEN_EVERYWHERE` (exec/shell_exec/passthru/proc_open) appliqués à tous, et `FORBIDDEN_EXCEPT_WHITELIST` (autres) skippés pour la whitelist.

**Action** : ✅ corrigé automatiquement.

### #B — `parseGetInheritance` retourne `false` sur sortie inconnue

**Sévérité** : 🟠 — **Pertinence Opus : — (additionnel)**
**Fichier** : `app/Gpo/Services/GpoService.php:436-441`

**Constat** : `preg_match('/GPO_INHERIT/i', $output) === 1` — si samba-tool retourne autre chose (i18n, version future), `false` est rendu = inheritance bloquée, ambigu non détecté.

**Solution retenue** : matcher explicitement `GPO_INHERIT` (true) XOR `GPO_BLOCK_INHERITANCE` (false). Si aucun, lever `RuntimeException`.

**Action** : ✅ corrigé automatiquement.
