## Détail des problèmes

### #1 — `late_command` preseed Debian appelle `action.php` legacy

**Sévérité** : 🔴
**Fichier(s)** : `resources/ipxe/linux/debian.cfg:83` + `resources/ipxe/linux/ubuntu.cfg` + `resources/ipxe/linux/debian_perso.cfg`

**Constat initial (Sonnet)** :
Le `late_command` dans `debian.cfg:83` pointe sur `http://###_SE4FS_IP_###/ipxe/linux/action.php` (URL legacy avec `.php`) au lieu de `/ipxe/linux/action` (route SE5 native créée dans la story). Conséquence : `LinuxPostInstallTracker::record()` n'est JAMAIS appelé en prod, le callback tombe sur le catchall legacy. `ubuntu.cfg` n'a pas de `late_command` du tout.

**Avis Opus (pertinence : 3/3)** :
Confirmé critique. `ubuntu.cfg` ET `debian_perso.cfg` sont AUSSI sans callback. La granularité minimale `Workstation::os='linux'` (D9 ratifié) ne se déclenche jamais pour Ubuntu et Nird. Aucun test n'asserte le contenu de la chaîne `late_command` du preseed généré → le bug est passé silencieusement.

**Solutions possibles** :
1. Corriger les 3 fragments (retirer `.php`) + ajouter `late_command` dans `ubuntu.cfg` et `debian_perso.cfg`.
2. Extraire le `late_command` dans un fragment dédié `callback.cfg` injecté par le service pour Debian/Ubuntu/Nird uniformément.

**Action** : ⏳ corrigé automatiquement (option 1 + test feature `it_serves_ipxe_linux_action_natively_not_via_catchall` + assertions `assertStringContainsString('/ipxe/linux/action ')` et `assertStringNotContainsString('/ipxe/linux/action.php')` dans `IpxeLinuxPreseedEndpointTest`).

### #2 — Menu poste inconnu : syntaxe iPXE invalide

**Sévérité** : 🔴
**Fichier(s)** : `resources/views/ipxe/menu/installation-linux.blade.php:16-25`

**Constat initial (Sonnet)** :
Le `@else` (cas poste inconnu) injecte `echo`/`sleep`/`chain` dans un bloc iPXE `menu ... choose` — invalide en syntaxe iPXE. `menu-default` pointe sur `install_deb_gnome` qui n'existe pas comme item. Pattern attendu (D7) = menu erreur dédié style `renderEnrollmentUnknownWorkstation`.

**Avis Opus (pertinence : 2/3)** :
Confirmé avec nuance. En pratique iPXE évalue `echo`/`sleep`/`chain` au parse → `chain --replace /ipxe/admin` se déclenche AVANT `choose`, masquant l'erreur. Mais les items `(s)/(r)/(x)` sont inatteignables. Le test `it_returns_error_menu_for_unknown_workstation` ne vérifie que la présence du message, pas la conformité syntaxique iPXE — il passe par chance.

**Solutions possibles** :
1. Refactoriser `installation-linux.blade.php` pour 2 paths complètement disjoints (`@if($isKnown)` englobe tout le bloc menu, `@else` rend body simple `echo`/`sleep`/`chain` sans `menu`/`choose`).
2. Sortir le rendu unknown vers `IpxeMenuRenderer::renderInstallationLinuxUnknown()` (helper string-concat pattern 3.3).

**Action** : ⏳ corrigé automatiquement (option 1 + test `assertStringNotContainsString('menu installation', $body)` au case `unknown`).
