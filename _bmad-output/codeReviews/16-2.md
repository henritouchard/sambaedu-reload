## Détail des problèmes

### #1 — Test AC4.2 contourne la regex de route via `Livewire::test()`

**Sévérité** : 🔴 Critique
**Fichier(s)** : `routes/web.php:222-225`, `tests/Feature/Gpo/GpoDetailRouteValidationTest.php`

**Constat initial** :
La regex `where('guid', '\{[0-9A-Fa-f]{8}-...\}')` est posée sur la route, mais `GpoDetailRouteValidationTest::it_returns_404_for_injection_string_without_calling_service` instancie le composant **directement via `Livewire::test('pages::app.gpo.[guid].index', ['guid' => 'INJECTION; rm -rf /'])`** — ce qui contourne complètement la regex de route. Le test passe parce que la regex défensive dans `mount()` (ligne 71) rattrape le cas. Mais cette double-validation n'est jamais testée *via le routeur HTTP*.

**Impact** : Couverture trompeuse. Si la regex `where()` est retirée par erreur, plus rien ne valide au niveau HTTP — pas de test pour le détecter.

**Solutions possibles** :
1. Ajouter un test HTTP `$this->get('/app/gpo/INJECTION')->assertStatus(404)` qui frappe le routeur réel.
2. Conserver les deux couches (déjà le cas), documenter explicitement.

**Action** : ✅ Corrigé automatiquement (ajout test HTTP).

### #2 — Commentaire trompeur sur l'ordre des routes

**Sévérité** : 🟠 Important
**Fichier(s)** : `routes/web.php:217-226`

**Constat** :
Le commentaire `IMPORTANT : /gpo/{guid} AVANT /gpo (sinon la route détail ne matche pas sous le préfixe app)` est incorrect. Laravel route sur l'URI complète, pas sur le préfixe ; `/app/gpo` ne peut jamais matcher `/app/gpo/{guid}` car `{guid}` est obligatoire.

**Impact** : Doc trompeuse → mauvaise compréhension future.

**Solutions possibles** :
1. Retirer le commentaire trompeur. Documenter que la regex stricte couvre la validation.

**Action** : ✅ Corrigé automatiquement.

### #3 — Double-injection `boot()` + `mount()` GpoService

**Sévérité** : 🟠 Important
**Fichier(s)** : `resources/views/pages/app/gpo/index.blade.php:49-67`, `[guid]/index.blade.php:60-83`

**Constat** :
Toutes les autres SFCs du projet injectent les services uniquement dans `boot()`, jamais dans `mount()`. Ici les deux reçoivent le service. Pattern non conforme. Si quelqu'un retire `boot()` en pensant qu'il fait double emploi avec `mount()`, le composant explose à la première interaction Livewire (refresh, sort, pagination) après hydratation.

**Impact** : Risque de régression silencieuse, divergence du pattern projet, code confus.

**Solutions possibles** :
1. Supprimer l'injection dans `mount()`. Garder `boot(GpoService $service)` uniquement. Appeler `$this->loadGpos()` à la fin de `mount()` — `boot()` aura été invoqué juste avant.

**Action** : ✅ Corrigé automatiquement (alignement sur le pattern projet).

### #8 — `toggleShowAll()` recharge GPO + tous containers

**Sévérité** : 🟠 Important
**Fichier(s)** : `[guid]/index.blade.php:80-140`

**Constat** :
`toggleShowAll()` ré-appelle `loadDetail()` qui re-appelle `get()` + `listContainers()` + N × (`getLinks` + `getInheritance`). Pour 12 containers : 1 + 1 + 24 appels samba-tool (~30s sur DC chargé) alors que rien n'a changé.

**Impact** : Latence UX dégradée + logs `gpo` polluées de doublons.

**Solutions possibles** :
1. Ne charger que les containers manquants (diff entre `containersToLoad` et déjà chargés).
2. Reset des caches uniquement sur changement de GUID.

**Action** : ✅ Corrigé (option 1). `loadContainerDetails(array $dns)` extrait, idempotent (skip si `array_key_exists`). `toggleShowAll()` n'appelle plus `loadDetail()` — uniquement `loadContainerDetails($this->desiredContainers())`. Première interaction : 5 containers chargés (1 + 1 + 10 appels). Toggle « Afficher tous » : seulement N-5 containers supplémentaires. Plus de doublon `get()` ni `listContainers()`.

### #9 — Regex GUID impose les accolades — fragile aux URLs partagées

**Sévérité** : 🟠 Important
**Fichier(s)** : `routes/web.php:222`, `[guid]/index.blade.php:71`

**Constat** :
La regex impose `{...}` dans le path. Navigation interne OK (Laravel encode/décode), mais copier-coller d'URL ou partage chat/mail peut casser sur certains clients qui mal-encodent les `{`/`}` (caractères réservés RFC 3986).

**Solutions possibles** :
1. Test feature de l'aller-retour navigateur via `route()`.
2. Accepter les deux formats (avec/sans accolades), normaliser dans `mount()`. Plus user-friendly.

**Action** : ✅ Corrigé (option 2). Regex de route assouplie : `\{?[0-9A-Fa-f]{8}-...\}?`. Méthode privée `normalizeGuid()` dans la SFC strip les accolades puis les rajoute systématiquement avant tout appel `samba-tool` (qui exige le format canonique). Test `it_accepts_guid_without_braces_and_normalizes` ajouté + test HTTP `the_route_regex_accepts_guid_without_braces_at_http_level`.

### #10 — `try/catch` capture `abort(404)`, AC2.7 violé

**Sévérité** : 🟠 Important
**Fichier(s)** : `[guid]/index.blade.php:88-96`

**Constat** :
Le `try/catch \Throwable` ligne 88-96 attrape la `HttpException` levée par `abort(404)`. Si `get()` retourne null → `abort(404, 'GPO inexistante.')` ligne 91 → rattrapé ligne 94 → re-`abort(404, 'GPO introuvable : '.$e->getMessage())`. Pire : si `get()` lève une vraie `RuntimeException` (samba-tool down), la page renvoie 404 au lieu d'afficher un toast d'erreur conformément à AC2.7.

**Impact** : AC2.7 violé. Utilisateur voit 404 alors que samba-tool est juste timeout.

**Solutions possibles** :
1. Sortir le `abort(404)` du `try`. `$gpoObj = ...; if ($gpoObj === null) abort(404)` après le bloc.
2. Pour l'exception réelle : remonter en toast + flag `$hasError` cohérent avec listing.

**Action** : ✅ Corrigé automatiquement.

### #12 — XSS faible via `onclick` concaténé avec GUID brut samba-tool

**Sévérité** : 🟡 Mineur
**Fichier(s)** : `[guid]/index.blade.php:189, 327, 350`, `index.blade.php:323, 374`

**Constat** :
`onclick="window.location.href='{{ route(..., ['guid' => $gpo['name']]) }}'..."` — `$gpo['name']` provient de `samba-tool gpo listall` sans re-validation. Risque très faible (impliquerait compromission AD), mais defense-in-depth manquante.

**Solutions possibles** :
1. Remplacer `onclick` par un wrapper Livewire (`wire:navigate`) ou un `<a>` autour de la `<tr>`.
2. Re-valider le format du GUID retourné par `GpoService::list()` côté SFC.

**Action** : ✅ Corrigé (option 1). Toutes les `<td>` cliquables du listing encapsulent leur contenu dans un `<a href="{{ route(...) }}">` au lieu d'un `onclick`. Bénéfices natifs : navigation clavier (tab + enter), middle-click ouvre nouvel onglet, screen-reader OK, pas de JS inline. Plus besoin de re-valider le GUID côté SFC vu que le finding #1 garantit la regex au niveau route.
