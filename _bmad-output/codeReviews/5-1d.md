### #M2 — Race condition `restore` ↔ `trash:purge`

**Sévérité** : 🟠
**Fichier(s)** : `app/Services/Filesystem/HomeDirService.php:131-154` ; `app/Console/Commands/TrashPurgeCommand.php:106-126`

**Constat** : Aucun lock entre admin qui restore depuis UI (`mv /home/trash/alice /home/alice`) et cron 02h00 qui purge. Scénarios :
- Cron énumère, admin restore entre-temps, cron supprime fantôme → audit faux positif
- Si restore échoue à mi-chemin, cron supprime résidus

**Décision Henri (2026-04-29 — Q3)** : Ajouter `Cache::lock('trash:action:'.$login, 60)` per-login dans `HomeDirService::restoreHomeDirectory()`, `HomeDirService::archiveHomeDirectory()` ET dans la boucle de suppression de `TrashPurgeCommand`. Si lock indisponible côté commande → skip + compteur `locked` dans le rapport final. Si lock indisponible côté HomeDirService → return false + log warning.

**Action** : ✅ Corrigé.
- `HomeDirService::archiveHomeDirectory()` : lock acquis après validation login, libéré dans `finally`. Return false si indisponible.
- `HomeDirService::restoreHomeDirectory()` : idem.
- `TrashPurgeCommand::handle()` : lock per-login dans la boucle, skip + compteur `$locked` si indisponible. Rapport final inclut `Verrouillés : N (opération en cours)`.
- 2 tests Unit ajoutés (`HomeDirServiceTest::it_returns_false_when_restore_is_locked` + `it_returns_false_when_archive_is_locked`).
- 1 test Feature ajouté (`TrashPurgeCommandTest::it_skips_locked_directory_during_purge`).
