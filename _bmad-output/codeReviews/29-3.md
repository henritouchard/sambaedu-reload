### #A — AC#2 sur-vendu : valeur permissive inerte pour clés Capability (ajout Opus)

**Sévérité** : 🟡

**Constat (second avis Opus)** : `permissive → UpstreamPermissive` (rang 6), or le provider de capacités émet **toujours** un candidat `Broadcast` (rang 5) pour `default_value`. Comme **toute** Capability a un `default_value`, le plancher permissif est **systématiquement battu** par le défaut diffusé → pour une clé adossée à une Capability (le cas central d'AC#1/#2), la **valeur** de l'item permissif amont n'est **jamais** servie ; seule sa qualité d'« item relaxable » compte. AC#2 (« la valeur amont permissive s'applique comme baseline ») n'est en pratique atteignable que pour une clé registry **sans** Capability. **Ce n'est PAS un bug** — c'est la décision Henri (« permissif sous le défaut diffusé »), correctement codée et testée — mais le libellé sur-vend la portée.

**Action** : ✅ **Corrigé** — AC#2 annoté ; mémoire projet `project_permissive_floor_least_specific` enrichie de la conséquence. Aucun code de production touché.

- **B. Cas pathologique `locked` + `permissive` sur la MÊME clé** : les deux candidats injectés (`Upstream`=-1, `UpstreamPermissive`=6) ; `min(specificity)` → `Upstream` gagne → **`locked` l'emporte**. Verrou jamais affaibli par un permissif coexistant. **Sûr par construction.**
