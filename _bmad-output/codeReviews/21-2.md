## Détail des problèmes

### P-1 / N-1 — Signature `connect(): static` = fatal PHP confirmé

**Sévérité** : 🔴 — **Pertinence Opus : 3 (vérifié sur le source ldaprecord v3.8.6)**
**Fichier(s)** : `app/Ldap/Fakes/ThrowingLdapConnection.php:49`

**Constat initial (review)** :
Le dev (sans vendor sur l'hôte) avait signalé l'incertitude. Sonnet l'a élevée en critique.

**Avis Opus** :
Confirmé par lecture du source v3.8.6 (version du `composer.lock`) : `public function connect(?string $username = null, ?string $password = null): void`. Le type `void` est **invariant** en PHP → `: static` est un fatal au **chargement de classe**. Conséquence aggravante (N-1) : `FakeAdGuardTest` charge la classe → **toute la suite PHPUnit host crashe** ; la validation T7 ne peut jamais passer. Le principe du garde-fou est par ailleurs correct (`run()` appelle `connect()` si non connecté, et la `RuntimeException` n'est pas un `LdapRecordException` → pas rattrapée en interne).

**Solutions possibles** :
1. `connect(...): void` (le `throw` rend le type de retour sans objet).

**Action** : correction automatique.
