## Détail des corrections appliquées

### #1 + #6 — Path traversal (defense-in-depth) ✅
`agent/provision/provision.go` : `validateRelPath(rel)` appelée dans `reconcileOne` AVANT `Resolve` — rejette tout RelPath absolu, avec volume (`C:`), ou contenant `..` (normalise les DEUX séparateurs `\` et `/` car le manifeste peut venir d'un OS distant). OS-agnostique → protège tous les resolvers (y compris le `fixedResolver` de test). Le sha256 reste la garantie d'intégrité du contenu. Test `TestReconcile_RejectsPathTraversal` (6 vecteurs : `../../`, `..\..`, `/etc/passwd`, `C:\`, remontée au milieu, vide) — aucun fichier créé, aucun GET émis.

### #2 — Faux `log_success` ✅
`scripts/update.sh` : le `mv -f manifest_tmp manifest` est désormais branché — succès ⇒ chmod/chown/`log_success` ; échec ⇒ `rm tmp` + `log_warning` explicite (agent en fail-soft au prochain cycle, vérifier droits/espace).

### #3 — Échappement JSON ✅
`scripts/update.sh` : `id`/`relpath` échappés (backslash puis guillemet) avant `printf` — un nom contenant `"` ne casse plus le manifeste. sha = hex sûr.

### #4 — tmp unique ✅
`agent/provision/provision.go` : `os.CreateTemp(dir, "."+base+".*.tmp")` au lieu de `<absPath>.<pid>.tmp` — pas de collision sur doublon d'`absPath`, pas de blocage par un tmp périmé d'un run tué.

### #5 — `+FollowSymLinks` — Won't-fix (justifié)
Les **9** blocs `Options` du vhost (`/wpkg/files`, `/wpkg/bundle`, `/wpkg/tools`, `/os`, …) utilisent tous `+FollowSymLinks` : c'est la convention projet. `tools_dir` est `www-admin:www-admin 755` (seuls root/www-admin y créent des liens) → risque concret faible. Modifier le seul `/wpkg/tools` introduirait une incohérence ; un durcissement `+SymLinksIfOwnerMatch` global est un sujet transverse hors 27.20.
