## Questions en attente

> Questions nécessitant une réponse de l'utilisateur avant corrections.

1. **#1 — NFR2 (toast < 500 ms)** : l'AC2 de la story exige un retour UI en < 500 ms, mais l'implémentation Livewire synchrone ne peut pas tenir cette contrainte pour `shutdown` et `restart` (Process::run RPC Kerberos bloque 2-10 s). Trois options :
   - **A.** Dispatcher un Queue Job + event Livewire pour retourner immédiatement (refactor moyen, nécessite worker queue)
   - **B.** Downgrader l'AC2 en "< 500 ms pour WOL uniquement, 2-10 s tolérés pour shutdown/restart"
   - **C.** Accepter tel quel et documenter la limitation en known-limitation

2. **#2 — Race condition restart** : le polling détecte "machine disponible" à t+3s sur un restart (la machine répond encore avant de s'éteindre). Deux options :
   - **A.** Machine à états (`restartPhase : shutting-down → waking-up`) qui attend un `ping === false` avant d'attendre `ping !== false`
   - **B.** Délai anti-rebond minimum (ex: 35 s avant premier poll readiness sur restart)

3. **#10 — Test regression vue groupe** : à corriger en même temps que #4 (voir ci-dessous). Corriger = ajouter test, oui/non ?

4. **Scope shutdown-force côté groupe** : deux options pour résoudre #4 :
   - **A.** Ajouter le wire:confirm renforcé dans le partial groupe (expose shutdown-force en batch — attention)
   - **B.** Filtrer shutdown-force hors du dropdown groupe (via un paramètre `$context = 'individual' | 'group'` sur `getAvailableMachineActions()`)

## Détail des problèmes

### #1 — NFR2 violé : executeMachinePowerAction synchrone

**Sévérité** : 🔴
**Fichier(s)** : `resources/views/pages/parc/machines/[id]/index.blade.php:168-231`

**Constat initial (review)** :
Le commentaire dit "on bascule l'état EN COURS AVANT le call backend" comme si cela permettait un retour UI rapide. Faux : Livewire ne re-rend qu'après le `return`. Le toast n'apparaît qu'APRÈS `ping()` + `Process::run("net rpc shutdown -t 30")`.

**Avis Opus** :
Confirmé. Le `-t 30` est un délai avant extinction, pas un timeout de retour. La RPC Kerberos peut bloquer 5-10 s. L'AC2 "< 500 ms" est physiquement impossible dans l'architecture actuelle.

**Solutions possibles** :
1. **A.** Queue Job (`DispatchMachinePowerActionJob`) + event Livewire — toast en 50 ms, polling inchangé
2. **B.** Downgrader AC2 en "< 500 ms pour WOL, best-effort pour shutdown/restart"
3. **C.** Accepter + documenter known-limitation

**Action** : ✅ Corrigé (option A choisie par l'utilisateur, 2026-04-20).

Détail de l'implémentation :
- Nouvelle migration `database/migrations/2026_04_20_120000_create_machine_power_action_tasks_table.php` — table persistante pour le suivi des actions.
- Nouveau modèle `App\Models\MachinePowerActionTask` avec états `queued/dispatched/running/completed/failed` et constantes de phase restart.
- Nouveau job `App\Jobs\DispatchMachinePowerActionJob` qui récupère la task, appelle le service power, et met à jour l'état (`running` → `completed|failed`).
- `resources/views/pages/parc/machines/[id]/index.blade.php::executeMachinePowerAction()` crée la task (status=queued), dispatche le job, et retourne immédiatement avec toast "Action lancée". Plus de `Process::run` inline dans le cycle Livewire.
- `pollMachineReadiness()` consomme l'état de la task (détection des failures remontés par le job) en plus du ping réseau.
- Propriété Livewire `$currentTaskId` pour référencer la task courante.
- `config/parc.php` expose `queue_connection` (default = `default`) pour router le job sur une queue dédiée en prod.

### #2 — Race condition restart : faux succès à t+3s

**Sévérité** : 🔴
**Fichier(s)** : `resources/views/pages/parc/machines/[id]/index.blade.php:274-279`

**Constat initial (review)** :
```php
$isResolved = match ($actionInProgress) {
    'wake', 'restart' => $ping !== false,
    ...
};
```
Pour restart, la machine répond encore à t+3s → faux succès UI.

**Avis Opus** :
Confirmé. Le legacy ne polling pas du tout, mais cette nouvelle feature est bugguée d'entrée. L'AC3 ("détecter le redémarrage") n'est pas tenu pour `restart`.

**Solutions possibles** :
1. **A.** Machine à états : `restartPhase : shutting-down → waking-up`
2. **B.** Délai anti-rebond : ignorer les 35 premières secondes post-click sur `restart`

**Action** : ✅ Corrigé (option A choisie par l'utilisateur, 2026-04-20).

Détail de l'implémentation :
- Colonne `restart_phase` (string, nullable) dans la table `machine_power_action_tasks` avec 2 valeurs : `waiting-down` (valeur initiale pour restart) et `waiting-up`.
- À la création de la task (action=restart), `restart_phase = 'waiting-down'`.
- Dans `pollMachineReadiness()` : tant que phase=`waiting-down`, le poll attend `ping === false` pour transiter vers `waiting-up`. En `waiting-up`, le poll attend `ping !== false` pour marquer la task `completed` et émettre le toast succès.
- Pour wake : logique inchangée (`ping !== false` = succès).
- Pour shutdown/shutdown-force : logique inchangée (`ping === false` = succès).
- 2 nouveaux tests Feature : `test_restart_polling_transitions_from_waiting_down_to_waiting_up`, `test_restart_polling_completes_when_machine_reboots`.

### #11 — logReadinessTimeout ne ferme pas le log WOL ouvert

**Sévérité** : 🟠
**Fichier(s)** : `app/Services/Parc/MachinePowerService.php:354-374`

**Constat initial (review)** : Non relevé par Sonnet.

**Avis Opus** :
La méthode crée une nouvelle ligne MachineBootLog avec `success=false, error_flags=1`, MAIS :
- Pas de `started_at` renseigné → durée d'attente incalculable
- La ligne précédente `wake, success=true, started_at=X` reste "ouverte" (stopped_at null) → un futur shutdown fermera erronément cette ligne

**Solutions possibles** :
1. **A.** Mettre à jour le log WOL ouvert (`stopped_at = now()`, `error_flags = 1`) plutôt que créer une nouvelle ligne
2. **B.** Renseigner `started_at = $openLog->started_at` + `stopped_at = now()` dans la nouvelle ligne + fermer le log WOL

**Action** : ✅ Corrigé (solution A — 2026-04-20). Implémentation avec fallback : si aucun log WOL ouvert n'est trouvé (edge case de concurrence ou reset DB), une ligne est créée avec `started_at = now() - $timeoutSeconds` et `stopped_at = now()` pour préserver l'audit trail.
