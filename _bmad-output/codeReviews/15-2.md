## Détail des problèmes

### #1 — Invalidation incomplète sur `AppProfileWorkstationGroupChanged`

**Sévérité** : 🔴 Critique (sonnet) — invalidé par Opus.
**Fichier** : `app/Wpkg/Deployment/Listeners/InvalidateWorkstationPackagesCache.php:40`

**Constat initial (review)** :
Sonnet a flaggé que le listener n'invalide que les postes du `WorkstationGroup` ciblé, pas les postes directs du AppProfile, ce qui créerait une incohérence avec `AppProfileApplicationChanged` (union postes directs + groupes).

**Avis Opus** : Pertinence **0**. Le code est strictement conforme à la spec AC4.2 (lignes 282-284 de la story) qui dit explicitement *« forget les caches de tous les postes du `WorkstationGroup` »* pour cet event. La distinction est sémantique et voulue : ajouter/retirer **un groupe** d'un profile n'affecte que les postes de ce groupe ; ajouter/retirer **une application** d'un profile (event différent) affecte tous les postes liés au profile. Sonnet n'a pas lu la spec.

**Action** : non-issue, pas de correction.

### #2 — `flushEventListeners()` global sans restauration dans tests

**Sévérité** : 🔴 Critique
**Fichier** : `tests/Support/WpkgSchemaBootstrapper.php:31-34`

**Constat initial (review)** :
`Workstation::flushEventListeners()` (et autres modèles) détache **définitivement** les observers Eloquent pour le reste du process PHPUnit. `tearDown()` ne restaure rien. Tout test ultérieur dépendant des `WorkstationObserver` / `AppProfileObserver` etc. tournera sans observer, masquant des régressions.

**Avis Opus** : Pertinence **3**. Side-effect global réel, pollution latente jusqu'à un test dépendant. Mitigation : `Model::$dispatcher` est statique partagé entre tous les modèles Eloquent — on peut substituer `flushEventListeners()` par `unsetEventDispatcher()` (un seul appel suffit à mute le pipeline pour tous les modèles), puis restaurer via `setEventDispatcher(app('events'))` dans `tearDown()`. Les observers sont attachés à `app('events')` au boot du provider, ils restent enregistrés et redeviennent actifs au reset.

**Solutions possibles** :
1. (retenue) Remplacer les 4 `flushEventListeners()` par un unique `Model::unsetEventDispatcher()`, ajouter `Model::setEventDispatcher(app('events'))` au début de `tearDown()`.
2. Utiliser `Model::withoutEvents(fn() => ...)` scopé par test — plus invasif.

**Action** : ✅ corrigé option 1.

### #3 — `Collection::sort()` case-sensitive sur `app_id`

**Sévérité** : 🟠 Important
**Fichier** : `app/Wpkg/Deployment/Services/WorkstationPackagesResolver.php:128/141`

**Constat initial (review)** :
`->sort()` utilise `SORT_REGULAR` (ASCII binaire). Si un `app_id` legacy est en majuscules, l'ordre alpha diverge.

**Avis Opus** : Pertinence **1**. Convention legacy = lowercase strict 100 %, risque pratique nul. Fix trivial (`->sort(fn($a,$b) => strcasecmp($a,$b))`) mais n'apporte rien sur la donnée actuelle.

**Action** : ✅ corrigé option A — `->sort(fn (string $a, string $b): int => strcasecmp($a, $b))` dans `WorkstationPackagesResolver:141`.
