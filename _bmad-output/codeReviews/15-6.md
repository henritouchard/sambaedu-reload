## Détail des problèmes

### #1 — 🔴 Régression : 8 tests pré-existants cassés (`system_settings` absente du bootstrapper)

**Fichier(s)** : `tests/Support/WpkgSchemaBootstrapper.php` (cause), `app/Wpkg/Deployment/Http/Controllers/WingetOutController.php:44`, `app/Http/Middleware/EnsureLocalRequest.php:58`

**Constat** : `WingetOutController::handle()` et `EnsureLocalRequest::isAllowed()` appellent désormais le résolveur → `SystemSetting::get()` → `SELECT … FROM system_settings`. Les tests d'endpoint Story 17.6 (`WingetOutEndpointTest`, `LinuxOutEndpointTest`) utilisent `WpkgSchemaBootstrapper::bootstrap()` qui **ne crée pas** `system_settings`. Résultat VM : **8 failed, 182 passed** (`QueryException: no such table: system_settings`). Le dev a patché en inline 2 tests de page GPO mais a raté les tests des endpoints qu'il modifiait. Viole **AC6.6** (suite existante verte) et l'invariant non-régression.

**Solution** : ajouter la création de `system_settings` **une fois dans `WpkgSchemaBootstrapper::bootstrap()`** (lieu central) ; retirer les patches inline dupliqués (tests de page + tests 15.6 qui créent la table localement). Relancer toute la suite `tests/Feature/Wpkg/`.

**Action** : corrigé automatiquement.

### #2 — 🟠 Audit (AC5) non réellement testé

**Fichier(s)** : `tests/Feature/Gpo/WpkgDeploymentSettingsPageTest.php:385-407, 409-425`

**Constat** : `toggle_winget_emits_structured_log_audit` installe un mock `Log` mais n'assert jamais le contenu capturé (`$logged` ignoré) ; assertion finale seulement sur `SystemSetting::get`. `confirm_add_cidr_emits_log_with_required_fields` ne vérifie que la persistance DB. → **AC5.1/AC5.2 (audit `user_id`/`setting`/`old`/`new` depuis `save()`) non couvert** — c'est précisément le piège Livewire D5.

**Solution** : `Log::shouldReceive('channel')->with('wpkg-deploy')->once()->andReturnSelf()` + `->shouldReceive('info')->once()->withArgs(fn($msg,$ctx) => $ctx['event']==='wpkg_deployment_setting_changed' && $ctx['old']===false && $ctx['new']===true && $ctx['user_id']===$admin->id)`. Idem CIDR (old=ancienne liste, new=nouvelle).

**Action** : corrigé automatiquement.

### #3 — 🟠 Validation allowlist non appliquée aux écritures programmatiques

**Fichier(s)** : `app/Wpkg/Deployment/Services/WpkgDeploymentSettings.php:56-73`, `app/Http/Middleware/EnsureLocalRequest.php:58-64`

**Constat** : `SafeIpCidrRule` n'est exécuté que dans le chemin UI (`prepareAddCidr()`). `allowedIps()` ne fait que filtrer non-string/vides, **sans re-valider**. Vérifié : `IpUtils::checkIp("203.0.113.5", ["0.0.0.0/0"])` = `true` → si `wpkg.allowed_ips` contient `0.0.0.0/0` (seed, SQL manuel, bug futur), `EnsureLocalRequest` **s'ouvre à tout Internet** sur des endpoints non authentifiés. La frontière dépend du seul point d'écriture UI.

**Solution** : `allowedIps()` re-filtre par `SafeIpCidrRule` (fail-closed : entrée invalide/trop large **ignorée**). Test « DB pollué à `0.0.0.0/0` → IP externe quand même 403 ».

**Action** : corrigé automatiquement (fail-closed) — cf. question #1.

### #4 — 🟡 Table/DB absente → 500 au lieu de comportement legacy

**Fichier(s)** : `app/Wpkg/Deployment/Services/WpkgDeploymentSettings.php:40,68`

**Constat** : si `system_settings` absente/DB down, `SystemSetting::get()` lève. En prod la table est toujours migrée (5.1c) → 500 reste fail-closed (pas d'ouverture), severité mineure, mais ≠ « strictement inchangé » (avant : pas de DB touchée).

**Solution possible** : try/catch retombant sur `config()` pour `wingetEnabled()` (jamais sécurité-sensible côté ouverture) et `[]` (deny) pour `allowedIps()`. **Recommandation : statu quo** (table = prérequis dur, documenté).

**Action** : en attente décision utilisateur (cf. question #2).

### #5 — 🟡 Tests 403 ne couvrent que `mount()`

**Fichier(s)** : `tests/Feature/Gpo/WpkgDeploymentSettingsPageTest.php:337-358`

**Constat** : les tests `*_aborts_403_without_server_admin` testent l'échec au mount, jamais `call('toggleWinget')`/`call('confirmAddCidr')`. Le code applique bien `abort_unless` par action (défense en profondeur OK) mais ce n'est pas prouvé.

**Solution** : test qui appelle directement l'action sans droit → 403.

**Action** : corrigé automatiquement.

### #6 — 🟡 Assertions `assertNotEquals(403, …)` trop laxistes

**Fichier(s)** : `tests/Feature/Wpkg/Deployment/Http/EnsureLocalRequestSettingsTest.php:98,111,125,151,177,211`

**Constat** : pour les cas « autorisé », seul « pas 403 » est exigé → un 500 passerait silencieusement (a masqué #1 dans ce fichier qui crée la table inline).

**Solution** : `assertOk()`/`assertStatus(200)` sur les cas autorisés.

**Action** : corrigé automatiquement.
