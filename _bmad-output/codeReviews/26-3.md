## Détail des problèmes

### #1 — `du` exit-code ≠ 0 tue le snapshot intégral (BLOQUANT)

**Sévérité** : 🔴 — **Pertinence Opus : 3/3**
**Fichier** : `app/Services/RoamingProfileService.php` (`scanProfileSizes`)

**Constat** : `du --max-depth=1 -b` sort en **code 1** dès qu'UN sous-dossier est illisible (ACL hétérogènes, profil en cours d'écriture pendant le scan nocturne) tout en imprimant des tailles VALIDES pour tous les autres. Le code faisait `if (!$result->successful()) return null;` → snapshot entier abandonné. Sur un `/home/profiles` réel (centaines de profils), il suffit d'un seul dossier protégé pour que la commande ne persiste **jamais rien** — pastille et compteur orphelins éternellement vides en prod, alors que tous les tests CI passent (pas de `/home/profiles` en CI). Bug masqué par les tests verts.

**Avis Opus** : confirmé et reproduit (`chmod 000` sur un sous-dossier → EXIT=1 + sorties valides). Seul bug réellement bloquant de la story.

**Action** : ✅ **Corrigé automatiquement.** `scanProfileSizes` parse désormais la sortie disponible quelle que soit l'issue ; les lignes d'erreur `du: …` (sans tabulation) sont ignorées par `parseDuOutput`. On ne retourne `null` (fail-soft) QUE si rien n'est exploitable (sortie vide ET code ≠ 0). Log en `warning` sur succès partiel, `error` sur échec total. Test ajouté `it_ignores_du_error_lines_and_keeps_valid_entries`.

### #2 — TOCTOU `detectOrphans` en batch

**Sévérité** : 🟠 → **Pertinence Opus : 1/3 (surévalué)**

**Constat initial (sonnet)** : la re-vérification d'orphelin se fait une fois avant la boucle, pas par dossier → AC #4 non respecté à la lettre.

**Avis Opus** : sonnet décrit mal le code. `purgeOrphanProfiles` construit `$stillOrphans` via `detectOrphans` (re-requête BDD fraîche) puis chaque dossier passe la Garde 2 (`isset($stillOrphans[$dir])`). L'AC #5 (« re-confirmer avant tout rm ») est **respecté** : un compte présent en base au moment de l'appel n'est jamais purgé (test `it_never_purges_a_dir_whose_user_exists`). La fenêtre TOCTOU résiduelle (quelques ms en mémoire PHP) est négligeable et intrinsèque à toute opération FS. Sur-ingénierie d'exiger un `EXISTS` par dossier.

**Action** : ❌ Non corrigé (faux positif).

### #3 — Flag `$created` unique pour deux tables

**Sévérité** : 🟡 — **Pertinence Opus : 2/3**
**Fichiers** : `tests/Unit/Services/RoamingProfileCleanupTest.php`, `tests/Unit/Console/ProfilesSnapshotCommandTest.php`

**Constat** : `$created` passe à `true` dès qu'UNE des deux tables est créée ; `tearDown` droppe les deux inconditionnellement → risque de drop d'une table `users` pré-existante d'une autre suite.

**Action** : ✅ **Corrigé.** Flags séparés `$createdUsers` / `$createdSettings` dans les deux fichiers ; `tearDown` ne droppe que ce que le test a créé.

### #4 — Test 403 testerait le mount, pas la méthode

**Sévérité** : 🟡 → **Pertinence Opus : 0.5/3 (faux positif)**

**Avis Opus** : en Livewire v3, `->call()` sur un handle existant déclenche une requête `update` (hydratation du snapshot), **pas un `mount()`**. Le 403 testé provient bien de la double-garde dans `purgeOrphans()`. Le test fait exactement ce qui est attendu.

**Action** : ❌ Non corrigé (faux positif).

### #5 — Chargement global des logins + `strtolower` PHP vs `LOWER()` SQL

**Sévérité** : 🟡 — **Pertinence Opus : 2/3**
**Fichier** : `app/Services/RoamingProfileService.php` (`detectOrphans`)

**Constat** : `pluck('login')` charge tous les logins en mémoire (acceptable : job nocturne uniquement, jamais au render). Sous-point réel : `detectOrphans` compare via `strtolower()` PHP (ASCII) alors que `findByLogin` utilise `LOWER()` SQL (locale-aware). Sur un login non-ASCII, divergence possible → un compte accentué pourrait apparaître orphelin dans le compteur. Risque de **suppression à tort** faible (la purge re-passe par `detectOrphans`, cohérent ASCII des deux côtés).

**Action** : 📝 **Documenté** (story Dev Notes + QA). Logins SambaEdu = sAMAccountName ASCII en pratique. Pas de changement de code.

### #6 — `isValueSafe` détournée pour des noms de dossier

**Sévérité** : 🟡 — **Pertinence Opus : 2.5/3**
**Fichier** : `app/Services/RoamingProfileService.php` (`purgeOrphanProfiles`)

**Constat** : `VALUE_REGEX` autorise `/` (conçue pour des chemins relatifs d'exclusion GPO). La réutiliser pour valider un nom de dossier de premier niveau était fonctionnellement rattrapé par `|| str_contains($dir, '/')`, mais le modèle de sécurité était trompeur (un lecteur pouvait croire qu'`isValueSafe` suffisait).

**Action** : ✅ **Corrigé.** Méthode dédiée `RoamingProfileService::isSafeProfileDirName()` (regex stricte `^[\w\-. ]+$` sans `/`, veto `..`/`.`). La Garde 1 de la purge l'utilise désormais. Defense-in-depth maintenue (Garde 3 realpath confiné inchangée).

### S1 — `rename` cross-device + collision suffixe

**Sévérité** : 🟠 — **Pertinence Opus : 2.5/3**
**Fichier** : `app/Services/RoamingProfileService.php` (`purgeOrphanProfiles`)

**Constat** : (a) `rename()` échoue `EXDEV` si `/home/profiles` et `/home/admin` sont sur des mounts différents — sans fallback. (b) Le suffixe `date('YmdHis')` (précision seconde) peut collisionner si deux purges du même dossier tombent dans la même seconde.

**Vérification VM** : `findmnt`/`stat` → `/home/profiles` et `/home/admin` sur **le même device** (`/dev/vda1`, id `65025`). `rename` OK sur l'infra actuelle.

**Action** : ✅ **Corrigé** (décision Henri : robustesse immédiate). Méthode `moveToTrash()` : `rename()` puis repli `mv -f` (cross-device) si échec ; succès confirmé seulement si la source a disparu. Repli cantonné au chemin d'action admin (jamais au render → invariant perf préservé). Collision de suffixe corrigée (`-N` incrémental). Tests `it_falls_back_to_mv_when_rename_fails_cross_device` + `it_never_shells_out_at_render_or_purge` (confirme zéro shellout au render).

### S2 — `_Trash_users` jamais vidé

### S3 — Troncature login `.*$`

**Sévérité** : 🟠 — **Pertinence Opus : 2.5/3**

**Constat** : `loginFromProfileDir` strippe `\.V\d+.*$`. Un login contenant `.V<chiffres>` serait tronqué → mal classé → potentiellement purgé. Divergence avec le legacy (qui exige le suffixe `.V` pour considérer un profil valide).

**Action** : ⏳ **Documenté** (hypothèse logins ASCII sans pattern `.V\d`) → **question #2**. Pas de modification de regex sans décision (changement de comportement pour les dossiers `.bak`).
