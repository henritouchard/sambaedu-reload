## Détail des problèmes

### #1 — `err.Error() == "EOF"` fragile

**Sévérité** : 🟠 (reclassé 🟡 par opus — dette robustesse, non bug actif)
**Fichier** : `agent/windows/handler_applications_windows.go:291`

**Constat initial (sonnet)** :
`parseWpkgXMLInstalled()` compare `err.Error() == "EOF"` au lieu de `errors.Is(err, io.EOF)`. Fragile si l'erreur est wrappée.

**Avis Opus** (2/3) :
Fonctionne en pratique (`io.EOF` nu retourné par `xml.Decoder.Token()`), mais anti-idiomatique. `io` n'est pas importé dans ce fichier. Reclassé 🟡.

**Action** : corrigé automatiquement (`errors.Is(err, io.EOF)` + import `"io"`).

### #4 — Profils par-hôte sans SetACL SYSTEM

**Sévérité** : 🟠
**Fichier** : `agent/windows/handler_applications_windows.go:206-226` + `agent/shared/files.go`

**Constat initial (sonnet)** :
`writeFileAtomicLocal()` écrit `profiles.xml`/`hosts.xml` sans ACL SYSTEM, contrairement aux autres fichiers agent.

**Avis Opus** (2/3) :
`profiles.xml` pilote QUELLES apps WPKG installe machine-wide. Si un user local peut le réécrire, il oriente une install SYSTEM (vecteur d'élévation). Asymétrie réelle avec le reste de l'agent.

**Solutions possibles** :
1. Passer les écritures via `store.writeAtomic()` (avec `setACL` SYSTEM)
2. Appeler `o.store.setACL(path)` après chaque fichier déposé
3. Créer le sous-dossier `wpkg/` via Store au démarrage du handler (setACL sur le dossier)

**Action** : en attente décision Henri (voir question #2 ci-dessus).

### #11 — Chemin `wpkg.xml` manquant : System32 (🔴 CRITIQUE — opus uniquement)

**Sévérité** : 🔴
**Fichier** : `agent/windows/handler_applications_windows.go:124-140`

**Constat (opus)** :
`wpkgXMLCandidatePaths()` ne tente que `%SystemDrive%\wpkg.xml` (C:\) et `%ProgramData%\wpkg.xml`. Or `wpkg-se4.js` écrit son settings file via `getSettingsPath()` (ligne 5206) qui résout `fso.GetSpecialFolder(1)` = `C:\Windows\System32`. Ce chemin n'est pas dans la liste des candidats.

**Conséquence en production** :
- `ListInstalled()` renvoie toujours `[]`
- `Test()` toujours faux → re-déclenchement WPKG à CHAQUE cycle (jamais de `compliant`)
- Inventaire toujours `error` pour toutes les apps (AC2 idempotence + AC4 inventaire cassés)

**Action** : corrigé automatiquement (ajout de `filepath.Join(os.Getenv("SystemRoot"), "system32", "wpkg.xml")`).
