## Détail des problèmes

### #1 — `Cache::lock::block()` lève au lieu de retourner false

**Fichier** : `app/Services/Network/DhcpService.php:238-262`

**Constat (sonnet)** : `Cache::lock('dhcp.reload', 30)->block(15)` lève `Illuminate\Contracts\Cache\LockTimeoutException` après timeout ; ne retourne jamais false. Le code `if (!$lock->block(15)) { throw new DhcpCommandException(...) }` est donc inatteignable. Documentation D-LOCK-1 promet `DhcpCommandException` au timeout, code ne respecte pas.

**Vérification opus** : confirmé (pertinence 2). Le toast d'erreur générique remonte au lieu d'un message de contention dédié.

**Solution** : wrapper le `block()` dans try/catch `LockTimeoutException` → throw `DhcpCommandException` avec contexte clair.

### #2 — Injection HTML dans `wire:click`

**Fichier** : `resources/views/pages/network/dhcp/_partials/leases-table.blade.php:46`

**Constat** : `wire:click="preFillFromLease('{{ $lease['mac'] }}', '{{ $lease['ip'] }}', '{{ $lease['hostname'] ?? '' }}')"` — Blade `{{ }}` échappe les apostrophes en `&#039;` ce qui casse la chaîne JS. Surface d'attaque si `dhcpd.leases` est manipulé.

**Solution** : passer par l'index du lease (`preFillFromLeaseByIndex({{ $loop->index }})`) et récupérer les valeurs côté PHP depuis la collection.

### #3 — Upsert `orWhere` non-déterministe

**Fichier** : `app/Services/Network/DhcpImportService.php:229-234` (et `DhcpService.php:616-619`)

**Constat** : `where(mac)->orWhere(name)->orWhere(ip)->first()` retourne la ligne avec `id` le plus bas, pas nécessairement celle matchant la MAC. Peut écraser une ligne différente, ou tomber sur violation `UNIQUE`. D-CSV-UPSERT documente la priorité MAC > name > IP, code ne l'implémente pas.

**Vérification opus** : pertinence 3 (très pertinent). C'est le bug le plus sérieux du lot.

**Solution** : pipeline `where('mac')->first()` puis fallback `where('name')` puis `where('ip')`, premier non-null gagne.

### #4 — `rendering()` spam sudo

**Fichier** : `resources/views/pages/network/dhcp/index.blade.php:49-61`

**Constat** : hook `rendering()` appelle `serviceStatus()` → process `sudo systemctl is-active` à chaque cycle Livewire (recherche debounced, ouverture modale, etc.). Si le service est down et `systemctl` lent, page inutilisable.

**Vérification opus** : pertinence 3.

**Solution** : `Cache::remember('dhcp.service_status', 15, fn() => ...)` dans `DhcpService::serviceStatus()`.

### #5 — Blocs malformés non comptabilisés

**Fichier** : `app/Services/Network/DhcpService.php:565-569`

**Constat** : regex `host ... { ... }` ne matche pas les blocs sans `}` fermant → skip silencieux. AC9 dit « comptabilisé en errors[] ».

**Décision Q1** : Améliorer le parser. Après le pass regex principal, détecter les fragments `host <cn> {` orphelins (sans match complet) → ajouter en `errors[]` avec ligne et raison.
