## Détail des problèmes

### #1 — Doc gate erronée (computer.control/scopé vs réel computer.install global)

**Sévérité** : 🟠 — **Pertinence Opus** : 3
**Fichier(s)** : `resources/views/pages/parc-settings/_partials/environment-tab.blade.php` (docblock l.20-24), story l.52 & l.135

**Constat initial (review)** : La story et le docblock du SFC affirment que `update-workstationGroup` mappe `computer.control` avec délégation scopée. En réalité `WorkstationGroupPolicy::update()` → `canAdminComputers()` → `computer.install` = **droit admin GLOBAL sans scoping**. C'est `manage-workstationGroup` qui porte `computer.control` + délégation scopée.

**Avis Opus** : Confirmé (3). Le **choix** de gate (`update`) est cohérent avec `parc/groups/[id]` (mêmes lignes 181/219) ; c'est la **justification écrite** qui est fausse. Deux issues mutuellement exclusives : corriger la doc (assumer admin global) OU basculer sur `manage` (activer le scoping promis).

**Action** : Doc corrigée pour refléter la réalité (`computer.install`, admin global, cohérent avec l'édition de parc). Le **choix fonctionnel** gate `update` vs `manage` est laissé en question ouverte à Henri (cf. Questions en attente #1).

### #2 — Valeur invalide via Livewire → null silencieux + toast succès trompeur

**Sévérité** : 🟠 — **Pertinence Opus** : 2
**Fichier(s)** : `resources/views/pages/parc-settings/_partials/environment-tab.blade.php` (l.84-86)

**Constat initial (review)** : `WorkstationEnvironment::tryFrom($value)` sur une valeur hors-liste retourne `null` → le parc est sauvé à `null` (= « Non déclaré ») et un toast de **succès** est émis. Une valeur corrompue (requête Livewire forgée) réinitialise silencieusement le parc en affichant un succès. Non testé.

**Avis Opus** : Confirmé (2). Surface d'attaque faible (le `<select>` n'expose que des valeurs valides) mais le commentaire « écarte défensivement » est trompeur — ça **avale** silencieusement. Correction simple et non ambiguë.

**Action** : Corrigé — `tryFrom() === null` sur valeur non-vide → `toastError` + `return` (aucune écriture). Commentaire reformulé. Test `invalid_value_toasts_error_and_writes_nothing` ajouté.

### #3 — Aucun test du refus de gate + docblock test mensonger

**Sévérité** : 🟡 — **Pertinence Opus** : 2
**Fichier(s)** : `tests/Feature/Livewire/ParcSettings/EnvironmentTabTest.php` (l.22 docblock)

**Constat initial (review)** : Le docblock annonce « le refus est couvert à part » — faux, aucun test ne le couvre. Le `setUp()` pose `Gate::before(... => true)` qui court-circuite la policy.

**Avis Opus** : Confirmé (2). La « double protection » annoncée n'est pas prouvée.

**Action** : Corrigé — test `save_is_forbidden_without_permission` ajouté (user sans droit, sans `Gate::before`, attend `AuthorizationException`) + docblock corrigé.

### #S1 — Précédence non fail-safe si une 4ᵉ case enum est ajoutée (trouvé par Opus)

**Sévérité** : 🟠
**Fichier(s)** : `app/Services/Agent/WorkstationEnvironmentResolver.php` (const `PRECEDENCE` l.51-55)

**Constat (Opus)** : `PRECEDENCE` est une constante manuelle de 3 éléments. Si l'Epic 27 ajoute une case sans l'ajouter à `PRECEDENCE`, la boucle ne la trouvera jamais → retombe silencieusement sur `shared_local`, même si c'est la seule valeur déclarée. Bug silencieux pour une story dont le but est d'alimenter des handlers futurs.

**Action** : Corrigé — test-garde `precedence_covers_every_enum_case` (`PRECEDENCE` exhaustive vs `WorkstationEnvironment::cases()`) + commentaire « toute nouvelle case DOIT être ajoutée ici » sur la constante.
