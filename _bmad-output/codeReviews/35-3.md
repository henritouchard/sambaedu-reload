## Détail des corrections

### #1 — Sonde anti-orpheline sur les écritures HKU

**Fichier(s)** : `agent/windows/handler_registry_windows.go` (Write), `agent/shared/handler_registry.go` (contrat `RegistryOps.Write`), `agent/shared/handler_registry_test.go`

**Solution appliquée** : avant toute écriture ciblant `HKEY_USERS`, sonde de la racine de fan-out (`.DEFAULT`/`<SID>`) via `OpenKey(QUERY_VALUE)` — `ErrNotExist` ⇒ no-op nil (jamais de clé orpheline ; la ruche disparaît de l'énumération au cycle suivant, l'item redevient conforme). Contrat documenté sur l'interface, fake aligné (`unmountedHku`), test du CHEMIN RÉEL ajouté : `TestRegistryHkuWriteSkipsHiveUnmountedAfterEnumeration` (énumérée puis démontée ⇒ `.DEFAULT` seule écrite, zéro orpheline, zéro erreur, conforme au cycle suivant). Le test à erreur injectée est conservé (il couvre l'isolation d'erreur générique). `ensure:absent` était indemne (Delete idempotent).

### #2 — Sémantique d'erreur en Test : design assumé, documenté

**Solution appliquée** : docblock de `RegistryHandler.Test` explicite — les erreurs de lecture restent FRANCHES en Test (y compris par-cible HKU) : une ruche chargée à ACL hostile met le type registry de la portée en error pour LE cycle (Apply non atteint). Contrepartie assumée : un Test qui avale les erreurs en drift masquerait des pannes réelles à la policy STRICT. L'isolation par-cible ne vaut qu'en Apply (effort maximal).

### #3 — Convention short-form documentée

**Solution appliquée** : docblock `ALLOWED_HIVES` du `CapabilitySpecCollisionGuard` — forme courte exclusive à l'authoring ; un import amont devra normaliser.
