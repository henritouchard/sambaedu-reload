## Détail des problèmes

### #1 — N+1 `AdSyncChecker`

**Sévérité** : 🟠 — **Pertinence Opus : 2**
**Fichier(s)** : `app/Services/AdSync/AdSyncChecker.php:328-345`

**Constat initial (review)** : `Workstation::all()` sans eager-load, puis `$machine->physicalRoom?->id` dans la boucle → l'accessor exécute `physicalRooms()->first()` à chaque itération (1 SELECT/machine). Régression vs la FK scalaire (0 requête).

**Avis Opus** : réel mais nuancé — la boucle faisait déjà `$machine->groups()->pluck('name')` (N+1 préexistant) ; chemin froid (diagnostic admin). La correction règle les deux N+1 d'un coup.

**Solution appliquée** : eager-load `physicalRooms` (et lecture des groupes via la relation chargée) dans `checkMachines()`.

### #2 — `$oldRoomId` hors transaction

**Sévérité** : 🟠 — **Pertinence Opus : 1**
**Fichier(s)** : `app/Services/Parc/WorkstationGroupService.php:1045-1069`

**Constat initial (review)** : en cas de swaps concurrents du même poste, la garde `$oldRoomId !== $roomId` peut être évaluée sur une valeur rassie et inhiber un dispatch `move` légitime.

**Avis Opus** : ne touche que le dispatch AD (idempotent, `tries=3`), jamais l'intégrité du pivot (transactionnelle, AC3 tenu). Scénario quasi-inexistant en contexte scolaire. `SELECT FOR UPDATE` = sur-ingénierie.

**Solution appliquée** : risque accepté, documenté par commentaire au point de capture.

### #3 — `importFromAd` : chemin de traverse + bug latent

**Sévérité** : 🟠 requalifiée **🔴** — **Pertinence Opus : 3**
**Fichier(s)** : `app/Services/Parc/WorkstationGroupService.php:1304-1313` (appelé par `resources/views/pages/sync-from-ad/index.blade.php:433`)

**Constat initial (review)** : `groups()->attach($group->id, ['physical' => true])` bypasse le swap (double-salle possible, pas de dispatch move, pas de validation).

**Avis Opus (requalification)** : pire — le guard d'existence `->wherePivot('physical', true)` ne voit pas une salle attachée par le swap (qui ne pose pas `physical`, relation sans `withPivot`). Second `attach` sur la même paire → violation `wg_ws_unique` → le catch externe (l.1325) **rollback l'intégralité de l'import AD**. La méthode n'est pas `@deprecated` (warning runtime seulement) et reste appelée par l'UI sync-from-ad.

**Solution appliquée** (arbitrage Henri : pas encore en prod, pas de données existantes) : 3e passe routée vers `assignMachineToPhysicalRoom((int) $ws->id, (int) $group->id, dispatchAdSync: false)` — nouveau paramètre `bool $dispatchAdSync = true` sur le swap ; skip si la salle courante est déjà la bonne ; guard `is_physical` défensif.
