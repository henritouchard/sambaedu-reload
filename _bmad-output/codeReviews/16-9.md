## Détail des problèmes

### #1 — Sidebar « Toutes les GPOs » non surligné sur sous-pages GUID

**Sévérité** : 🟡 Mineur
**Fichier(s)** : `resources/views/components/organisms/sidebar.blade.php:103`

**Constat initial (sonnet)** :
Le `request()->is('admin/settings/gpo')` fait un match exact. Sur `/admin/settings/gpo/{guid}` ou `/admin/settings/gpo/{guid}/links`, aucun des 3 liens du bloc GPO ne reçoit la classe active. Le bloc collapse reste ouvert (via `@checked(request()->is('admin/settings/gpo*'))`), mais aucun item surligné.

**Avis Opus** (pertinence 2/3) :
Le scénario QA `16.9-3` ligne 1349 documente explicitement que « *aucun lien direct vers ces sous-pages paramétrées GUID n'est exposé dans la sidebar (iso-Phase 1)* ». Le comportement actuel est donc **intentionnel** et conforme à la doc QA. En revanche, l'UX reste sous-optimale : aucun feedback visuel sur la position hiérarchique.

**Solutions possibles** :
1. **Laisser tel quel** (cohérent avec la doc QA Phase 1, cohérent avec le fait qu'il n'y a pas de breadcrumb dans `<x-organisms.page>`)
2. Modifier la condition pour surligner « Toutes les GPOs » sur les sous-pages GUID : `request()->is('admin/settings/gpo') || (request()->is('admin/settings/gpo/*') && ! request()->is('admin/settings/gpo/wine') && ! request()->is('admin/settings/gpo/wpkg-deployment'))`

**Action** : ❌ Non corrigé — décision user 2026-05-17 = solution 1 (laisser tel quel, cohérent avec la doc QA).

### #6 — `assertStringContainsString` au lieu de `assertRedirect()`

**Sévérité** : 🟡 Mineur
**Fichier(s)** : `tests/Feature/Gpo/LegacyAppGpoRoutesRedirectTest.php` (toutes les méthodes)

**Constat initial (sonnet)** :
L'AC6.2 mentionnait `assertHeader('Location', '...')` ou équivalent strict. L'implémentation utilise systématiquement `assertStringContainsString` qui matche en sous-chaîne.

**Avis Opus** (pertinence 1/3) :
Convention de qualité plus que sécurité. `assertRedirect($uri)` combine `assertStatus(3xx)` + `assertHeader('Location', $uri)` — plus expressif.

**Action** : ✅ Corrigé — 3 redirections statiques migrées vers `assertRedirect('/admin/settings/gpo[/...]')`. Les 2 routes GUID conservent `assertStatus(301)` + `assertHeader('Location', $expected)` strict.

### #7 — URLs hardcodées `url('/admin/settings/gpo/...')` au lieu de `route('admin.gpo.*')`

**Sévérité** : 🟡 Mineur (mais dette réelle)
**Fichier(s)** :
- `resources/views/pages/admin/settings/gpo/[guid]/index.blade.php:284, 434, 458`
- `resources/views/pages/admin/settings/gpo/[guid]/links/index.blade.php:554`
- `resources/views/pages/admin/settings/gpo/wpkg-deployment/index.blade.php:295, 313`

**Constat (opus)** :
Plusieurs liens internes utilisent `{{ url('/admin/settings/gpo/' . $this->guid . '/links') }}` au lieu de `route('admin.gpo.links', ['guid' => trim($this->guid, '{}')])`. Si l'URL change un jour, ces hardcodes casseront silencieusement. Le pattern `route()` est déjà utilisé dans `gpo-back-link.blade.php:58` et `[guid]/index.blade.php:366`.

**Action** : ✅ Corrigé — toutes les occurrences remplacées par `route('admin.gpo.*')` avec strip d'accolades sur le GUID.
