- `classGroupNames(): Collection` — noms nus des classes (`type='classe'`) dont l'utilisateur est membre.
- `sharesClassGroupWith(User $other): bool` — intersection des classes.

## Détail des problèmes

### #1 — `syncGroupsWithAd` no-op silencieux pour classes foldées

**Sévérité** : 🔴 — **Fichier(s)** : `app/Services/UserGroupService.php`

**Constat (sonnet, confirmé opus 3/3)** : `syncGroupsWithAd([$id])` passait le `name` SQL nu en `onlyGroupNames`, comparé aux CN bruts AD → aucun match → 0 upsert. Non destructif (passe `deleted` skip) mais bouton UI « Synchroniser avec AD » cassé.

**Correctif** : le filtre `onlyGroupNames` de `syncFromAd` matche désormais chaque CN AD sur sa base nue (`stripClasseLikePrefix`) en plus du CN brut. Test #7 ajouté.

**Action** : corrigé.

### #2 — `UserService::persistUserGroupsToSql` ne rattache plus l'élève à sa classe

**Sévérité** : 🔴 — **Fichier(s)** : `app/Services/UserService.php:1444-1451`

**Constat (sonnet, confirmé opus 3/3)** : lookup `'Classe_'.$c` ne matche plus la ligne nue → élève non rattaché à sa classe SQL à la création.

**Correctif** : lookup classe par nom nu + fallback `Classe_<c>` + garde `type IN ('classe','class')`. `oldClassIds` inchangé (capte la ligne nue via `type='classe'`). Branche catégorie/fonction intacte. Test #8 ajouté.

**Action** : corrigé.

### #3 — `UserPolicy::sharesClassWithTarget` → prof ne voit/reset plus aucun élève

**Sévérité** : 🔴 — **Fichier(s)** : `app/Policies/UserPolicy.php:248-256`

**Constat (sonnet, confirmé opus 3/3)** : logique vestige `type='equipe'` + `name LIKE 'Equipe_%'/'PP_%'` → vide après fold → `return false` systématique → régression story 7.2.

**Correctif** : recâblé sur le helper partagé `User::sharesClassGroupWith()` (membres de la même ligne nue `type='classe'`, rôle via `User.role`). Scope toujours strict (prof voit uniquement SES classes). Test #10 réécrit au modèle post-fold.

**Action** : corrigé.

### #4 + #5 — `shouldFold` non-idempotent + N `EXISTS`

**Sévérité** : 🟠 — **Fichier(s)** : `app/Services/UserGroupService.php` (`shouldFold`)

**Constat (sonnet, confirmé opus 3/3 et 2/3)** : la décision de fold lisait un état SQL muté (`EXISTS`) → `Equipe_` orphelin basculait `equipe`→`classe` au 2e run (viole AC6) ; + N requêtes sur gros lots.

**Correctif** : décision de fold sur le **seul lot AD courant** (`$foldAnchorBases`), `EXISTS` supprimé → idempotence (AC6) ET perf corrigées en un seul changement. `Equipe_` orphelin reste type `equipe` nom nu, stable sur N runs. Test #9 ajouté (2 runs).

**Action** : corrigé.

### #6 — `total_groups_detected` compte les CN bruts
