## Détail

### #1 — `room: null` vs docblock `""` 🟡 (pertinence 2)
`OverlayMachineStateProvider.php:39` : le docblock affirmait « `null`/absent → room vide (`""`) » alors que le code émet `room: null` (et le test assert `assertNull`). Sans impact fonctionnel (Go retombe sur `""`), mais commentaire mensonger. **Action** : ✅ docblock réécrit — l'item porte `room: null` (valeur nulle explicite, iso `wallpaper asset: null`) ; c'est `ComposeOverlayDocument` (Go) qui garantit `room: ""` dans le document, pas l'item d'état.

### #2 — Cas `room:null` non testé côté Go 🟡 (pertinence 2)
Tous les tests compose passaient une `string`. Le cas réel `{kind:"machine", room:null}` (poste sans WG physique) n'était pas couvert. **Action** : ✅ `TestComposeOverlayDocumentMachineRoomNull` ajouté → `room:null` ⇒ `"room": ""` + `machine.name` local.

### #3 — Best-effort machine-sain/session-corrompue 🟠 (pertinence 2)
`TestOverlayDocumentForSession_CorruptedCacheGraceful` ne couvrait que « session corrompue SANS cache machine → false ». Le scénario CŒUR de la story (machine sain + session corrompue/à-moitié-écrite → `ok=true`, room préchargée, identity vide) n'était pas prouvé ; et le log `writeOverlayDocument` disait « aucun cache **de session** » alors que `false` = aucune des DEUX portées. **Action** : ✅ `TestOverlayDocumentForSession_MachineSaneSessionCorrupted` ajouté (room remplie, identity vide, ok=true) + log reformulé « aucun cache exploitable (machine ni session) ».

### #4 — Tri 2 providers `type()=='overlay'` 🟡 (pertinence 1)
`StateCompiler::sortedProviders()` trie par `type` → comparateur 0 entre les deux providers overlay. Sans conséquence (buckets de portée disjoints : `session` vs `machine` → wire-format stable). **Action** : ❌ différé. Invariant désormais = disjonction `(type, scope)`. Un tiebreak secondaire (classe) blinderait le futur si un 3ᵉ provider overlay/session apparaissait — noté, non urgent.

### #5 — `updatedAt` item machine 🟢 (pertinence 0)
`updatedAt: workstation->updated_at` est une métadonnée d'item (tiebreak `exclusive`, jamais emprunté ici), **hors du payload hashé** → n'entre pas dans l'ETag. La salle étant invariante, l'ETag machine reste stable. **Action** : ❌ ignoré (aucun bug). Vigilance future : ne pas injecter de timestamp dans le payload machine.

### #6 — Contrat self-consistant 🟢
Vérifié : golden 6 items (1/4/1) ; identity session 3 clés sans `room` ; item machine portée `machine` `{kind:"machine", room}` ; les 2 constantes figées byte-identiques (`8174042c…4975`) ; hashes par-item et hashState CALCULÉS par les hashers réels (tests `each_state_item_hash_matches` PHP + `TestHashItemGoldenItemsMatchTheirHashFields` Go verts). **Pas de bidouille.**

### #7 — Partition des portées 🟢
Le compagnon (droits user) ignore `state.Machine` et ne lit que son cache session per-SID. La lecture du cache machine est exclusive à `OverlayDocumentForSession` (chemin SYSTEM au logon). `KIND_RESERVED_MACHINE` reclasse un signal posté revendiquant `kind:"machine"` (symétrique d'`identity`, pas d'avalement). Aucune fuite.
