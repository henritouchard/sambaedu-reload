## Détail des problèmes

### #1 — Les assertions `assertNotEquals(404)` masquent des 500 réels

**Sévérité** : 🔴 Critique
**Fichier(s)** : `tests/Feature/LegacyModuleDhcpTest.php:166, 194, 225, 259, 287`

**Constat initial (review)** :
Test VM live (`curl -sI http://localhost/dhcp/make_reservations.php`) → **HTTP 500 Internal Server Error**. Le test `test_make_reservations_loads_without_fatal` passe avec 27 assertions tout en produisant un 500 en production. Même schéma pour les autres endpoints scripts qui retournent 302 (redirection `/interdit.html`) via `header_authorize_script` sans passer par le bootstrap métier — c'est donc un test du routage, pas du shim. Aucun test ne valide que le module fonctionne réellement.

**Solutions possibles** :
1. Whitelister `[200, 302]` (rejetter explicitement 500) + vérifier le contenu attendu (droits refusés pour pages authentifiées, ok pour scripts).
2. Ajouter un bypass `se4_key` dans les params des scripts pour traverser `header_authorize_script` et atteindre le code métier.
3. Au minimum, documenter dans le test que 500 est rejeté (et non masqué).

**Action** : ⏳ En attente (lié à Q3 — décision sur tests authentifiés).

### #2 — `make_reservations.php` produit un 500 en production VM

**Sévérité** : 🔴 Critique
**Fichier(s)** : `legacy/modules/dhcp/make_reservations.php:9`

**Constat initial (review)** :
Le script appelle `export_dhcp_reservations($config)` définie dans `sambaedu/includes/ldap.inc.php:4947`. Or le stub `legacy/stubs/ldap.inc.php` est prioritaire dans l'include_path et empêche le chargement du vrai `sambaedu/includes/ldap.inc.php`. Les 4 fonctions métier DHCP (`set_dhcp_reservation`, `list_dhcp_leases`, `export_dhcp_reservations`, `import_dhcp_reservations`) ne sont jamais définies → fatal error `Call to undefined function`. Confirmé empiriquement : endpoint renvoie 500. AC1/AC5 violées. Le Dev Agent Record affirme « make_reservations.php accessible sans fatal » — inexact.

**Solutions possibles** :
1. Ajouter les shims manquants dans `legacy/ldap.inc.php` avec `_shim_log_unimplemented()` (cohérent avec pattern existant : `create_machine`, `create_group`).
2. Supprimer le stub `legacy/stubs/ldap.inc.php` et charger le vrai `sambaedu/includes/ldap.inc.php` sélectivement.
3. Documenter comme limitation bloquante (fonctionnalité DHCP non utilisable via le shim, à livrer uniquement avec Epic 8).

**Action** : ⏳ En attente décision user (Q1). Impact sur estimation : +1-2h si shim complet.

### #3 — Pas de purge `apcu_delete('dhcp_reservations_lock')` en tearDown

**Sévérité** : 🟠 Important
**Fichier(s)** : `tests/Feature/LegacyModuleDhcpTest.php:97-111, 361-388`

**Constat initial (review)** :
Le test `test_script_make_reservations_with_apcu` purge le verrou avant l'appel (L376-378) mais pas après. Si la requête plante entre `apcu_store` et `apcu_delete`, le verrou persiste entre exécutions. OK en CLI PHPUnit (process éphémère), mais dangereux en CI avec PHP-FPM persistant ou en smoke test VM.

**Solutions possibles** :
1. Ajouter `apcu_delete('dhcp_reservations_lock')` dans `tearDown()`, guardé par `extension_loaded('apcu')`.
2. Dupliquer la purge en `setUp` (pattern défensif).

**Action** : ✅ Corrigé — purge APCu ajoutée en `setUp` et `tearDown`.

### #6 — Injection shell via samba-tool dans `dnsupdate.php`

**Sévérité** : 🟠 Important (atténuée par `se4_key`, mais vulnérable si bypass)
**Fichier(s)** : `legacy/modules/dhcp/dnsupdate.php:26,31,35` + `sambaedu/includes/samba-tool.inc.php:69,1142,1173,1184`

**Constat initial (review)** :
`$_POST['name']` et `$_POST['ip']` sont concaténés sans escape dans des commandes shell exécutées via `exec("/usr/bin/samba-tool " . $command)`. Un nom `foo;rm -rf /` serait injecté. Garde-fou : `header_authorize_script` (IP + clé se4). Confiance réseau uniquement.

**Solutions possibles** :
1. Ne pas corriger (SHIM EXPRESS — on garde le comportement legacy).
2. Documenter comme tech-debt pour Epic 8 (sanitize-name regex `[a-zA-Z0-9._-]+`).

**Action** : ✅ Documenté dans la story § Limitations + tech-debt Epic 8.
