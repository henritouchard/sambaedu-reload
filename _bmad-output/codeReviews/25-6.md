## Détail des corrections appliquées

### P5 — `wire:confirm` sur « Activer »
« Activer » déclenche le déploiement Rainmeter sur **tout le parc** au prochain check-in — l'action la plus impactante — alors que seul « Désactiver » portait une confirmation. Ajout d'un `wire:confirm` symétrique sur « Activer ».

### P6 — Pas de fuite de chemin dans le toast
`AgentToolException` (cas `hash_failed`/`storage_unavailable`) embarquait le chemin disque absolu, affiché tel quel via `toastError`. Le toast utilisateur affiche désormais un message générique + le `reason` machine ; le chemin détaillé reste dans le **log** serveur.

### P1 + P8 — Cleanup orphelin sur exception DB + test
`upload()` : `try/finally` (`@unlink` du fichier déplacé) autour de l'écriture DB post-`moveConfined` → une exception `updateOrCreate` (DB down, contrainte) ne laisse plus de `.zip` orphelin. Test ajouté : un refus (et un échec post-`move`) ne laisse aucun fichier dans `tools_path`.

## Problèmes laissés en l'état (par décision)

- **N1 (follow-up)** : sortir le provisioning de la skin du chemin de lecture GET (le déclencher au boot/upload) pour éviter une écriture disque + warning par check-in à l'échelle parc (NFR4). Noté pour une story de suivi.
- **P7** : le test manifest recalcule le hash de la skin canonique au runtime → il suit la skin (pas cassant), mais ne détecterait pas une régression de contenu. Compromis assumé (pas de hash figé).
