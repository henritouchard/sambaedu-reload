## Détail des problèmes

### #1 — 🔴 DO-1 : `linux_out` rend body vide pour tous les postes Linux

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Wpkg/Deployment/Http/Controllers/LinuxOutController.php` ; cause racine documentaire dans la story (D1).

**Constat initial (Sonnet)** : `ApplicationScriptsAssembler` (17.2) injecte `id=<md5_session>` dans le préambule de `startup.linux`, pas `id=<hostname>`. Donc `WorkstationPackagesResolver::resolve(<md5>)` → vide → body `""` → 0 paquet APT. Le fallback « le poste boot quand même » est trompeur (0 logiciel applicatif). Solutions proposées : bloquer, corriger 17.2, ou flag.

**Avis Opus (pertinence 3/3)** : Confirmé ligne par ligne. `ApplicationScriptsGenerator.php:103` calcule `$id = md5(strtolower($user).strtolower($machine).$action.$application)` ; `ApplicationScriptsAssembler.php:368` injecte ce md5 ; `startup.linux:3` fait `curl -F "id=$id"`. **MAIS** Sonnet a manqué la vraie cause racine et le bon correctif : la décision **D1 de la story est basée sur une prémisse fausse**. Vérifié dans le code :
- `CacheAppContextWriter::write()` (16.7/16.11/16.15) écrit `Cache::store('app_context')->put('apps.'.$id, $context, 1800)` avec `liste_applications` en passthrough dans `raw`.
- Les 6 endpoints `*_out.php` natifs (`wallpaper`, `firefox`, `thunderbird`, `network`, `veyon`, `associations`) résolvent tous via `AppContextRepository::findById($id)` (md5), PAS par hostname (cf. `AssociationsOutController.php:83`).
- Le legacy `linux_out.php` lui-même fait `apcu_fetch("apps.$id")` puis `$info['liste_applications']` — jamais d'appel resolver.

→ **Modifier 17.2 (`id=$(hostname)`) serait une erreur** : casserait la parité bytes 17.2/17.4 ET les 6 autres endpoints. `winget_out` n'est PAS concerné (`install.ps1` envoie `machine=$env:ComputerName` = vrai hostname, et le legacy `winget_out.php:61` résout par hostname sans APCu → la résolution native par hostname y est correcte).

**Solutions possibles** :
1. **(Recommandée Opus)** Aligner `LinuxOutController` sur les 6 siblings : injecter `AppContextRepository`, valider `id` md5 (`^[a-f0-9]{32}$`), `findById($id)`, extraire `raw['liste_applications']`, puis charger les `Application` + construire la liste apt. Iso-legacy strict. `winget_out` reste inchangé.
2. Flag `WPKG_LINUX_OUT_ENABLED=false` par défaut (active le natif seulement quand prêt) + dette tracée — palliatif, ne corrige pas le fond.
3. Bloquer le merge.

**Action** : ✅ **Corrigé** (décision Henri 2026-05-25 : « aligner sur les 6 siblings »). `LinuxOutController` injecte désormais `AppContextRepository` en constructeur, valide `id` md5 strict (`^[a-f0-9]{32}$` ; id absent/invalide → body `""` 200, parité `apcu_fetch` sur clé non posée), `findById($id)` (contexte expiré/absent → body `""` 200 + `Log::debug` iso siblings), puis extrait `raw['liste_applications']`. **Plus aucun appel `WorkstationPackagesResolver`** côté `linux_out` (le contexte porte déjà la liste pré-résolue, iso-legacy strict).

**Forme exacte de `liste_applications` constatée** : liste **plate de chaînes** (`app_id` en minuscules, dédupliquée). Côté legacy `applications.inc.php:969` : `array_map('strtolower', array_column(array_column(info_poste_applications(...), "info_app"), "id_nom_app"))`. Côté natif `ApplicationScriptsGenerator::resolveInstalledApplications()` : `$apps[] = strtolower((string) $name)` (sortie de `WorkstationPackagesResolver::resolve()` mappée lowercase). Le legacy `linux_out.php:27` matche par `array_search(strtolower($package_id), $liste_applications)` — donc **case-insensitive**. Pour reproduire fidèlement cette sémantique sans dépendre de la collation DB, `ApplicationXmlReader::loadByAppIds()` matche désormais en **`LOWER(app_id) IN (lowercased_inputs)`** + indexe le résultat par `strtolower(app_id)`. Sans impact pour `winget_out` (qui passe les `app_id` bruts du resolver = même casse que la DB → `lower==lower` matche toujours). `WingetOutController` reste **inchangé**.

Tests adaptés : `LinuxOutEndpointTest` seede désormais `apps.<md5>` via `Cache::store('app_context')->put('apps.'.$md5, [...], 1800)` (iso-runtime `CacheAppContextWriter`). Cas conservés : happy path (apt explicite + fallback app_id, casse mixte `VLC`), id absent → body vide, id non-md5 → body vide, contexte absent → body vide, POST, IP non-locale → 403 ; + cas S1 (app non-Installed exclue).
