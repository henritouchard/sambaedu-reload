## Détail des problèmes

### #1 — Lettre explicite réservée non filtrée (passe 1 de `resolveLetters`)

**Sévérité** : 🟠 — **Pertinence Opus** : 2/3
**Fichier(s)** : `app/Services/Agent/Providers/DrivesStateProvider.php` (`resolveLetters`, passe 1)

**Constat initial (Sonnet)** : la passe 1 retenait toute lettre explicite stockée en DB sans la confronter à `RESERVED_LETTERS`. Un `network_share` créé (via tinker) avec `letter='K:'` produisait un 2ᵉ candidat `K:` d'UNC différente du home → payloads non identiques → non dédupliqués par le compilateur (dédup **par payload complet**, vérifié `StateCompiler::contentKey`) → l'agent reçoit deux montages réclamant K:, le home (lecteur le plus critique) pouvant être masqué silencieusement.

**Avis Opus** : confirmé réel (dédup par payload, pas par lettre). Risque pratique faible en 34.1 (pas d'UI ; factory `letter=null` auto-assigne hors-réservées) mais conséquence sévère et garde triviale. Cohérent avec le **piège #4** de la story (« l'attribution de lettre doit exclure A,B,C,D,H,I,K,L ») que le dev n'avait appliqué qu'à l'auto-assignation, pas au chemin explicite.

**Action — corrigé automatiquement** : en passe 1, une lettre explicite ∈ `RESERVED_LETTERS` est ignorée (`Log::channel('agent')->warning`, `action_type=agent.drives.reserved_letter_ignored`) et le share **bascule en auto-assignation** (passe 2) sur une lettre sûre du pool — il reste visible sans écraser le home. Test ajouté : `explicit_reserved_letter_falls_back_to_auto_assignment` (le home K: reste sur `\users\<user>\`, le share pirate atterrit sur M:, une seule entrée K:).

### #2 — N+1 dans `provision()`

**Sévérité** : 🟠 — **Pertinence Opus** : 2/3
**Fichier(s)** : `app/Services/Filesystem/NetworkShareService.php` (`provision`)

**Constat initial (Sonnet)** : `provision()` faisait `loadMissing('assignments')` sans la cible polymorphe `assignments.assignable` ; `loginFor`/`unixGroupFor` rechargeaient ensuite `User::find`/`UserGroup::find` par assignation (N+1).

**Avis Opus** : confirmé. Chemin froid (provisioning ponctuel, N petit) → propreté plus que bug, mais à corriger avant 34.3 (templates = nombreuses assignations). Eager-load `morphTo` via `assignments.assignable` supporté (1 requête/type).

**Action — corrigé automatiquement** : `loadMissing(['assignments', 'assignments.assignable'])`. Active le chemin `relationLoaded('assignable')` déjà prévu dans `loginFor`/`unixGroupFor`.

### #3 — Pool de lettres épuisé : omission silencieuse (+ bug pré-existant révélé)

**Sévérité** : 🟡 (+ 🟠 pour le bug révélé) — **Pertinence Opus** : 2/3
**Fichier(s)** : `app/Services/Agent/Providers/DrivesStateProvider.php` (`resolveLetters` passe 2 + boucle candidats)

**Constat initial (Sonnet)** : au-delà de 14 répertoires auto (pool `M..Z`), `nextFreeLetter` renvoyait `null` et le share était omis par `continue` **sans trace**, contredisant la culture fail-soft-non-silencieux du service.

**Bug pré-existant révélé par le test ajouté** : la boucle de construction des candidats faisait `$letterByShare[$row->share_id]` sans garde → `ErrorException: Undefined array key` dès qu'un share était omis. Le « fail-soft » annoncé n'était donc **jamais atteint** — le 15ᵉ share faisait planter toute la compilation `drives` (DoS de l'état pour ce user).

**Action — corrigé automatiquement** : (a) `Log::warning` (`action_type=agent.drives.letter_pool_exhausted`) sur épuisement ; (b) garde `?? null` + `continue` dans la boucle candidats (omission réelle au lieu d'un crash). Test ajouté : `exhausted_letter_pool_omits_the_extra_share` (15 shares → 16 candidats K/H + M..Z, le 15ᵉ omis proprement).

### #6 — Commentaire fallback `unixGroupFor`

**Sévérité** : 🟡 — **Pertinence Opus** : 1/3
**Fichier(s)** : `app/Services/Filesystem/NetworkShareService.php` (`unixGroupFor`)

**Constat** : le repli `strtolower(name)` n'applique pas le préfixe `classe_`/`equipe_`. Sonnet et Opus concluent que c'est **doublement défensif** (le regex de repli rejette les noms réellement invalides ; un nom de groupe inexistant fait échouer `setfacl`, tracé, fail-closed — pas de sur-octroi). Pas de bug.

**Action — corrigé automatiquement** : commentaire explicatif ajouté (pourquoi pas de préfixe dans ce chemin dégradé, fail-closed).
