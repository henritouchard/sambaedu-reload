## Détail des problèmes principaux

### F1 — 🟠 AC2.5 non couvert : aucun test Feature pour JWT révoqué

**Fichier(s)** : `tests/Feature/Api/V1/Config/*.php` (aucun fichier ne contient `revok*`)

**Constat sonnet** : AC2.5 stipule « Chaque appel avec JWT révoqué (entrée `workstation_jwt_revocations` + cache APCu) retourne 401 + code `jwt.revoked` ». Aucun test rédigé. La non-conformité n'est pas documentée dans les DO-*.

**Avis Opus (pertinence 2/3)** : Vérifié. Le middleware `EnsureWorkstationJwt` (16.10) supporte la révocation et est testé en 16.10. La couverture est donc implicite par cohérence middleware. Néanmoins, AC2.5 demande une preuve explicite — 1 test ajouté dans `ApiV1ConfigSecurityTest` matérialiserait l'AC sans complexité.

**Solutions** :
1. Ajouter `revoked_jwt_returns_401_revoked` dans `ApiV1ConfigSecurityTest` ciblant `/api/v1/wallpaper` (≤15 lignes, pattern iso `PingControllerTest`)
2. Documenter explicitement AC2.5 comme couvert par cohérence middleware 16.10 dans Dev Agent Record

**Action** : ⏳ Décision Henri Q1 — recommandation Opus = solution 1.

### F2 — 🟠 Double lookup Workstation DB dans `AppPolicyController::resolveNative`

**Fichier** : `app/Http/Controllers/AppPolicyController.php` lignes 116-117

**Constat sonnet** : `$resolver->resolveAppPolicyScope()` fait un premier lookup `Workstation::query()->where('uuid', $workstationUuid)->first()` (dans `WorkstationConfigContextResolver` ligne 196), puis le controller fait un second lookup ligne 117. Race condition possible + inefficacité.

**Avis Opus (pertinence 3/3 — confirmé)** : Vérifié. Bug réel. La vérification de nullité utilise `$wgWorkstation` (second lookup) alors que `$scope` provient du premier. En conditions normales : double query inutile. En race condition (poste supprimé entre les 2 hits) : incohérence d'état.

**Solutions** :
1. **Recommandée** : utiliser `$resolver->resolve($workstationUuid)` qui retourne `null` si introuvable. Tester `=== null` puis appeler `resolveAppPolicyScope` uniquement si non-null.
2. Étendre `resolveAppPolicyScope` pour retourner un indicateur `workstationFound: bool` explicite.

**Action** : ✅ Correction auto (solution 1).

**Constat sonnet** : Signature `apiV1(WorkstationConfigContextResolver $resolver, ...)` mais `$resolver` n'est jamais appelé. Lookup direct `Workstation::query()->where('uuid', ...)->first()` à la place — viole D4 (résolution via resolver).

### F5 + Opus-21 — 🟠 Test `workstation_uuid_query_is_ignored` ne prouve pas l'isolation JWT

**Avis Opus (pertinence 3/3 — confirmé)** : Le test promet une preuve forte mais en réalité ne valide rien. La seule garantie réelle est le test archi `no_controller_reads_workstation_uuid_from_input` (grep statique).

**Solution combinée** : refactor en utilisant `/api/v1/wallpaper` avec UUID_A seedé (200 image) + UUID_B inexistant en DB en query (`?workstation_uuid=UUID_B`). Si le controller respectait la query → 404 ; si JWT respecté → 200. Preuve binaire.

**Action** : ✅ Correction auto.

### Décisions techniques notables post-corrections

- **F4 + DTO accesseur** : pas besoin d'ajouter d'accesseur Eloquent sur le DTO `WorkstationConfigContext`. Le champ `machineName: string` suffit pour `ShortcutExportController::apiV1` (`$request->merge(['machine' => $ctx->machineName])`).
- **Opus-11 partiel** : seul `WallpaperController::composeWallpaperResponse` voit ses Cache-Control retirés. Les autres controllers (`Network`, `Veyon`, `Associations`, `AppPolicy::baseHeaders`) conservent leurs headers explicites car ces helpers sont aussi appelés par le chemin legacy (`legacyOut` / `legacyFirefoxOut` / etc.) où le middleware `auth.v1.secure-headers` n'est PAS attaché. Les retirer aurait altéré le comportement legacy → AC7.2 violé.
- **F2 résolution** : `AppPolicyController::resolveNative` appelle désormais `resolve()` d'abord (vérification null), puis `resolveAppPolicyScope()`. C'est volontairement 2 lookups DB (au lieu d'1 dans un monde idéal) pour ne pas surcharger l'API du resolver — `resolveAppPolicyScope` retourne les Eloquent `WorkstationGroup`+`User` plus pratiques pour `AppCustomizationService`. La race condition F2 originale est éliminée car les 2 appels passent par le même resolver (donc même UUID, même état DB à l'instant T).
- **F8 / `requireImagick()`** : helper privé léger (`markTestSkipped` si `class_exists('Imagick')` est false). Pattern symétrique pourrait être appliqué dans `ApiV1ConfigSecurityTest::workstation_uuid_query_is_ignored_in_favor_of_jwt` qui utilise aussi Imagick — actuellement il skip directement avec `markTestSkipped` au début (cohérent mais pas factorisé).
