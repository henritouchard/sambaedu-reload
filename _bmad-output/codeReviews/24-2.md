## Détail des problèmes

### #1 — `X-Agent-Mac` jamais envoyé — anti-clonage AC5 inerte

**Sévérité** : 🔴
**Fichier(s)** : `agent/windows/SambaEduAgent.ps1`

**Constat initial (Opus)** :
Le middleware `AuthenticateAgentToken.php` vérifie `X-Agent-Mac` pour l'anti-clonage (`isMacMismatch()`). L'agent n'envoie que `X-Agent-Hostname` — jamais `X-Agent-Mac` — donc `isMacMismatch()` retourne toujours `false`. L'anti-clonage MAC est inerte. Le commentaire prétendait « hostname COURT + MAC » : trompeur.

**Avis Fable** : Pertinence 3 — finding exact. Câbler naïvement est risqué : un poste sur Wi-Fi ou dock USB présente une MAC différente de celle d'enrôlement (NIC PXE) → quarantaine de postes légitimes en masse. Le vrai garde-fou reste le token per-poste. Recommandation : ne pas câbler maintenant, documenter comme limitation volontaire MVP, planifier le fix middleware (match sur liste de MACs) en 25.x.

**Correction appliquée** : commentaire trompeur corrigé dans `SambaEduAgent.ps1`, limitation documentée dans `docs/agent/agent-skeleton.md`.

**Action** : ⏳ en attente décision utilisateur (voir Question 1)

### #2 — `$script:PreviousToken` jamais remis à `$null`

**Sévérité** : 🔴
**Fichier(s)** : `agent/windows/SambaEduAgent.ps1`

**Constat initial (Opus)** :
`$script:PreviousToken` est posé lors d'une rotation mais jamais purgé. Tout 401 futur (révocation admin, token expiré) déclenche un réessai parasite avec un token périmé. La fenêtre de grâce (censée être immédiate) devient permanente.

**Avis Fable** : Pertinence 3 — bug réel confirmé. Fix clair et non-ambigu.

**Correction appliquée** : `$script:PreviousToken = $null` posé dès qu'une réponse non-401 est obtenue avec le token courant (≠ previous), dans `Invoke-AgentHttpWithGrace`.

**Action** : ✅ corrigé automatiquement

### #3 — Affectation morte / logique rotation clarifiée

**Sévérité** : 🟠
**Fichier(s)** : `agent/windows/SambaEduAgent.ps1`

**Constat initial (Opus)** :
`$script:Token = $script:PreviousToken` (ligne ~309) serait "morte" car token relu depuis disque au cycle suivant.

### #7 — Jitter `Get-Random` : cast int manquant

**Sévérité** : 🟡
**Fichier(s)** : `agent/windows/SambaEduAgent.ps1`

**Constat initial (Opus)** :
`Get-Random -Maximum` est borne exclusive. Avec des bornes double (résultat de `[Math]::Floor`), `Get-Random` tire un réel → le `+1` décale la moyenne de +0,5 s.

**Avis Fable** : Pertinence 1 — bug réel mais différent du raisonnement Opus. Corrigé par cast `[int]`.

**Correction appliquée** : `$jitterMax = [int][Math]::Floor(...)` pour tirage entier uniforme symétrique.

**Action** : ✅ corrigé automatiquement

### #8 — UUID SMBIOS vide/all-F non validé

**Sévérité** : 🟡
**Fichier(s)** : `agent/windows/SambaEduAgent.ps1`, `agent/shared/ContractV1.ps1`

**Constat initial (Opus)** :
Un firmware qui n'expose pas l'UUID retourne `FFFFFFFF-FFFF-FFFF-FFFF-FFFFFFFFFFFF` ou vide → spam `identity_mismatch` côté serveur.

**Avis Fable** : Pertinence 2 — et plus grave qu'Opus ne le disait : un UUID vide avec paramètre `Mandatory [string]` fait crasher `Build-Report` → cycle en échec permanent sur ces postes.

**Correction appliquée** : détection UUID vide/all-F/all-0 → WARNING local, envoi tel quel (champ déclaratif) ; `[AllowEmptyString()]` ajouté sur `$Uuid` dans `Build-Report`.

**Action** : ✅ corrigé automatiquement

### #10 — `sc.exe delete` asynchrone — "marked for deletion"

**Fichier(s)** : `agent/windows/Uninstall-SambaEduAgent.ps1`, `agent/windows/Install-SambaEduAgent.ps1`

**Constat initial (Opus)** :

**Correction appliquée** : poll 30 s après `sc.exe delete` dans `Uninstall` ; même poll dans le chemin de réinstallation de `Install` (remplace le `Start-Sleep 2` aveugle).

**Action** : ✅ corrigé automatiquement
