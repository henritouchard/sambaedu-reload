## Détail des problèmes

### #1 — Bug d'OS dans `wrapInterpreters` : bash wrappé en `os=WINDOWS`

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Gpo/Services/ApplicationScriptsAssembler.php:906-908, 913-923`

**Constat initial (review)** :
`wrapInterpreters()` détermine `$os` une seule fois à partir de `$info['os']`, puis l'applique au wrapping de TOUS les interpréteurs (`cmd` ET `bash`). Or `headerScripts()` (branche `else` lignes 333-351) populate **toujours** `header['bash']` avec un shebang `#!/bin/bash...` même quand `info.os === 'windows'`. Donc en mode wrapper activé pour un logon Windows, `texts['bash']` (non vide) serait enveloppé avec un wrapper Windows (`wrapper-cmd.blade.php` → `Invoke-RestMethod`), produisant un binaire incohérent (cmd autour d'un script bash). Le test `it_wraps_cmd_output_with_invoke_restmethod_when_flag_enabled` cache le bug en mockant la réponse — la combinaison réelle n'est jamais exercée.

**Solutions possibles** :
1. Dériver `$os` du nom d'interpréteur dans la boucle : `cmd → WINDOWS`, `bash → LINUX`. Supprimer la lecture de `$info['os']` pour cette projection.
2. Skip explicitement `bash` quand `$info['os'] === 'windows'` (mais introduit asymétrie).
3. Ajouter un test négatif qui vérifie la combinaison `os=windows + interpreter=bash` (wrapper appelé avec `ScriptExecutionOs::LINUX`).

**Action** : à corriger automatiquement (solution 1 = canonique).

### #2 — Test `it_returns_unwrapped_output_when_flag_disabled` incomplet vs parité bytes

**Sévérité** : 🟠 Important
**Fichier(s)** : `tests/Feature/Gpo/ApplicationsScriptsWrapperIntegrationTest.php:126-141`

**Constat initial** :
Le test vérifie seulement l'absence de `Invoke-RestMethod` / `curl -fsS -X POST` dans `out['cmd']`. Il n'assert pas la **parité bytes vs sortie non-wrappée** : si le wrapping est appelé puis désactivé via un comportement incorrect, ou si `$texts` est muté différemment, ce test pourrait passer sans détecter la régression. Ce filet contredit AC3.2 (« sortie identique iso-legacy »). Le mock `wrap()->never()` valide bien le no-op, mais ne couvre pas le chemin où `$wrapper = null` (DI absente).

**Solutions possibles** :
1. Snapshot la sortie sans wrapper, activer le flag à false, comparer `assertSame`.
2. Ajouter un cas où l'Assembler est construit sans wrapper DI (`new ApplicationScriptsAssembler(null, null)`) et flag false → ne doit pas appeler `app()`.

**Action** : à corriger automatiquement (solution 1).

### #3 — Flag config `sambaedu.scripts.logging.enabled` jamais déclaré

**Sévérité** : 🟠 Important
**Fichier(s)** : `config/sambaedu.php` (clé absente), `app/Gpo/Services/ApplicationScriptsAssembler.php:902`

**Constat initial** :
La clé `sambaedu.scripts.logging.enabled` est lue (default `false`), mais n'apparaît nulle part dans `config/sambaedu.php`. Aucune entrée racine `'scripts' => ['logging' => ['enabled' => env(...)]]` n'a été créée. Pour que Story 17.5 puisse la flipper via artisan ou que l'environnement la pilote (`SAMBAEDU_SCRIPTS_LOGGING_ENABLED`), elle doit être déclarée. Sans ça, `config:cache` n'embarquera jamais la valeur — fragile.

**Solutions possibles** :
1. Ajouter `'scripts' => ['logging' => ['enabled' => (bool) env('SAMBAEDU_SCRIPTS_LOGGING_ENABLED', false)]]` dans `config/sambaedu.php` + entrée `.env.example` correspondante.
2. Réserver à 17.5 (mais 17.2 introduit le lecteur de clé — incohérence pattern D3).

**Action** : à corriger automatiquement (solution 1, après confirmation question Henri #3).

### #4 — `putenv()` ne traverse pas le cache `env()` Laravel

**Sévérité** : 🟠 Important
**Fichier(s)** : `tests/Unit/Gpo/ApplicationScriptsAssemblerTest.php:401-405, 414-417`

**Constat initial** :
Le test utilise `putenv()` pour positionner les variables. En Laravel 11 + vlucas/phpdotenv mode `Immutable` par défaut : si la variable a été chargée au boot (depuis `.env`), `putenv()` n'a aucun effet, et `env()` retourne la valeur du cache. Si jamais chargée, `getenv()` la voit — mais comportement non garanti et fragile selon l'ordre d'exécution. Risque de tests instables / faux-verts.

**Solutions possibles** :
1. Utiliser `\Illuminate\Support\Env::getRepository()->set('SAMBAEDU_GLPI_URL', '...')` (ou `forceSet` en mode immutable) avec teardown `clear()`.
2. Repenser le test pour passer par `config()->set()` (testant uniquement la chaîne config, pas env) et un autre test isolé qui couvre le fallback env via `Env::getRepository`.

**Action** : à corriger automatiquement (solution 1).

### #7 — Normaliseur DOMAINSID redondant + lookahead inutile

**Sévérité** : 🟡 Mineur
**Fichier(s)** : `tests/Feature/Gpo/ApplicationsScriptsByteParityTest.php:62-63`

**Constat initial** :
Deux regex sont appliquées en chaîne :
```
'/SET DOMAINSID=S-1-5-21-[\d-]+/' → 'SET DOMAINSID=__SID__'
'/SET DOMAINSID=(?!__SID__)/'    → 'SET DOMAINSID=__SID__'
```
La 2e attrape **toute** occurrence non encore normalisée (y compris valeurs vides). La 1re est redondante puisque la 2e couvre tout. Code fragile.

**Solutions possibles** :
1. Une seule regex : `'/SET DOMAINSID=[^\r\n]*/' → 'SET DOMAINSID=__SID__'`. Simple, déterministe, no lookahead.

**Action** : à corriger automatiquement.
