### #8 — Trou AC12a : source WPKG système non synchronisée à l'update

**Sévérité** : 🟡 — **Pertinence Opus** : 1/3
**Fichier(s)** : `scripts/update.sh`, `database/seeders/DepotApplicationSeeder.php`

**Constat initial (Sonnet/Opus)** : aucun provisioning d'une source WPKG système. L'investigation a montré que toute la plomberie SE5 existe déjà (`depots` → `DepotSyncService` → `depot_applications` → install → `applications` → `WpkgBundleGenerator` → bundle Apache).

**Clarification Henri** : le lien `sambaedu-wpkg-xml` était une erreur ; la vraie source = `http://deb.sambaedu.org/wpkg/xml/packages.xml`, qui est **déjà le dépôt PRIMAIRE seedé** (`DepotApplicationSeeder`, `is_primary=true`). Donc « enregistrer le dépôt » est déjà fait. Seul manquait l'appel de synchronisation à l'update (`update.sh` n'invoquait jamais `appstore:sync` → dépôt enregistré mais jamais rafraîchi).

**Décision Henri** : option 1 — câbler une sync fail-soft + l'installation/marquage `required` des paquets reste une **opération admin supérieure** (explicitement acté).

**Action** : ✅ Corrigé — fonction `ensure_appstore_catalog_sync` ajoutée à `scripts/update.sh` (appelée dans `main()` après `ensure_appstore_write_dirs`), modelée sur `ensure_agent_required_tools` : check de présence de la commande, exécution sous `www-admin`, **fail-soft** (dépôt distant injoignable → `log_warning`, jamais d'échec d'update). Rafraîchit `depot_applications` depuis le dépôt primaire à chaque update. L'install + le marquage `is_parc_default` des paquets « système » obligatoires restent un geste admin ultérieur (hors code de provisioning).
