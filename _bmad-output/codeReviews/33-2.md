## Détail des problèmes

### #1 — Test de log sans garde `fail()`

**Sévérité** : 🟠 — **Pertinence Opus** : 2 (confirmé)
**Fichier(s)** : `tests/Feature/ControlHub/UnsupportedSchemaVersionRejectionTest.php:191-206`

**Constat initial (review)** : `test_rejection_is_logged_with_declared_and_supported` capture `UnsupportedSchemaVersionException` sans `fail()` après `ingest()`. Incohérent avec les autres tests du fichier. Une régression qui retirerait le `throw` ne casserait le test qu'indirectement (via `Log::shouldHaveReceived`).

**Avis Opus** : Réel mais impact pratique faible — le `withArgs` exige `context['supported']` (l'ancien repli loggait `'fallback'`), donc une régression complète échouerait quand même. Seule une régression partielle (warning conservé, throw retiré) passerait en faux-vert. Coût du `fail()` = nul.

**Action** : ✅ Corrigé — `$this->fail(...)` ajouté après `ingest()`.

### #2 — Ordre validation contenu-avant-version

**Sévérité** : 🟠 — **Pertinence Opus** : 2 (confirmé, va plus loin que sonnet)
**Fichier(s)** : `app/Services/ControlHub/ControlHubContractIngestionService.php:92-118`

**Constat initial (review)** : Les `normalizeX()` (lignes ~92-106) précèdent `negotiate()` (ligne ~118). Un payload doublement invalide retourne l'exception de contenu, pas de version → diagnostic trompeur (AC#5).

**Avis Opus** : Confirmé. Valider la VERSION avant le CONTENU est plus correct sémantiquement. Déplacement **sûr** (negotiate pur, zéro DB, aucun caller, pas de try/catch, tests verts). **Contre-argument** : non déclenchable avec une seule version supportée (la normalisation est la logique v1.0). Pertinent mais non urgent. Manque associé : aucun test ne caractérise l'ordre des causes.

**Solutions possibles** :
1. Déplacer l'extraction `schema_version` + `negotiate()` en tête de `ingest()`, avant les `normalizeX()`, + ajouter un test de caractérisation de l'ordre des causes.
2. Différer jusqu'à l'introduction d'une 2ᵉ version supportée (documenter la dette).

**Action** : ✅ Corrigé (décision utilisateur : appliquer maintenant). `negotiate()` déplacé en tête de `ingest()`, AVANT les `normalizeX()`. Test de caractérisation `test_version_is_validated_before_content` ajouté (un payload version-incompatible ET contenu-invalide lève bien l'exception de VERSION). Non-régression : 171/171 verts.

### #3 — Preuve d'immuabilité des enfants par décompte seul

### #5 — Fausse acceptation silencieuse d'un `schema_version` float

**Sévérité** : 🟡 (sonnet) → 🟠 (relevée) — **Pertinence Opus** : 2 (sous-coté par sonnet)
**Fichier(s)** : `app/Services/ControlHub/ControlHubContractIngestionService.php:114-117`

**Constat initial (review)** : Cast `is_string || is_int ? (string) : null`. Un `schema_version: 1` (int) → `'1'` rejeté ; mais un `schema_version: 2.0` (float JSON) n'est ni `is_int` ni `is_string` → `null` → accepté comme version courante par défaut. Asymétrie non testée.

**Avis Opus** : **Sous-coté.** Ce n'est pas qu'un trou de test mais un **trou de correction** : un float `2.0` est **silencieusement accepté** comme s'il était absent, alors qu'une version DÉCLARÉE incompatible doit être rejetée (AC#1). La direction de l'asymétrie est dangereuse (fausse ACCEPTATION, pas fausse alerte).

**Solutions possibles** :
1. Ajouter `is_float` au garde de cast : un float déclaré est coercé en string et négocié → rejeté (puisque ≠ `1.0` en égalité stricte).
2. Rejeter tout `schema_version` présent non coercible.

**Action** : ✅ Corrigé — `is_float` ajouté au cast (solution 1) ; tout `schema_version` numérique déclaré est désormais négocié (et rejeté s'il n'est pas exactement supporté). Tests float + int ajoutés. _Résiduel documenté_ : un `schema_version` non-scalaire (array/bool) reste traité comme absent — angle non flaggé, hors-scope 33.2.
