### #1 — Tests `GpoBackLinkComponentTest` probablement tous en 403

**Sévérité** : 🔴 Critique
**Fichier** : `tests/Feature/Gpo/GpoBackLinkComponentTest.php:55-60, 78-97, 103-123, 129-146, 152-170`

**Constat initial** :
Les 4 tests font `givePermissionTo('server.admin')` puis HTTP GET sur `/app/parc-settings/wallpapers...`. Or `wallpapers/index.blade.php:17-21` exige `wallpaper.manage` via `abort_unless(...->can('wallpaper.manage'), 403)`. Le trait `BootstrapsSpatieTables` ne seede que `server.admin`. Aucun `Gate::before` ni bypass admin. Conclusion : les tests retournent 403, pas 200. T5.2/T5.3 ont été punted "ACTION HENRI" sans validation → ces tests n'ont **jamais tourné vert**.

**Solutions possibles** :
1. `Gate::define('wallpaper.manage', fn() => true)` + `Gate::define('app.customize', fn() => true)` dans le `setUp()`
2. Seeder les permissions et les assigner au user de test dans `BootstrapsSpatieTables`
3. Tester le composant en isolation via `Blade::render('<x-molecules.gpo-back-link />')` (piège 6 de la story)

**Action** : ⏳ Décision Henri (Q1)

### #2 — Breadcrumb se vide après re-render Livewire

**Sévérité** : 🔴 Critique
**Fichier** : `resources/views/components/molecules/gpo-back-link.blade.php:14`

**Constat initial** :
`Request::query('from_gpo')` lit la query string de la **requête HTTP courante**. En Livewire 3, après tout `wire:click` ou `wire:model.live`, la requête devient `POST /livewire/update` SANS la query string d'origine. Conséquence : au premier GET le breadcrumb s'affiche, mais dès une interaction sur la page (filtre wallpapers, create, etc.), le composant re-rendu retourne `$guid = null` → breadcrumb disparaît silencieusement. Casse la promesse "préserve le contexte de navigation" (D4) et le scénario QA 3.5.

**Solutions possibles** :
1. Composant Blade stateless → passer `$guid` en prop depuis le parent qui le stocke en `#[Url(keep: true)] public ?string $from_gpo`
2. Utiliser `url()->previous()` pour récupérer le referrer (fragile)
3. Documenter explicitement la limitation et accepter (out-of-scope V2)

**Action** : ⏳ Décision Henri (Q2)

### #3 — `Request::query('from_gpo')` accepte un tableau

**Sévérité** : 🟠 Important
**Fichier** : `resources/views/components/molecules/gpo-back-link.blade.php:14, 21, 32`

**Constat initial** :
Si URL = `?from_gpo[]=foo&from_gpo[]=bar`, `Request::query('from_gpo')` retourne un `array`. Cast `(string) $guid` produit "Array" + warning PHP. Pas d'XSS (Blade échappe) mais comportement défensif manquant.

**Solution retenue** : Garde `is_string()` avant utilisation :
```php
$rawGuid = Request::query('from_gpo');
$guid = is_string($rawGuid) && $rawGuid !== '' ? $rawGuid : null;
```

**Action** : ✅ Corrigé automatiquement
