### #4 — Timezone non validée comme IANA valide

**Sévérité** : 🟠 → Pertinence Opus : **3/3 — SÉRIEUX**
**Fichier(s)** :
- `app/Http/Requests/Parc/StoreWorkstationGroupScheduleRequest.php:43`
- `app/Http/Requests/Parc/UpdateWorkstationGroupScheduleRequest.php` (mêmes règles)
- `resources/views/pages/parc/groups/[id]/index.blade.php:915` (validation inline)

**Constat initial** :
`['required', 'string', 'max:64']` laisse passer `"toto"`, `"UTC+2"`, `"Paris"`. `Carbon::parse(time, 'toto')` lève `InvalidTimeZoneException` → catch-all dans `executeDue` → tick skippé silencieusement pour CE schedule, invisible depuis l'UI.

**Avis Opus** :
Problème réel, correction simple. Test empirique : Laravel `timezone` (ou `timezone:all`) accepte `Europe/Paris`, rejette `Paris`, `toto`, `UTC+2`.

**Action** : ✅ **Corrigé** — règle `['required', 'timezone']` appliquée dans les deux FormRequests + validation Livewire `saveSchedule`.

### #5 — Index unique `(schedule_id, ran_for_date, ran_for_time)` cassé après `nullOnDelete`

**Sévérité** : 🟠 → Pertinence Opus : **2/3**
**Fichier(s)** : `database/migrations/2026_04_22_100002_create_workstation_group_schedule_runs_table.php:35-60`

**Constat initial** :
PostgreSQL considère `NULL != NULL` dans un UNIQUE classique. Après suppression d'un schedule → `schedule_id = NULL` pour les runs orphelins → doublons théoriques possibles.

**Avis Opus** :
Risque purement rétroactif (un schedule supprimé ne génère plus de runs). Garde `runAlreadyExists` du service filtre sur `schedule_id` non-null et empêche le flux nominal. Correction de doctrine (hygiène DB) à appliquer.

**Action** : ✅ **Corrigé** — index converti en partiel PostgreSQL `WHERE schedule_id IS NOT NULL` (avec fallback SQLite pour tests).

### #13 — Clone one-shot crée un placeholder `run_at=now+1h` qui fire tout seul (NOUVEAU)

**Sévérité** : 🔴 → Pertinence Opus : **3/3 — BUG PROD RÉEL**
**Fichier(s)** : `app/Services/Parc/WorkstationGroupScheduleService.php:210-215`

**Constat initial (Opus, non détecté par Sonnet)** :
`cloneOneShot()` crée immédiatement un schedule `enabled=true, run_at=now+1h` pour éviter la CHECK constraint. Si l'utilisateur clone puis **ne confirme pas** la nouvelle date (ferme modale, crash navigateur, rate la modale), le schedule placeholder fire **1h après** avec l'action du source → **exécution non sollicitée sur toutes les machines du groupe**.

**Avis Opus** :
Bug prod réel. La fenêtre d'attaque est de 1h pendant laquelle l'user doit avoir le réflexe de supprimer le clone s'il ne veut pas confirmer.

**Action** : ✅ **Corrigé** — `cloneOneShot()` crée maintenant le clone avec `enabled=false`. L'utilisateur doit explicitement activer le clone après l'avoir daté. Test #14 mis à jour en conséquence.

## Points forts (relevés par Sonnet)

1. **Architecture tick→enqueue→worker exemplaire** — commande artisan pure dispatcher (1 SELECT + N enqueue), aucun I/O réseau. Exactement comme D1 spécifié.
2. **Idempotence multi-couches robuste** — 4 couches (guard `exists()`, unique index DB, `withoutOverlapping(5)`, filtre 409 4.3) testées. Le `drift_seconds` dans `summary` post-downtime est un bonus de qualité.
3. **DST correctement géré** — pattern `Carbon::parse(time_of_day, timezone)->setDate(...)` évite le bug classique `"H:i"` sur `now()` UTC.
4. **Backward-compat `executeGroupMachinesAction`** — ajout `?string $initiatedBy = null` non-breaking. 58 tests 4.3 passent sans modification. Traçabilité `schedule:<id>` vs `user:<id>` opérationnelle.
5. **Cloning avec modale auto-ouverte** — `cloneOneShot()` ouvre directement la modale d'édition (couplé avec fix #13 = UX optimale).
