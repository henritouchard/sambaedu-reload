## Questions en attente

> Décisions de design à trancher par Henri avant clôture. Non bloquantes pour la
> mécanique livrée (29 tests verts), mais conditionnant l'UX et une dette latente.

1. **Bascule A→B d'un label libre (finding #3 / M1)** — un `<select>` à choix unique
   qui interdit le remplacement direct : si un groupe porte le label libre `A` et que
   le refnum choisit `B`, le service lève `alreadyLabeled` (« détachez d'abord »).
   Aujourd'hui : refus explicite + l'utilisateur doit sélectionner « Aucun », sauver,
   puis ré-assigner `B`. **Veut-on plutôt un remplacement direct** (auto-détacher `A`
   puis assigner `B` dans la même opération) ? Cela suppose aussi de trancher
   l'**atomicité** : envelopper `updateGroup()` + mapping de label dans une transaction
   unique, ou pré-valider l'assignabilité du label AVANT `updateGroup()` (sinon les
   autres champs sont committés même quand le label est refusé).

2. **Durcissement mass-assignment `controlhub_label` (finding #5)** — `controlhub_label`
   est dans `$fillable` de `WorkstationGroup`. Aucun chemin live ne l'expose
   (les composants curent leurs tableaux), mais `WorkstationGroupService::updateGroup(['controlhub_label'=>…])`
   contournerait le service de label. **On durcit maintenant** (allowlist dans
   `validateGroupData` ou retrait de `$fillable`) **ou on l'assume en dette documentée** ?

## Détail des problèmes

### #1 — Fausse erreur de toast (label réservé/dangling porté)

**Sévérité** : 🔴 — **Fichier(s)** : `resources/views/pages/parc/groups/[id]/edit/index.blade.php`, `app/Services/ControlHub/WorkstationGroupLabelService.php`

**Constat (review sonnet)** : `loadGroup()` met `controlhubLabel` = nom du label porté. Si ce label est `reserved` (norme dès 30.3) ou « dangling » (retiré du contrat par la réconciliation 28.2), `save()` route vers `assignLabel()` qui lève `reserved`/`unknown` APRÈS que `updateGroup()` a commité les autres champs → champs sauvés mais toast d'erreur + pas de redirect. Toute édition (même changer le nom) d'un groupe à label réservé échouait.

**Avis Opus** : pertinence **3**, bloquant réel et **atteignable dès aujourd'hui** (la réconciliation prune/recreate de 28.2, déjà live, peut transformer un `free` porté en `reserved` ou le supprimer sans attendre 30.3).

**Correctif appliqué** : le no-op idempotent `if ($group->controlhub_label === $labelName) return;` est remonté **tout en haut** de `assignLabel()`, avant la résolution du contrat et les checks unknown/reserved. Ré-affirmer le label déjà porté ne lève donc plus jamais d'erreur. Tests : `editing_a_group_holding_a_reserved_label_saves_other_fields_without_error` + variante `dangling`.

### #2 — `detachLabel()` ne valide pas le mode (bypass via requête forgée)

**Sévérité** : 🔴 — **Fichier(s)** : `app/Services/ControlHub/WorkstationGroupLabelService.php`

**Constat (review sonnet)** : un refnum autorisé peut forger `controlhubLabel=''` sur un groupe à label réservé → `save()` appelle `detachLabel()` qui n'effectue aucune vérification de mode → le label imposé par l'amont est effacé.

**Avis Opus** : pertinence **2**, réel. **MAIS le fix proposé par sonnet (guard `reservedLabelHeld` dans `save()`) est non robuste** : `reservedLabelHeld` est aussi une propriété publique forgeable et n'est pas recalculée au début de `save()`. Le garde-fou DOIT être côté service.

**Correctif appliqué** : `detachLabel()` résout le contrat actif et **refuse** (`LabelAssignmentException::reserved`) si le label porté est `reserved`. Défense en profondeur additionnelle : `#[Locked]` sur `reservedLabelHeld` / `freeLabelNames` / `hasActiveContract` (édition + création). Test : `detaching_a_reserved_label_is_refused_by_service`.

### #3 / M1 — Non-atomicité + bascule A→B

**Sévérité** : 🟠 — **Fichier(s)** : `resources/views/pages/parc/groups/[id]/edit/index.blade.php`

**Constat** : `updateGroup()` et le service de label sont dans deux transactions distinctes ; un échec du second laisse les autres champs committés. M1 (manqué par sonnet, confirmé Opus) : changer un label libre `A` pour `B` lève `alreadyLabeled` — un `<select>` à choix unique qui interdit le remplacement, geste utilisateur naturel.

**Avis Opus** : pertinence **2**. Le correctif de #1 (no-op en tête) supprime le cas « édition sans changer le label », mais **PAS** le cas A→B actif. C'est un choix de design (remplacement vs refus + affordance UI) + une stratégie d'atomicité.

**Action** : ⏳ **Décision Henri (Q1)** — non corrigé automatiquement (plusieurs solutions valides, impact UX).
