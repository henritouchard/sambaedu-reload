## Détail des problèmes

### #1 — Composant Livewire sans root element
**Sévérité** : 🟠 — **Fichier** : `resources/views/components/organisms/install-log-modal.blade.php:92-250`

Livewire impose un seul élément racine au render. Quand `$visible=false` (état initial), le `@if ($visible) ... @endif` enrobe TOUT — le template ne rend rien. En `APP_DEBUG=true`, la détection multi-root crashe ; en prod le morphing perd son ancrage (boutons fantômes après plusieurs cycles).

**Solution appliquée** : `<div>` racine permanent qui enveloppe le `@if ($visible)`. Pattern identique à `shortcut-assignment-modal.blade.php`.

---

### #2 — Double requête DB par cycle de render
**Sévérité** : 🟠 — **Fichier** : `install-log-modal.blade.php:33,95`

`WorkstationApplicationStatus::find($statusId)->with(...)` exécuté dans `open()` puis re-exécuté à chaque render dans le bloc `@php` du template. Chaque interaction (Copier, close...) → +1 SELECT JOIN.

**Solution appliquée** : hydratation de toutes les métadonnées (`wstName`, `appName`, `statusLabel`, `statusBadge`, `installedVersion`, `reportedAt`, `rebootRequired`) en propriétés publiques Livewire au moment de `open()`. Plus de `find()` côté template.

---

### #3 — Cache empoisonné sur erreur transitoire
**Sévérité** : 🟠 — **Fichier** : `app/Services/Windows/WorkstationLogReader.php:80-103`

`Cache::remember()` cache aussi les `content => null` (race entre `file_exists` et `fopen`). 60s d'unavailability injustifiée si le fichier redevient lisible.

**Solution appliquée** : remplacement par `Cache::get()` + `Cache::put()` conditionnel (uniquement si `content !== null`).

---

### #4 — Path traversal interne accepté
**Sévérité** : 🟠 — **Fichier** : `WorkstationLogReader.php:34-39`

`basename('foo/../../../bar.log')` retourne `'bar.log'` qui passe les couches 1-4. Le mur final est uniquement la couche 5 (containment realpath). Si demain quelqu'un retire la couche 5 « car redondante », le mur tombe.

**Solution appliquée** : regex `^[A-Za-z0-9._-]+\.log$` après basename. Test dédié `it_rejects_basename_with_internal_traversal`.

---

### #5 — Injection service — PHPDoc manquant
**Sévérité** : 🟡 — **Fichier** : `install-log-modal.blade.php:13`

Propriété privée `$logReader` injectée via `boot()`. Fonctionne en Livewire v3 mais fragile si refactor futur déplace l'usage avant `boot()`.

**Action** : En attente — décider entre PHPDoc `@var ... injecté via boot()` ou bascule à `app(WorkstationLogReader::class)` à l'usage.

---

### #6 — Test cache ne prouve pas le HIT
**Sévérité** : 🟡 — **Fichier** : `tests/Unit/Services/WorkstationLogReaderTest.php:278-290`

Le test lit 2x le même fichier sans modif → même contenu, que le cache marche ou pas. Aucune assertion sur la mise en cache effective.

**Solution appliquée** : remplacement par `Cache::shouldReceive(...)` strict, ou alternative — réécriture du fichier sans changer mtime (`touch -t`) et vérification que la lecture renvoie l'ancien contenu (preuve de cache HIT).

---

### #7 — CP850 non garanti sur toutes les builds mbstring
**Sévérité** : 🟡 — **Fichier** : `WorkstationLogReader.php:139`

`mb_convert_encoding(..., 'UTF-8', 'CP850')` peut lever `ValueError` (PHP 8.1+) si mbstring est compilé sans CP850 (Alpine slim, distroless).

**Solution appliquée** : guard `in_array('CP850', mb_list_encodings(), true)` + fallback Windows-1252 (très proche pour les caractères latins). Test ajouté.

---

### #8 — Race `filemtime` → cache `:0`
**Sévérité** : 🟡 (résolu indirectement par #3)

Si le fichier disparaît entre `file_exists` et `filemtime`, mtime = 0 → cache empoisonné. Couvert par la correction #3 (on ne cache plus les null).

## Points positifs

1. **Sécurité path traversal multi-couches sérieuse** — basename + suffixe `.log` + null byte + base dir non-vide/non-`/` + realpath + containment via `str_starts_with($realResolved, $realBase . DIRECTORY_SEPARATOR)`. Le `DIRECTORY_SEPARATOR` final évite le bug classique `/var/log/foo` ⊂ `/var/logfoo-evil`.
2. **Encodage CP850 documenté et testé avec les vrais octets** (`\x82`, `\x88`) — commentaire de classe explicite, détection BOM UTF-16/UTF-8 avant fallback CP850. Aucune compromission silencieuse.
3. **Suppression complète et propre des anciennes méthodes** `openDeploymentModal`/`closeDeploymentModal`/`getDeploymentModalStatusProperty` et des anciens `<dialog>` inline sur les 2 pages. Migration cohérente vers `<livewire:components::organisms.install-log-modal />` avec `wire:click="$dispatch('open-install-log-modal', { statusId: ... })"`.
