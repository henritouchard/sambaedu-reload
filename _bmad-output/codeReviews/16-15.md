## Détail des problèmes

### #1 — Test bi-compat AC7.6 cassé en testing

**Sévérité** : 🔴 Critique
**Fichier(s)** : `tests/Feature/Gpo/AppContextChainTest.php:86-115` + `phpunit.xml:34`

**Constat (review)** :
`phpunit.xml:34` force `APP_CONTEXT_CACHE_DRIVER=array`. Le test bi-compat appelle `CacheAppContextWriter::write()` qui pose dans le store `array` (mémoire process), PAS dans APCu. Le test fait ensuite `apcu_fetch('apps.'.$id)` direct qui retourne `false`. Sur VM avec `apc.enable_cli=1`, le test n'est pas skippé → assertion échoue.

**Solution** :
- (Option A) Override explicite : `config()->set('cache.stores.app_context.driver', 'apc')` + `$this->app->forgetInstance('cache')` AVANT chaque exécution
- (Option B) Garde supplémentaire : `markTestSkipped` aussi si `config('cache.stores.app_context.driver') !== 'apc'`

**Action** : ⏳ Attente décision Q4. Option B = défaut conservateur (skip propre, pas de force driver). Option A = couverture réelle mais plus invasif.

### #3 — Dégradation gracieuse APCu absent : promesse AC3.3 fausse

**Sévérité** : 🟠 Important
**Fichier(s)** : `app/Services/AppCustomization/CacheAppContextWriter.php:81-88`, story AC3.3

**Constat (review)** :
Story AC3.3 affirme « Cache facade dégrade gracieusement nativement ». **Faux pour `apc` non chargé** : Laravel `CacheManager::createApcDriver` instancie `new ApcStore(new ApcWrapper, …)`. Au premier `put`/`get`, `apcu_store`/`apcu_fetch` est appelé sans guard `function_exists`. Si l'extension n'est pas chargée → `Error: Call to undefined function apcu_store()` fatal.

**Impact** :
En prod sans APCu chargé, l'endpoint `/gpo/applications.php` passe à 500 au lieu de mode dégradé. La méthode `apcuAvailable()` supprimée (AC3.2) avait cette protection.

**Solution** :
- (Option A) try/catch \Throwable autour des appels Cache writer (log warning + continue)
- (Option B) Documenter que prod DOIT avoir APCu (et la « dégradation gracieuse » n'est plus une feature)

**Action** : ⏳ Attente décision Q1.

### #6 — `fetchCached` perd la garde md5

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Gpo/Services/ApplicationScriptsGenerator.php:322-329`

**Constat (review)** :
```php
private function fetchCached(string $id): ?array
{
    $payload = Cache::store('app_context')->get('apps.' . $id);
    ...
}
```
Aucune garde md5. Story AC6.1 dit « Garde md5 + retour `null` si payload non array préservés » → garde **manquante**. `CacheAppContextRepository:32` l'a bien.

**Solution** :
Restaurer la garde en tête : `if ($id === '' || ! preg_match('/^[a-f0-9]{32}$/i', $id)) { return null; }`

**Action** : ✅ À corriger automatiquement (bug clair, AC6.1 explicite).

### #10 — Driver fallback : `CACHE_DRIVER=file` casse store `app_context`

**Sévérité** : 🟡 Mineur
**Fichier(s)** : `config/cache.php:48`

**Constat (review)** :
Chain : `APP_CONTEXT_CACHE_DRIVER → CACHE_DRIVER → 'apc'`. Si `CACHE_DRIVER=file` et `APP_CONTEXT_CACHE_DRIVER` non défini → store `app_context` devient `file` (round-trip FS = exactement le risque listé au cadrage).

**Solution** :
Forcer `'driver' => env('APP_CONTEXT_CACHE_DRIVER', 'apc')` en court-circuitant `CACHE_DRIVER` (ne tombe sur `apc` que via l'env dédié ou le défaut hardcodé).

**Action** : ✅ À corriger automatiquement (sécurité par défaut renforcée).
