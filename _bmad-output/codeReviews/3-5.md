## Détail des problèmes

### #1 — URL `action.php` legacy dans template `unattend.xml`

**Sévérité** : 🔴 Critique
**Fichier(s)** : `resources/ipxe/windows/unattend.xml:112`

**Constat initial (sonnet)** :
Le template XML copié depuis le legacy contient :
```xml
<CommandLine>%comspec% /c curl -sL --retry 20 --retry-max-time 300 --fail -F "etape=oobe" -F "name=###_NAME_###" -o "%windir%\action.cmd" "http://###_SE4FS_NAME_###/ipxe/Win10/action.php"</CommandLine>
```
L'URL cible est `ipxe/Win10/action.php` (endpoint legacy PHP). La story 3.5 a créé un endpoint natif `GET|POST /ipxe/windows/action` géré par `IpxeWindowsActionController`.

**Avis Opus** : confirmé (pertinence 3). Le hook OOBE post-installation pointe vers le legacy. En SE5-only sans les fichiers `.php` déployés, la requête OOBE tombe en 404 → `WindowsPostInstallTracker::recordOobeComplete()` jamais appelé → `workstation.os` reste NULL, `status` reste `'installation WinPE'` indéfiniment. Même bug critique que 3.4 finding #1.

**Solutions possibles** :
1. Remplacer dans le template XML : `/ipxe/Win10/action.php` → `/ipxe/windows/action`
2. Ajouter un test feature `it_renders_native_action_url_not_legacy_php` asserting que le XML servi contient `/ipxe/windows/action` et ne contient pas `Win10/action.php`

**Action** : ✅ correction automatique sûre (orchestrateur)

### #3 — Credentials injectés sans passer par `WindowsXmlPlaceholders::sanitize()`

**Sévérité initiale** : 🟠 Important → **Sévérité finale** : 🟡 Mineur (rétrogradé opus)
**Fichier(s)** : `app/Ipxe/Services/WindowsUnattendBuilder.php` (lignes ~274-400)

**Constat initial (sonnet)** :
Spec D6 dit : *"Toutes les valeurs passent par `WindowsXmlPlaceholders::sanitize($value)` avant injection dans le DOM."* Or les credentials (`adminse_passwd`, `adminse_name`, `domain`, `win_user`, `win_user_passwd`, `win_key`, `se4install_*`) sont passés directement à `setNodeValue()` sans sanitize préalable.

**Avis Opus** (pertinence 1) :
- `setNodeValue()` utilise `textContent =` de DOMDocument qui escape NATIVEMENT les caractères XML (`<`, `>`, `&`, `'`, `"`)
- `IpxeHostnameSanitizer::sanitizeForIpxeOutput()` est appliqué sur `$name` (workstation) — couche additionnelle
- Les credentials viennent de `config('sambaedu.*')` = trust boundary (admin contrôle)
- L'absence de `sanitize()` est de la défense en profondeur manquante mais pas une faille exploitable

**Solutions possibles** :
1. Wrapper chaque credential : `$this->setNodeValue($node, WindowsXmlPlaceholders::sanitize($autoLogonPasswd));`
2. Documenter : la sanitize XML native DOMDocument est suffisante pour le périmètre 3.5 (config trustée + hostname déjà sanitizé) — laisser tel quel

**Action** : ⏳ question user (refactor ou doc-only)

### #N1 — `getAdOu()` n'existe pas → toujours fallback `CN=Computers`
