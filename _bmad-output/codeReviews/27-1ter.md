## Détail des problèmes

### #1 — Idempotence per-user survendue
**Sévérité** 🟠 · **Fichier** `agent/shared/rainmeter.go`
**Constat (opus)** : en prod Rainmeter écrit ses settings dans le `.ini` ; au logon suivant il diverge du durci → réécriture systématique. Le test d'idempotence porte sur un fichier jamais touché par Rainmeter (non représentatif).
**Évaluation orchestrateur** : pertinence 1. Le comportement (réécriture à chaque logon) est **correct et voulu** (D5 : réimposition). C'est un point d'honnêteté de doc, pas un bug. L'écriture précède le lancement de Rainmeter → aucun conflit.
**Action** : ✅ commentaire ajouté sur `WriteUserRainmeterIni` clarifiant que le no-op ne vaut qu'avant consommation par Rainmeter ; en régime établi la réécriture est la norme (D5).

### #2 — Suppression `.ini` racine + test d'extraction manquant
**Sévérité** 🟠 · **Fichier** `agent/shared/rainmeter_provision.go`, `rainmeter_provision_test.go`
**Constat (opus)** : la suppression cible le seul `.ini` racine ; aucun test n'extrait un vrai portable embarquant un `.ini`.
**Évaluation orchestrateur** : pertinence 2. Cibler le `.ini` racine est **fonctionnellement suffisant** (seul celui aux côtés de l'exe force le mode portable). Le gap réel = test.
**Action** : ✅ `portableFixture` embarque désormais un `Rainmeter.ini` à la racine ; l'assertion existante (`SettingsPath()` absent après `SyncRainmeterTool`) prouve maintenant la suppression de bout en bout (zip → extraction → absence).

### #3 — Fenêtre de course extraction→suppression
**Sévérité** 🟠 · **Fichier** `agent/shared/rainmeter_provision.go`
**Constat (opus)** : entre la bascule de l'arbre extrait (qui pose le `.ini` portable) et sa suppression par `ensureRainmeterConfig`, un `Rainmeter.exe` lancé verrait son `.ini` voisin → mode portable → modale.
**Évaluation orchestrateur** : pertinence 2. Fenêtre réelle quoique rare (re-provisioning mid-session). Fix propre disponible.
**Action** : ✅ `extractRainmeterAtomic` retire le `Rainmeter.ini` **dans le temporaire, avant la bascule** → l'arbre définitif ne reçoit jamais de `.ini` racine (fresh install : fenêtre éliminée). La suppression idempotente d'`ensureRainmeterConfig` est conservée pour l'upgrade d'une install antérieure.

### #4 — `.tmp` orphelin sur crash
**Sévérité** 🟡 · **Évaluation** : pertinence 0. Pattern `WriteFileAtomic` existant partout ; pas de régression ; `.tmp` non chargé par Rainmeter ; dossier auto-nettoyable par l'user. **Action** : ❌ ignoré.

### #5 — Assertion test SkinPath creuse
**Sévérité** 🟡 · **Fichier** `agent/shared/rainmeter_test.go`
**Constat (opus)** : l'assertion `HasPrefix(SkinsDir(), DefaultRainmeterRoot)` ne compare pas le SkinPath émis au store (et masque la divergence de séparateur `\` vs `/`).
**Évaluation orchestrateur** : pertinence 2. Assertion sans valeur probante.
**Action** : ✅ remplacée par une comparaison normalisée (`\`→`/`, slash terminal retiré) entre le SkinPath émis et `prodStore.SkinsDir()` — vraie vérification de cohérence.

### #6 — README obsolète
**Sévérité** 🟡 · **Fichier** `agent/README.md:300-305`
**Constat (opus)** : décrit toujours le `.ini` durci posé sous ProgramData ACL Users:R.
**Évaluation orchestrateur** : pertinence 2. Doc contradictoire avec le code livré.
**Action** : ✅ paragraphe réécrit (mode installé, `.ini` en `%APPDATA%` writable posé par le compagnon, `SkinPath` vers skins ProgramData RX, suppression du résiduel).

### #7 — Test d'ordre trivial
**Sévérité** 🟡 · **Évaluation** : pertinence 1. Le test garde l'invariant d'ordre (`.ini` avant launch) contre un futur réordonnancement — valeur faible mais non nulle. **Action** : ❌ gardé tel quel.
