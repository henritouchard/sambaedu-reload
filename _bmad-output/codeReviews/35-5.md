## Détail des problèmes

### #1 — Dépassement varchar(255) sur `capabilities.description`

**Sévérité** : 🔴 | **Pertinence** : 3 (vérifiée : 275 caractères, colonne `$table->string()` = varchar(255) PG ; piège connu « Tests SQLite — varchar non appliqué »)
**Fichier(s)** : `database/migrations/2026_07_03_130000_seed_capability_photo_viewer_restored.php`

**Solution appliquée** : description raccourcie (~210 caractères) — la nuance « ne choisit pas l'app par extension » vit dans la story + runbook QA, pas dans le tooltip. Test STRUCTUREL ajouté (`all_seeded_capability_strings_fit_their_postgres_varchar_columns`) : label/description/category ≤ 255 pour TOUTES les capacités seedées, présentes et futures — généralise la protection (recommandation fast-follow de la review, faite immédiatement).

### #2 — Parc-defaults éditable pour une capacité inactive

**Sévérité** : 🟠 | **Pertinence** : 2 (vérifiée : `openEdit()`/`saveDefault()` ne gardaient que admin + verrou amont ; `photo_viewer_restored` est la PREMIÈRE capacité `is_active=false` en base — trou pré-existant devenu atteignable)
**Fichier(s)** : `resources/views/pages/admin/settings/parc-defaults/_partials/registry-tab.blade.php`

**Solution appliquée** : garde serveur `is_active` dans `openEdit()` ET `saveDefault()` (defense-in-depth, toast explicite) + bouton `@disabled` avec tooltip. Test dédié `ParcDefaultsInactiveCapabilityTest` (3 cas : openEdit refusé, saveDefault refusé en contournement UI, non-régression capacité active).

### #3 — Description de gate figée vs flip

**Sévérité** : 🟡 | **Pertinence** : 2
**Fichier(s)** : docblock de la migration de seed

**Solution appliquée** : note ajoutée au docblock — la migration de flip doit AUSSI réécrire `description`. L'orchestrateur (qui écrit la migration de flip à l'intégration de la vague 2, après preuve du support `name=""` par la 35.2) l'implémentera ainsi.
