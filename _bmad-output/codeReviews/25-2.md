## Détail des problèmes

### #1 — Mécanique de restart in-process structurellement cassée (BLOQUANT)

**Sévérité** : 🔴
**Fichier(s)** : `agent/windows/update_windows.go` (`restartService` ~l.159-194, `swapAndRestart`), `agent/windows/service_windows.go`, `agent/windows/install_windows.go:88-97`

**Constat initial (sonnet)** :
`SelfUpdate` est appelée depuis la goroutine `agent.Run()`. `restartService` envoie `svc.Stop` puis attend 20s que le service soit `Stopped` avant `s.Start()`. Mais le service ne peut pas atteindre `Stopped` tant que `RunCycle`/`Run` n'a pas rendu la main → la boucle d'attente expire → `s.Start()` échoue sur `StopPending` → faux échec rapporté. Le service termine ensuite gracieusement (`return false, 0`), et la recovery SCM (configurée « arrêt anormal uniquement », sans `SetRecoveryActionsOnNonCrashFailures`) ne se déclenche pas. Après un swap réussi, l'agent ne redémarre pas avant le prochain boot.

**Avis Opus (3/3)** :
Confirmé et **plus grave** : deadlock déterministe. Chaîne tracée — `Run`(goroutine)→`RunCycle`→`SelfUpdate`(loop.go:209)→`SwapAndRestart` synchrone→`restartService`. `cancel()` est appelé par `Execute` mais `Run` n'observe `ctx.Done()` qu'après le retour de `RunCycle`, lui-même bloqué dans la boucle d'attente → `done` ne se ferme jamais. `restartService` attend 20s, `Execute` libère à 30s : `s.Start()` est tenté à T+20s sur `StopPending` → échec. À T+30s arrêt gracieux → recovery SCM non déclenchée (le commentaire `install_windows.go:88-90` confirme « un ARRÊT PROPRE n'est pas relancé »). Le bug est **indépendant des timings** : stop+start in-process depuis le process qu'on arrête est intrinsèquement cassé. Violation directe de l'AC2. Aggravé par M5 : `shared.Version` reste vN → divergence permanente → re-download + re-swap + faux échec en boucle.

**Solutions possibles** :
1. (A) Après swap réussi, `os.Exit(≠0)` → recovery SCM relance avec vN+1.
2. (B) Process tiers détaché (`sc stop && sc start` / `updater.exe`).
3. (C) Tâche planifiée one-shot.

**Action** : en attente de décision utilisateur (A/B/C). Le rework de P1 conditionne P6, M1, M2, M5, M6 (tous dans `windows/` ou la frontière swap/tests).

### #2 — Fail-open de la 2e porte de sécurité

**Sévérité** : 🟠
**Fichier(s)** : `agent/shared/update.go:145`

**Constat initial (sonnet)** : `if a.VerifyAuthenticode != nil` — si la primitive est nil mais `SwapAndRestart` non-nil, le flux atteint le swap sans vérif signature (hash serveur seul).

**Avis Opus (2/3)** : Confirmé. En pratique câblé ensemble dans `main_windows.go:157-158`, donc pas de trou en prod ; risque = régression future. Pour une story « sécurité fail-safe », une porte qui dépend d'un `!= nil` plutôt que d'un échec dur est une faiblesse réelle.

**Action** : **corrigé automatiquement** — fail-closed : si `SwapAndRestart != nil && VerifyAuthenticode == nil`, refus de swap (log + `pendingUpdateError`), pas de skip de la vérif.

### #4 — Troncature UTF-8 byte-unsafe

**Sévérité** : 🟡
**Fichier(s)** : `agent/shared/update.go` (`truncateDetail`)

**Constat initial (sonnet)** : `s[:max]` coupe à l'octet → séquence UTF-8 cassée sur messages FR accentués.

**Avis Opus (2/3)** : Confirmé. `json.Encoder` remplace par U+FFFD (pas de crash), mais glyphe parasite ; aucun test ne couvre une troncature accentuée. À soigner pour une story « la plus testée ».

**Action** : **corrigé automatiquement** — troncature sur frontière de rune (`[]rune`).

### #5 — Re-download complet à chaque cycle

**Sévérité** : 🟡
**Fichier(s)** : `agent/shared/update.go` (`SelfUpdate`)

**Constat initial (sonnet)** : pas de skip si le binaire stagé est déjà présent/valide → re-download ~7 Mo à chaque `ttl_seconds` pour un parc bloqué sur signature invalide.

**Avis Opus (2/3)** : Confirmé, incohérent avec `SyncWallpaperAssets` (assets.go:113-120, stat+skip content-addressed). Amplifié par P1/M5 (re-download permanent sur tout poste ayant swappé).

**Action** : **corrigé automatiquement** — avant download, si `stagedPath` existe et son SHA-256 == `manifest.Hash`, sauter le download (iso `SyncWallpaperAssets`).
