## Détail des problèmes

### #1 — Index incohérent : test stagé contredit le code stagé

**Sévérité** : 🔴 → ✅ Corrigé
**Fichier(s)** : `tests/Unit/Services/UserGroupServiceLegacyCompatibilityTest.php`

**Constat (review opus, vérifié par l'orchestrateur)** : le fichier de test était `MM` (staged + unstaged divergents, 66+/61-). La version **stagée** assertait l'ancien comportement STRICT (`assertSame(['3A','equipe_3a','pp_3a'])`, `pp_3a`→`custom`), la version **working tree** le nouveau comportement casse-insensible (1 ligne `3a` type `classe`, bob PP). Le « 40/40 vert » du dev avait été obtenu sur le working tree. Le test a été modifié **après** le `git add` initial → signe d'activité concurrente sur le working tree (cf. aussi la feature non liée « members-tabs » apparue en cours de session).

**Correctif appliqué** : `git add` de la version working tree cohérente. Index re-vérifié (`M ` propre), tests relancés sur l'état réel : `UserGroupServiceLegacyCompatibilityTest` 40/40, non-régression 40/40.

### #2 — Scope creep : 3 helpers rendus casse-insensible hors File List

**Sévérité** : 🔴
**Fichier(s)** : `app/Services/UserGroupService.php` — `foldPrefixOf` (l.831), `stripClasseLikePrefix` (l.1033), `detectTypeFromAdGroupName` (l.1173)

**Constat** : 6 comparaisons `str_starts_with` → `strncasecmp`. Ces helpers servent TOUT le chemin `syncFromAd` (import global, create/delete, syncGroupsWithAd), pas seulement `updateGroup`. Changement comportemental large présenté comme un refactor d'une ligne ; absent du File List de la story.

**Action** : ⏳ Q1 — décision de cadrage. Recommandation review (et orchestrateur) : **accepter dans 4.16 + corriger File List/spec** (le changement est indissociable, cf. #3).

### #3 — Changement de casse nécessaire mais corrige un bug pré-existant plus large

**Sévérité** : 🟠 → nécessité confirmée
**Constat (tracé)** : `updateGroup` passe `$lookupName='3a'` à `onlyGroupNames`. Pour le CN AD réel `classe_3a`, l'ANCIEN `foldPrefixOf` (`str_starts_with($cn,'Classe_')`) renvoyait `null` → CN exclu du filtre → read-back scopé = no-op → lookup post-sync lèverait `RuntimeException`. Donc scoper `updateGroup` **sans** le fix casse aurait **cassé l'édition de groupe sur le parc réel** (AD lowercase, cf. mémoire `project_vm_ad_junk_classe_groups`). Le bug de casse pré-existait sur le chemin global (mal-fold + mal-type des CN minuscules) ; 4.16 le rend bloquant (le mode scopé n'a pas le filet `whereNotIn`).

**Action** : ✅ Légitime et indissociable. Trou de spec : la story aurait dû imposer le cas AD lowercase dès le départ → corrigé via Q1.

### #4 — Casse traitée de façon incohérente

**Sévérité** : 🟠
**Fichier(s)** : `app/Services/UserGroupService.php:1015` (`guardReservedPrefixOnCreate`), `:1128` (`resolvePrimaryGroupName`, branche `matiere_classe`)

**Constat** : ces 2 comparaisons restent `str_starts_with` après le passage casse-insensible des helpers de fold. Elles opèrent sur l'entrée **utilisateur** (rawName du form create), pas des CN AD → risque moindre, mais un nom NU `classe_x` (minuscule) ne serait pas bloqué par le garde-fou (expansion fantôme `Classe_classe_x`), et `matiere_x@y` minuscule produirait `Matiere_matiere_x@y`.

**Action** : ⏳ Q2 — harmoniser (avec test) ou documenter le choix strict-case sur la saisie UI.

### #5 — Pas de test du read-back scopé sur AD lowercase (chemin `updateGroup`)

**Sévérité** : 🟠

Le seul motif qui rend le fix de casse nécessaire (AD lowercase) n'a aucune couverture **sur le chemin scopé d'`updateGroup`** (les tests lowercase/mixte exercent l'import global). Une régression réintroduisant `str_starts_with` dans le filtre resterait verte.

**Action** : ⏳ Auto-corrigeable après Q1 — ajouter `it_scopes_read_back_to_edited_group_on_update_with_lowercase_ad_cns`.

### #6 — Doc QA §10 en CN canoniques

**Sévérité** : 🟡

### #7 — Scopage `onlyGroupNames` asservi indirectement

**Sévérité** : 🟡 → ✅ accepté
**Constat** : AC4 (`it_does_not_purge_out_of_scope_groups_on_update`) prouve par effet que `whereNotIn` n'a pas tourné = preuve forte du mode scopé. AC1 (argument exact) non asservie directement. Acceptable (l'effet vaut preuve).

### #8 — `name` foldé non déterministe en casse mixte

**Sévérité** : 🟡
**Constat** : `buildFoldedGroups` projette `name = base` du 1er CN rencontré (suffixe casse d'origine), clé fold = `mb_strtolower`. En casse mixte (`Classe_3A`+`equipe_3a`), le `name` SQL peut « clignoter » `3A`/`3a` selon l'ordre AD. `LOWER(name)` neutralise le lookup → OK fonctionnellement, affichage UI varie. Aggravé par le fix casse mais hors scope strict.

**Action** : ⏳ Q3 — canonicaliser ou follow-up.
