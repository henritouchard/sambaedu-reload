## Questions en attente

> Questions nécessitant une décision de l'utilisateur (non bloquantes — défauts appliqués).

1. **Formulation des messages "déjà activé/désactivé" (problèmes #3 + S2)** — Le message d'idempotence est calculé depuis `config('sambaedu.scripts.logging.enabled')` (état vu par le process), pas depuis la valeur réelle sur disque. Si le `.env` a été édité à la main sans `config:clear`, ou si la config est cachée, le message peut diverger de la réalité disque (le flag écrit reste correct). De même, si `config:clear` échoue, le warning "cache vidé" reste affiché. **Défaut appliqué : laissé tel quel** (la config est précisément la source que l'Assembler 17.2 consomme). Veux-tu reformuler en "flag positionné à X" pour éviter toute affirmation sur l'état antérieur ?

2. **Atomicité de l'écriture `.env` (problème #7)** — `File::put()` n'est pas atomique. Le pattern write-tmp-then-rename a été **volontairement écarté** : risque I/O quasi nul en LAN mono-serveur, incohérent avec le style projet (`key:generate`, `ClearAllCaches` utilisent `File::put` direct), et — surtout — `rename()` crée un nouvel inode qui **casserait la préservation de l'ownership `www-admin`** (uid 599) actuellement garantie par l'écriture in-place (cf. S1). Confirmer que ce choix (in-place, non atomique) convient.

## Détail des problèmes

### #1 — `preg_replace()` peut retourner `null` → `.env` vidé silencieusement

**Sévérité** : 🔴 Critique
**Fichier(s)** : `app/Console/Commands/Concerns/ManagesScriptLoggingFlag.php`

**Constat initial (review Sonnet)** :
`preg_replace()` retourne `null` en cas d'erreur PCRE (backtrack limit, etc.). Le code faisait ensuite `File::put($path, (string) $contents)` avec `(string) null === ''` → `.env` effacé en entier, sans exception, avec message de succès. Perte du fichier de config.

**Avis Opus (pertinence 2)** :
Bug réel confirmé (`(string) null === ''` testé). MAIS sur un `.env` (quelques dizaines de lignes courtes, regex sans backtracking catastrophique car `.` ne traverse pas `\n` sans flag `s`), `PREG_BACKTRACK_LIMIT_ERROR` est en pratique inatteignable → probabilité réelle quasi nulle. Le sous-argument de la review « faux positif sur préfixe partagé `..._EXTRA` » est **faux** : `preg_quote` est présent et le pattern exige `=` immédiatement après la clé (testé → 0 match). Reste un garde-fou défensif trivial et sain.

**Action** : ✅ **Corrigé automatiquement**. Ajout de `if ($replaced === null) { Log::error(...); return false; }` avant l'écriture (le caller retourne alors `Command::FAILURE`). Suppression du cast `(string)` devenu inutile.

### #2 — CRLF : la ligne modifiée perd son `\r`

**Sévérité** : 🟠 Important
**Fichier(s)** : `app/Console/Commands/Concerns/ManagesScriptLoggingFlag.php`

**Constat initial (review Sonnet)** :
Sur un `.env` en `\r\n`, le mode `m` fait que le match `^KEY=.*$` consomme le `\r` (`.` matche `\r`) puis `$` matche avant `\n` → le remplacement perd le `\r`, créant un fichier à terminateurs mixtes (violation AC2.2 "byte-pour-byte").

**Avis Opus (pertinence 2)** :
Reproduit factuellement. Sévérité réelle faible (un `.env` Laravel sur VM Linux est quasi systématiquement en LF ; dotenv tolère les deux), mais c'est une vraie entorse littérale à l'AC2.2. Fix simple et non ambigu.

**Action** : ✅ **Corrigé automatiquement**. Bascule du pattern de `=.*$` vers `=[^\r\n]*` (sans ancre `$`) : `[^\r\n]*` borne le match à la valeur **sans consommer le terminateur de ligne**, qui est donc préservé byte-pour-byte (LF comme CRLF). Test dédié `preserves_crlf_line_endings_on_replacement` ajouté (vert sur VM).

### #3 — Message "déjà activé/désactivé" basé sur `config()` potentiellement stale

**Sévérité** : 🟠 Important (réel : cosmétique)
**Fichier(s)** : `WinscriptLogsEnableCommand.php:28`, `WinscriptLogsDisableCommand.php:29`

**Constat initial (review Sonnet)** :
`$alreadyEnabled = $this->loggingFlagEnabled()` lit `config()` (cache mémoire/disque), pas le `.env` réel. Si le `.env` a été modifié à la main sans `config:clear`, le message "déjà activé" peut mentir.

**Avis Opus (pertinence 2)** :
Confirmé. **Le résultat écrit reste correct** ; seul le message d'enrobage peut diverger. AC1.3 impose d'ailleurs de lire l'état *effectif* via `config()` pour `status` — c'est donc un choix de design assumé. Pour enable/disable, le message "déjà X" est cosmétique. Choix produit → décision utilisateur.

**Solutions possibles** :
1. Laisser tel quel (config = source réellement consommée par l'Assembler).
2. Lire la valeur réelle du `.env` sur disque pour calculer le message.
3. Reformuler en "flag positionné à X" (sans affirmer l'état antérieur).

**Action** : ⏳ **En attente de décision utilisateur** (cf. Question 1). Défaut : option 1.

### #7 — `File::put` non atomique

**Sévérité** : 🟡 Mineur
**Fichier(s)** : `app/Console/Commands/Concerns/ManagesScriptLoggingFlag.php`

**Constat initial (review Sonnet)** : `file_put_contents` non atomique → `.env` tronqué si interruption I/O. Fix proposé : write-tmp-then-rename.

**Avis Opus (pertinence 1, recommande de NE PAS appliquer)** :

Le fix serait contre-productif sans re-chown explicite.

**Action** : ❌ **Non corrigé (volontaire)**. Cf. Question 2. Défaut : conserver l'écriture in-place.
