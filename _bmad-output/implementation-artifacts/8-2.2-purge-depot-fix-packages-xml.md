# Story 8.2.2 : Purge des apps disparues du dépôt + fix packages.xml

Status: done
Depends on: 8.2.1 (done)
Parallélisable avec: 8.2.3 (done)

## Story

As a **responsable de collège**,
I want que le catalogue local reflète fidèlement le dépôt distant et que le packages.xml servi soit propre,
So que je ne vois pas d'applications fantômes et que les postes Windows reçoivent un XML exploitable.

## Contexte

Deux lacunes du code Laravel actuel (pas du legacy) identifiées après le refactoring 8.2.1 :

1. **Purge manquante** : `DepotSyncService::parseAndUpsertApplications()` (lignes 99-169) ne fait que des upserts — les apps retirées du dépôt distant restent en base indéfiniment dans `depot_applications`.
2. **packages.xml incomplet** : `PackagesXmlService::regenerate()` (lignes 25-64) a 3 problèmes :
   - Pas de tri alphabétique par `app_id`
   - Les noeuds SambaEdu (`<download>`, `<delete>`, `<untar>`, `<unzip>`) sont copiés tels quels — le client WPKG Windows ne les comprend pas
   - Chemin hardcodé `$storagePath . '/packages.xml'` au lieu de `config('sambaedu.wpkg.packages_xml_path')`

## Acceptance Criteria (BDD)

1. **Purge après sync** — Given le dépôt distant a retiré une application, When je synchronise le dépôt, Then l'application disparaît de `depot_applications`.

2. **Purge ciblée par branche** — Given une app existe dans les branches "stable" et "testing" du dépôt, When la branche "testing" la retire mais "stable" la conserve, Then seule l'entrée "testing" est supprimée.

3. **Purge avec statistiques** — Given 3 apps sont purgées après sync, When le résultat de `syncDepot()` est retourné, Then `result['purged']` vaut 3 et un log info est émis.

4. **Tri alphabétique** — Given des applications sont installées, When le `packages.xml` est régénéré, Then les noeuds `<package>` sont triés par attribut `id` (ordre alphabétique ASCII).

5. **Nettoyage noeuds SambaEdu** — Given le `packages.xml` est régénéré, When je lis le fichier, Then les noeuds `<download>`, `<delete>`, `<untar>`, `<unzip>` sont absents du XML servi.

6. **XML recipe intact** — Given une Application a un champ `xml` contenant des noeuds `<download>`, When `regenerate()` est appelé, Then `Application.xml` en base reste inchangé (seul le fichier disque est nettoyé).

7. **Bon chemin config** — Given la config `sambaedu.wpkg.packages_xml_path` est définie, When le `packages.xml` est régénéré, Then il est écrit à ce chemin exact.

## Dev Notes

### Piège DOM : NodeList live

`DOMNodeList` retourné par `getElementsByTagName()` est **live** — supprimer un noeud change la liste. Il faut itérer avec `while ($nodes->length > 0)` et toujours supprimer `$nodes->item(0)`.

### Purge : timing par rapport à la transaction

La purge doit être HORS de la transaction upsert. Si on met la purge dans la transaction et qu'une app est à la fois upsertée et purgée (bug edge case), on risque un deadlock ou une incohérence. L'ordre est : transaction upsert → commit → purge → log.

### Config packages_xml_path

La valeur par défaut dans `config/sambaedu.php` L177 est : `/var/sambaedu/unattended/install/wpkg/packages.xml`
Attention : `PackagesXmlService` utilise actuellement `$this->storagePath . '/packages.xml'` (soit `/var/se4fs/wpkg/packages.xml` — incorrect).
Après fix : utiliser `$this->packagesXmlPath` directement.

### Incohérence storagePath

`AppStoreService` et `PackagesXmlService` utilisent `/var/se4fs/wpkg` comme fallback, tandis que `PackageInstallerService` et la config utilisent `/var/sambaedu/unattended/install`. Ce n'est PAS dans le scope de cette story — la correction se fera en 8.2.6 (orchestration). Ne pas modifier les fallbacks des autres services.

### XML recipe vs packages.xml

- `Application.xml` = le XML recipe complet (avec `<download>`, `<untar>`, etc.) — source de vérité pour le flow d'installation
- `packages.xml` sur disque = ce que le client WPKG Windows consomme — ne doit contenir que les noeuds WPKG standard (`<check>`, `<install>`, `<upgrade>`, `<remove>`, `<depends>`)

### Piste future : stocker les directives serveur en JSON au lieu de XML

Les noeuds SambaEdu (`<download>`, `<delete>`, `<untar>`, `<unzip>`) ne servent qu'au backend Laravel. `PackageInstallerService::parseXmlDirectives()` les convertit immédiatement en tableaux PHP associatifs. On pourrait stocker ces directives en JSON (champ `jsonb` dédié) à l'ingestion, ce qui éliminerait le parsing DOM côté serveur et le nettoyage noeuds dans `PackagesXmlService`. Le `packages.xml` disque resterait du XML pour le client WPKG Windows — pas d'impact côté postes.
