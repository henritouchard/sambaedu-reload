# Story 8.2.5 : Post-traitement (delete, untar, unzip)

Status: backlog
Depends on: 8.2.4

## Story

As a **développeur**,
I want exécuter les directives de post-traitement après les téléchargements,
So que les fichiers obsolètes sont nettoyés et les archives extraites conformément au XML recipe.

## Contexte

Le legacy exécute les directives de post-traitement **uniquement si tous les téléchargements ont réussi** :
- `<delete file="...">` — supprime des fichiers obsolètes (`unlink`)
- `<untar tarfile="..." target="...">` — extrait des `.tar.gz` via `PharData`
- `<unzip zipfile="..." target="...">` — extrait des `.zip` via `ZipArchive`

Tous les chemins sont relatifs à `config('sambaedu.wpkg.storage_path')`.

## Acceptance Criteria

1. **Delete** — Given le XML recipe contient `<delete file="wpkg/packages/firefox/old.exe">`, When le post-traitement s'exécute, Then le fichier est supprimé. Si le fichier n'existe pas, aucune erreur (silencieux).

2. **Untar** — Given le XML recipe contient `<untar tarfile="wpkg/packages/app/archive.tar.gz" target="wpkg/packages/app/">`, When le post-traitement s'exécute, Then l'archive est extraite au bon chemin.

3. **Unzip** — Given le XML recipe contient `<unzip zipfile="wpkg/packages/app/archive.zip" target="wpkg/packages/app/">`, When le post-traitement s'exécute, Then l'archive est extraite au bon chemin.

4. **Statut PostProcessing** — Given le post-traitement démarre, When le statut est mis à jour, Then `InstallationLog.status` passe à `PostProcessing`.

5. **Enrichissement FileManagerService** — Given `FileManagerService`, When les nouvelles méthodes sont ajoutées, Then `extractTarGz()` et `extractZip()` sont disponibles et testables.
