# Story 8.2.3 : Téléchargement XML recipe + vérification SHA-512

Status: done
Depends on: 8.2.1

## Story

As a **développeur**,
I want télécharger et vérifier le XML recipe individuel d'un package avant installation,
So que l'intégrité du fichier est garantie et que les directives d'installation sont extraites de manière structurée.

## Contexte

Le legacy (`depot_liste_app.php`) télécharge le XML recipe d'un package depuis `$info_app["url_xml"]`, vérifie son hash SHA-512 contre `$info_app["sha_xml"]`, puis parse les noeuds `<download>`, `<delete>`, `<untar>`, `<unzip>`.

Le code Laravel actuel (`AppStoreService::downloadPackageXml()`, ligne 176) télécharge le XML mais **ne vérifie jamais le hash** et ne parse pas les directives. Le XML est juste sauvegardé tel quel dans `Application.xml` et sur disque.

**Deux formats XML distincts** :
- **Catalogue dépôt** (`packages.xml` distant) : `<packages><branch id="stable"><package .../></branch></packages>` — parsé par `DepotSyncService` (fonctionne déjà)
- **XML recipe individuel** : `<packages><package ...><download/><delete/><untar/><unzip/></package></packages>` — c'est ce que cette story implémente

## Acceptance Criteria

1. **Téléchargement en tmp** — Given une `DepotApplication` a une `xml_url`, When l'installation démarre, Then le XML recipe est téléchargé dans `$storagePath/wpkg/tmp2/<app_id>_<date>.xml`.

2. **Vérification SHA-512** — Given le XML recipe est téléchargé, When le hash SHA-512 est calculé, Then il est comparé à `depot_applications.xml_sha`. Si mismatch → exception + suppression du fichier.

3. **Hash absent = skip** — Given `xml_sha` est null, When la vérification est tentée, Then elle est sautée (log warning).

4. **Parsing des directives** — Given le XML recipe est valide, When il est parsé, Then les directives sont retournées dans un tableau structuré : `{ packages: [], downloads: [], deletes: [], untars: [], unzips: [] }`.

5. **Enrichissement FileManagerService** — Given `FileManagerService`, When les nouvelles méthodes sont ajoutées, Then `downloadWithHash()` et `hashFile()` sont disponibles et testables.

### Pattern de hash existant dans le codebase

`verifyIntegrity()` (ligne 248) fait déjà :
```php
$computedHash = hash_file('sha256', $installerPath);
if (strtolower($computedHash) !== strtolower($expected)) {
    @unlink($installerPath);
    throw new \RuntimeException("...");
}
```
→ **Reproduire exactement ce pattern** en SHA-512 pour `verifyXmlHash()`.

### Pattern de download existant

```php
// Download avec sink (pas de body en mémoire — bon pour les gros fichiers)
Http::timeout($this->downloadTimeout)
    ->withOptions(['sink' => $targetPath])
    ->get($url);

// Download simple (body en mémoire — OK pour les XML < 1 Mo)
$response = Http::timeout($this->syncTimeout)->get($url);
file_put_contents($path, $response->body());
```
→ Pour le XML recipe (< 1 Mo), le pattern simple suffit. Pour `downloadWithHash()` (réutilisable pour les installeurs en 8.2.4), utiliser le pattern `sink`.

```php
$dom->loadXML($content);
$packages = $dom->getElementsByTagName('package');
foreach ($packages as $package) {
    $appId = $package->getAttribute('id');
    // ...
}
```
→ **Réutiliser ce pattern exactement** dans `parseDirectives()`.

### Structure XML recipe (rappel)

```xml
<packages>
  <package id="firefox" name="Mozilla Firefox" revision="125.0"
           compatibilite="6" category2="Internet" priority="5" reboot="false">
    <check ... /><install ... /><upgrade ... /><remove ... /><depends ... />
    <download url="http://..." saveto="wpkg/packages/firefox/setup.exe"
              md5sum="abc123" sha256sum="def456"/>
    <download url="http://..." saveto="wpkg/packages/firefox/lang.msi"
              sha256sum="ghi789"/>
    <delete file="wpkg/packages/firefox/old-setup.exe"/>
    <untar tarfile="wpkg/packages/firefox/archive.tar.gz" target="wpkg/packages/firefox/"/>
    <unzip zipfile="wpkg/packages/firefox/archive.zip" target="wpkg/packages/firefox/"/>
  </package>
</packages>
```

Les chemins `saveto`, `file`, `tarfile`, `target` sont relatifs à `config('sambaedu.wpkg.storage_path')`.

### Points de vigilance

1. **Ne PAS modifier `DepotSyncService`** — il gère le catalogue, pas les recipes individuels
2. **Ne PAS supprimer `downloadPackageXml()`** — cleanup en 8.2.6
3. **`$depotApp` vs `$application`** : les données source (xml_url, xml_sha) viennent de `DepotApplication`, pas de `Application`. L'ancien code copiait xml_url/xml_sha dans Application au `firstOrCreate` (ligne 100-101) — le nouveau code lit directement depuis `$depotApp`.
4. **Timeout** : utiliser `syncTimeout` (30s) pour le XML recipe, pas `downloadTimeout` (300s) qui est pour les binaires
5. **Le répertoire tmp2/** n'existe probablement pas encore sur la VM — le créer automatiquement

### Modèles de données pertinents

**`DepotApplication`** — colonnes source :
- `xml_url` : URL du XML recipe (`string|null`)
- `xml_sha` : hash SHA-512 du XML (`string|null`)
- `app_id` : identifiant unique du package (`string`)

**`Application`** — colonnes cible :
- `xml` : contenu XML brut (`text|null`)
- `local_xml_path` : chemin disque du XML (`string|null`)
- `xml_url`, `xml_sha` : copiés depuis DepotApplication à la création
