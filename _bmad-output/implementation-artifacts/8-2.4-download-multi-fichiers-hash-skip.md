# Story 8.2.4 : Téléchargement multi-fichiers avec hash et skip

Status: done
Depends on: 8.2.3

## Story

As a **responsable de collège**,
I want que l'installation d'un package télécharge tous les fichiers nécessaires,
So que les installeurs et dépendances sont disponibles sur le serveur pour le déploiement WPKG au boot des postes.

## Contexte

Le legacy (`depot_liste_app.php` + `download_file()`) itère sur tous les noeuds `<download>` du XML recipe et télécharge chaque fichier individuellement avec vérification de hash. Si un fichier existe déjà avec le bon hash, il est sauté. Si un téléchargement échoue, toute l'installation est annulée.

Le code Laravel actuel ne gère qu'un seul `installer_url` par application. Cette story remplace ce flow par le multi-fichiers.

Les chemins `saveto` sont relatifs à `config('sambaedu.wpkg.storage_path')` = `/var/sambaedu/unattended/install`.

## Acceptance Criteria

1. **Multi-download** — Given un package a N noeuds `<download>`, When l'installation s'exécute, Then les N fichiers sont téléchargés aux chemins `$storagePath/$saveto`.

2. **Hash SHA-256 prioritaire** — Given un `<download>` a `sha256sum`, When le fichier est téléchargé, Then le hash SHA-256 est vérifié.

3. **Fallback MD5** — Given un `<download>` n'a pas `sha256sum` mais a `md5sum`, When le fichier est téléchargé, Then le hash MD5 est vérifié.

4. **Skip intelligent** — Given un fichier existe déjà à `$storagePath/$saveto` avec le bon hash, When le téléchargement est tenté, Then il est sauté et le fichier existant est conservé.

5. **Installation atomique** — Given un hash mismatch sur un fichier, When la vérification échoue, Then l'installation complète est annulée — les fichiers déjà téléchargés restent en `tmp2/` (non déplacés vers leur chemin final).

6. **Progression en base** — Given l'installation télécharge des fichiers, When chaque fichier est terminé, Then `InstallationLog.progress`, `InstallationLog.downloaded_bytes` et `InstallationLog.message` sont mis à jour (requêtable pour le front).

### `FileManagerService` — méthodes à utiliser

- **`downloadWithHash(url, targetPath, sha512, sha256, md5, timeout)`** (ligne 404) — télécharge via `Http::sink()`, vérifie le hash selon la priorité sha512 > sha256 > md5, supprime le fichier et throw si mismatch. Pour cette story : passer `sha256: $download['sha256sum'], md5: $download['md5sum']`, ne pas passer `sha512` (les `<download>` n'ont pas de SHA-512).
- **`hashFile(path, algo)`** (ligne 387) — wrapper de `hash_file()`, throw si fichier absent. Utiliser pour vérifier les fichiers existants (skip intelligent).
- **`move(source, destination, createDir)`** (ligne 178) — `rename()` avec création auto du répertoire parent. Retourne `bool`.

### Pattern skip intelligent (à implémenter)

```php
$finalPath = $this->storagePath . '/' . $download['saveto'];

// Déterminer l'algo et le hash attendu
$expectedHash = $download['sha256sum'] ?? null;
$algo = 'sha256';
if (empty($expectedHash)) {
    $expectedHash = $download['md5sum'] ?? null;
    $algo = 'md5';
}

// Skip si le fichier existe avec le bon hash
if (file_exists($finalPath) && $expectedHash) {
    $actualHash = $this->fileManagerService->hashFile($finalPath, $algo);
    if (strtolower($actualHash) === strtolower($expectedHash)) {
        Log::info('[AppStore] Skip fichier existant avec hash correct', ['path' => $finalPath]);
        continue;
    }
}
```

### Structure du tableau `$downloads` (sortie de `parseDirectives()`)

```php
$downloads = [
    ['url' => 'http://...', 'saveto' => 'wpkg/packages/firefox/setup.exe', 'md5sum' => 'abc123', 'sha256sum' => 'def456'],
    ['url' => 'http://...', 'saveto' => 'wpkg/packages/firefox/lang.msi',  'md5sum' => null,     'sha256sum' => 'ghi789'],
];
```

Attention : `md5sum` et `sha256sum` peuvent être `null` OU une string vide (`''`) selon le XML source. Traiter les deux comme "pas de hash" (`empty()` plutôt que `=== null`).
